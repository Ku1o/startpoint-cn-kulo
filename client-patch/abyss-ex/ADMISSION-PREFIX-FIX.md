# EX 正式客户端准入签名修复

Android 与 iOS 原候选更新了构建号和密钥，但保留了编译器折叠后的 `SP-ADMISSION-1\n<旧构建号>\n` 字符串。客户端以新号申请挑战，再用含旧号的消息生成 HMAC，因此在服务器允许新号且密钥正确时仍会收到 `CLIENT_NOT_ALLOWED`。

修复将实际证明前缀与新构建号保持一致，不推进准入号、不轮换密钥，不修改服务器严格模式或旧号期限。发布替换表及双端构建/验证入口同时检查折叠字符串，防止仅核验 BuildConfig 而漏过消息字面量。

Android 从原 EX APK 修复一个字符串池条目，保持方法体及其余 SWF 标签不变；更换 AIR UUID 和对应 DEX 身份，使用原证书签名并验证 v1/v2 与 ZIP 对齐。

iOS 从原 EX R2 IPA 原位修复运行 ABC 的一个字符串池条目，并同步完整 ABC、AOT 摘要及主 SWF 摘要。原生指令、方法表、重定位、段布局及其他 ZIP 成员不变；沿用 TrollStore unsigned 方式，完成三种签名尾部替换布局验证。

验证从原包与修正版实际载荷提取构建号、密钥及签名前缀，访问各平台公网准入端点：两个原包证明均被拒绝，两个修正版证明均成功。此验证没有登录玩家账号或操作玩家数据，不代替设备启动及战斗验收。

修复工具：`repair_admission_prefix.py`；实际载荷与公网正反例验证：`verify_admission_prefix.py`。最终成品身份见 `release.json` 及成品目录修复回执。2026-09-18 双端 accepted registry 已登记离线验收，范围见 [验收记录](../ACCEPTANCE-ABYSS-EX-20260918.md)，历史回执不改写。
