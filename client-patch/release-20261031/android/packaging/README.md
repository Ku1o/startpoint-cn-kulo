# Selective APK recipe

`package_delta.py --revision tutorial|trigger9000|dash --out <fresh work_dir/android output>` reuses the existing repository `client-patch/pr43-port/package_android.py`, x86_port and binary manifest parser plus `client-patch/abyss-autostart/sign_apk.ps1`. It does not execute an old whole-SWF builder. Its base APK/SWF hashes, old UUID and expected signer are explicit; no accepted registry is read or changed. Original package input/output identities are in contract.json. A future authorized rebuild uses a new ordered UUID and therefore has a different APK SHA.

Private `android.inputs.signer_config` is a hash-guarded JSON containing absolute path fields java, powershell, build_tools, keystore, credential_path and expected_signer_sha256. This source contains no material, password, credential XML or secret. Source preparation never opens those files. At an explicitly authorized package run, the existing private signer reads its own material using the existing credential-path interface. Never log secret contents or place this private configuration in Git.

Guards retained: base hash, canonical fresh UUID with DEX ordering, exact expected three changed members only, untouched bundle/admission, unique ZIP entries/CRC, signer fingerprint/v1/v2, zipalign, final SWF exact hash, every unrelated member byte-exact, inverse Manifest/DEX UUID restoration. Packaging does not install a device, touch services/resources/database, update accepted registry, upload or deploy. Use the outer bounded Windows Job wrapper; no packaging is performed for source-only validation. The relocated common wrapper is unexecuted.
