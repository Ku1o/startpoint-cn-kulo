# Cumulative client source recipes

This source integration preserves the selected gameplay mechanisms, native teammate-effects preference, native shop presentation, and the tutorial/9000/dash repairs. It is built on the registered cumulative R11 inputs, not on a whole donor client. APK, IPA, SWF, ABC, native/AOT objects, SDKs, signatures, credentials, original decompilation archives and local build receipts are not repository source.

The gameplay contribution comes from [PR106](https://github.com/Ku1o/startpoint-cn-kulo/pull/106), frozen head `5f70aec391c011f8d3066d41021fe06f27c07f84`, author account [kuronzzhan-droid](https://github.com/kuronzzhan-droid). Selective integration, platform adaptation and the later narrow repairs are distinguished in the component lineage manifests. The archive's whole build and excluded features are not adopted.

## Source layout

- `android/capabilities/` contains the transactional R11 editor and selected mechanism recipe. `android/upstream/` contains only the required patch-source dependency closure and small interpreter checks, with the fixed upstream source revision recorded separately.
- `android/contracts/` pins the actual successful group order, selected helper labels and the narrow instruction/header contracts needed to relocate historical locks. The two custom helper recipes are upstream-added methods; no official class source tree or broad P-code export is included.
- `android/carry163/` preserves the replacement `cn.carry` helper and reversible native hooks. The rejected original163 module is excluded.
- `settings/` preserves the original preference persistence, UI event chain and conditional render integration. Native shop methods remain native; no degree-specific shop helper is added. P5 remains independent of the teammate preference.
- `android/tutorial/`, `android/trigger9000/` and `android/dash/` preserve the exact minimal follow-up repairs and finite typed regression recipes. `android/packaging/` keeps packaging logic separate from signing inputs.
- `android/resources/` provides read-only bundled-resource verification. Its historical344 contracts do not claim that later resource chains have the same winners.
- `ios/` preserves both the cumulative334 recipe and the later17-business/22-AOT repair recipe, including wildcard sidecar/accessors, strict loader/unwind/relocation checks and actual compiled Atom ABI checks.
- `contracts/` contains the final method-selection and input-lineage contracts. `tests/` provides bounded source/configuration checks.

Two existing source files outside this directory contain the matching tutorial guard swap: `client-patch/content-operations/src/cn/content/ContentOperationsState.as` and its `content-operations-ios` counterpart. The display-period false return precedes the shared-date lookup. No save schema, stored progress identifier, ownership or account binding is changed by this source integration.

## Private inputs and outputs

Set `SP_CLIENT_INPUTS` to an untracked JSON file. Its top-level `work_dir` must be outside the checkout. Component examples describe their input roles; combine the `settings`, `android` and `ios` objects in the same private document. Relative role paths resolve from that document, not from the current shell directory. Nested AIR `air_config.sdk` and `air_config.java` must use absolute tool paths as required by the adopted importer. No dependency installation is performed by these recipes.

The retained binary baselines, donor payload, original AS fixture archive, SDK, Java, native libraries and284 ABC dependencies remain explicit private inputs with identity guards. Handwritten implementation and build logic live in the repository. Existing build metadata used as an input is data, not an external task-script dependency. For relocated iOS metadata, use `ios/report_rebind.py` with explicit report/artifact mappings as described in `ios/REPORT-REBIND.md`; it updates only declared paths and report-SHA links while preserving payload and ABI values. The complete real report graph has not been replayed after relocation. This is not a self-contained original-author game project.

## Construction order

For the frozen Android sequence, run the capability recipe with `--frozen-release-profile --run <fresh-name>`. The profile replays the actual successful group order and verifies each known output hash. It deliberately defers the final dash helper so that the standalone final repair preserves the recorded MethodInfo ordering. The normal donor selection retains the completeness fix that includes `MemberImpl.wfxRunDashAction`.

Continue with the carry helper and hooks, the no-degree UI/render composition, the tutorial guard permutation, the full9000 delta, and the final missing dash helper. Each stage consumes an explicitly pinned input and writes a new external output. The final selection has291 changed/added Android method bodies; this count is distinct from total methods and from the iOS compiled target count.

Use the component READMEs for exact command arguments, external input roles and validation boundaries. iOS has its own R11/cumulative input chain; Android bytes are a method reference and cannot replace the iOS native baseline. New method/static storage must retain the reviewed slot, namespace, activation and MethodEnv contracts. A successful compiler exit is insufficient without the target-symbol and actual-package checks.
