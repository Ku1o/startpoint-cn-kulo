# Private iOS report rebinding

`report_rebind.py` is the repository-owned metadata adapter. It never copies payloads or executes a compiler. Configure `SP_CLIENT_INPUTS.ios.report_rebind` with `reports` and `artifacts` dictionaries. Each report role has `path`, original `sha256`, relative new `output`, and `bindings`. A binding names an existing JSON `pointer`, exact `old` value, and either an `artifact` role or another `report` role. A report dependency may name its existing `sha_pointer`; the original value must equal that child's original report SHA before it is updated to the new report SHA. Artifact roles require explicit path/SHA; native/ABC/package pointers must use a file role and require `guard_pointer` to the unchanged original payload SHA before the directory/file branch is selected. Neither a directory role (even with an empty member list) nor a JSON report node can replace a native/ABC/package path. Existing conventional sibling report-SHA fields require an explicit correct `sha_pointer`; ambiguous multiple companion fields are rejected rather than guessed. Directory roles require a `members` contract (array pointer plus name/SHA field names). No directory tree is copied.

The graph is preflighted before output creation. Unknown roles, path fields, old-path mismatches, cycles, output traversal, existing outputs, source hash changes and wrong report-SHA associations are rejected. JSON artifacts containing further readable paths must be report nodes, preventing hidden unbound report dependencies. Only approved non-reading tool-provenance fields may remain opaque, explicitly with their old value/reason. They are not build dependencies. Handwritten Python/PowerShell tools used as input must be repository-owned.

Only declared path strings and report-file SHA associations are changed. A canonical protected projection must match before/after for each node; payload SHA, MethodInfo, function addresses/bytes, flags, activation, slots, ABI and other semantic metadata remain unchanged. `REBIND-RECEIPT.json` records both original and new report SHA. Map its settings-link/package outputs back to `ios.settings_link_report`/`settings_package_report` with their new SHA. Set separate `settings_full_abc` and `settings_native` payload roles; inspection no longer requires an old directory layout. Native hash evidence is declared/reused in sparse inspection; the adapter and existing linker/checker verify actual payload identity. This does not relax final native guards.

After allocation of the existing 512 MiB/60 second test Job, run the tiny synthetic controls only:

`python -B report_rebind.py --self-test --repository <read-only actual checkout> --output <fresh external JSON>`

This has one positive two-node/nested/member/hash-link/protected-field case and thirteen rejection cases. It creates only tiny temporary fixtures, removes them, and does not read real carriers, SDK, native or AOT data. It is suitable for the same source-only test window. The complete real private DAG is not tested by these fixtures.

For a future explicitly authorized metadata rebinding run, use `python -B report_rebind.py --output <fresh work_dir/ios/report-rebind/run directory>` under its separately allocated bounded Job. Relative private input paths resolve from the private configuration file. Supply every node and actual file role explicitly; absent mappings fail closed instead of selecting historical paths. Keep reports and payload data external. No old report, source checkout, platform carrier, registry or admission state is modified.
