## 原因与证据

所提供 stdout 日志第 166185、166311、170073、170396 行均为 iOS 1.8.4 / 资源 1.4.104 的 `TypeError: Error #1009`，栈顶是 `HudMemberStatus.run()`，随后进入 Gear / HudContainer 初始化链。服务器截断 crash body，不能只搜索结尾的 F1009 字段，否则会漏掉这些记录。侧件保留脱敏摘要，不复制登录信息。

累计移植给 `HudMemberStatus` 添加了 `wtsReadyNormalNext`、`wtsReadyFeverNext`、`geraldReadyNext` 三个 int 字段，只重新编译了 update。AIR arm64 将 int 等 32 位字段排在引用字段前面，追加 trait 导致引用字段整体移动 8 字节。这个布局顺序也可在 [Adobe AVMplus 的 Traits::finishSlotsAndMethods](https://github.com/adobe/avmplus/blob/master/core/Traits.cpp#L1135-L1141) 中核对。

实际 R3 原生 run 在 `0x102aca980` 从 `this + 0x48` 读取 featuresPermit，而 R3 update / 运行时类布局使用 `this + 0x50`。原构造器仍往 `0x40` 写 member，类布局却将其排在 `0x48`；这能使 run 的首次读取为空并抛出 1009。仅给 run 加空判断会留下其他读取、写入和语音状态的错位。

## 修复范围

- 从 SHA-256 `61a545ea867e97837fee2204c1649e362d6e3be2d98aa80abd3931111354a9af` 的实际 R3 IPA 继续。
- 将三个计数器存储类型改为 Number，使用已有 Double 常量 0 作为默认值，每次读取显式转 int，保持原有 0/1、0/1/2 轮换规则。
- 原有字段保持：prevSkillPointCycle `0x28`、viewOrder `0x30`、playhead `0x38`、member `0x40`、featuresPermit `0x48`、features `0x50`、effectManager `0x58`、character `0x60`。新计数器位于 `0x68 / 0x70 / 0x78`。
- 只重新链接一个 2988 字节的 HUD update 原生函数；放在 LINKEDIT 前新增的 16 KiB RX 段 `__HUDSTATE`，同时更新现有方法表及两个历史入口。没有 RWX 段。
- 当前运行 ABC 只改三个字段的类型/默认值，完整 ABC 额外包含五处整数读取转换；主 SWF 更新对应的 AOT 身份。保留方法、类和常量编号。
- 累计准备器同步修正；构建器和验证器加入原有字段偏移保护，阻止仅追加 int trait 的旧错误再次生成。
