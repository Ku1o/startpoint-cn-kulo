# R10 Android 重开黑屏：本地账号记录恢复

2026-09-15，MuMu 模拟器-1 出现首次能进入、退出整个模拟器后再次启动黑屏。本次直接输入为已交付的 R10 正式内网 APK，包含累计优化和 Android 准入校验。

## 已确认的原因与边界

现场安装 APK 的 SHA-256 与交付文件一致。黑屏期间应用进程存活；重新生成 AIR 缓存仍然黑屏，缓存 SWF 也没有落后于 APK。临时启动探针捕获首个 `Error #2030`，随后是初始化未完成引起的 Sipo 阶段异常。

`Local Store/custom_Release_Android/account` 与根目录 `_device` 记录均为 0 字节。账号读取直接进入 `DAT_RB` 解包，没有空文件保护，在画面初始化前抛出 EOF。仅备份并移开空账号记录，原启动流程立即恢复标题和登录页；设备记录原有读取代码已有异常恢复，之后重建为 62 字节。

账号、设备记录及相关文件读写方法与 9 月 13 日已验收 APK 相同；目前没有证据表明 R10 性能优化引入了这个读写缺陷。原写入路径先删除旧文件再建立新文件，存在失败后留下空记录的窗口；现场文件何时、因何写空尚未查明，不能直接认定某次写入被强制中断。

## 精确修改范围

| 既有主 ABC 方法体 | 修改 |
| --- | --- |
| 29386 `AccountLocalStore_Impl_.get` | 已存在但大小为 0 的账号文件返回原有 `Option.None`，继续现有登录流程。非空有效数据及其读取、解包和解析逻辑不变。 |
| 29390 `saveAccountData` | 保留既有序列化、压缩、目录与路径选择；去掉写前删除，调用 `LocalRecordIO`。 |
| 29456 `DeviceLocalStore_Impl_.writeFile` | 保留既有设备副本选取与编码；同样改为通过 `LocalRecordIO` 写入。 |

新辅助类写入同目录 `.sp-write` 临时文件，关闭并核对长度后再覆盖目标；空载荷直接拒绝，写入失败清理其临时普通文件并保留旧记录。同步调用不改变已有记录格式，不承诺系统断电时的持久化语义。非空损坏记录并未在此次补丁中自动忽略。

构建逐一冻结核对全部 96,631 个既有方法体，仅上述 3 个方法有修改；反向还原验证原字节码一致。其他 ABC、非 ABC 标签、原有常量池前缀、类布局、方法签名、资源和原生类行为均保留。测试探针和文件用例仅在 `--probe` 构建加入，交付 APK 无这些类和入口。
