# StarPoint CN 主动技能特效：制作与复用

用于新角色主动特效、风格返修、选稿和本地批量准备。先读当前角色配方及本页；只有缺少对应证据时再展开官方研究。机制安全与原生坐标仍遵循 [runtime-content-safety.md](runtime-content-safety.md)，图集按 [client-cdn-resource-safety.md](client-cdn-resource-safety.md) 核算。本页不改变接入、发布或源仓权限。

## 下次任务的直接入口

- 案例目录（历史本地记录）：保留 V12、V13＋V7 完整离线 V3 的历史案例及 V6 固定身份的离线证据；官方观察与未采用试稿见下方参考与失败记录。记录绑定具体文件；不要把最后修改的目录或名称带 final 的目录当成当前选稿。
- [整角色阶段编排](character-production-workflow.md)：从原稿、立绘、人物、声音和 UI 推进到完整离线候选时先读；本页继续负责主动演出及既有专题细节。
- [复用工具](../scripts/active_skill_pipeline.py)：列出/核验案例、准备隔离工作目录、调用已验证的原生编译与读回。先运行 `--help` 获取实际参数，不手写另一个编译器。
- 万圣稻穗当前入口：整角色制作指针（历史本地记录），由其中的 recipe、candidate 和报告路径定位实际文件；主动视觉另看技能选稿（历史本地记录）。当前版本、声音数量和验收范围读取实际配方与回执，不固定为 V3 或六句；历史记录保留原有范围。游戏接入仍待做，音量听感明确留待游戏时记 `deferred_to_game`，不因旧待试听文字要求反复网页听审。production-standard-v1 的配方及检查器仅适用历史 V1，不能直接验证 schema 2。

能力范围：当前通用复用入口支持 `caster / field / hit` 三组、普通 alpha、现有无新增声音的 Flatomo 编译路径。图像生成、审美判断、机制设计、角色专用预览器和游戏测试不是这个脚本自动完成的部分。V12 渲染器带本角色尺度、靶标和时序，必须检查适配，不能仅替换角色名就用于另一角色。

## 从创意到一版可审阅演出

1. **查当前状态，再查相近先例。** 绑定玩法、已采用人物、允许变化的层、输出目录及主动子预算。按题材/角色气质和动作形态选择已有官方样本；完整样本已足够时复用，不重扫 CDN。先问“上一例哪一项方法可以复用、哪一项不适用”，再决定是否补新的官方证据。
2. **先定主动作与接替关系。** 用几句可见动作说明起手、释放、高潮、结果、退场，以及人物何时恢复。先画固定战场尺度的关键姿态或短动态，判断主物象是否清楚；不要先堆小图、粒子和光晕再寻找主题。素材设计为动作服务。
3. **拆成有分工的小素材。** 区分承托暗面、主体暖芯、侧焰/边缘、局部内流、冲击短片、语义物件与余亮。局部片必须共同形成一个主形，随后由另一组形态接班；复制完整小物件绕圈或把复杂大图缩小，不等于学会原版构成。先做一个局部动作，再放进完整场地检查，局部采用不能直接推定全场采用。
4. **编排并编译。** 保持伤害事件、控制/隐藏和视觉寿命三条独立时间线；变动伤害或控制必须单独声明。按原生 tick、语义锚点、矩阵、局部相位和图层组织。调用既有编译器；预览消费原生读回数据，不用另一套随意运动的动画冒充成品。实际核算完整 sheet 含 margin 的面积，并同时记录图种、预建实例与单 tick 叶命令数。
5. **按本轮风险复核后交付。** 同尺度看纯人物、完整正常速度、半速与交界连续帧。核对主题/重量/主次/遮脸/换姿/收尾；静态板不能代替连续播放结论。检查实际原生、已保护文件和交付身份；只补变化影响的验证。工程与审美状态分别记录，采用后统一更新配方、当前选稿和采用记录，保留历史候选。

只在决定缺失会改变机制、取舍或授权边界时询问。正常实施和检查不反复要求确认；未获得最终审美采用时如实保留试稿状态。

## 动作设计的判断点

以动作类型选择方法，不把所有技能做成 V12：

| 动作 | 应有的可见因果 | 易出现的错误 |
| --- | --- | --- |
| 砸落/投射/弹出 | 方向与加速、接触、短促压缩或爆开、尾部追赶、结果物件离开落点 | 整团匀速漂浮，接触后长期成盘，物件先于撞击出现 |
| 弹跳/抛出 | 抛物线上升减速、顶点过渡、回落加速、较弱余弹、最后落定 | 正弦来回、不衰减的弹簧、底边穿过落点、突然消失 |
| 光束/斩击/贯穿 | 稳定方向，轴向流动，截面/边缘支持主形，先撤长结构再撤短余亮 | 整束左右摆、亮片绕圈、各层同时透明 |
| 召唤/角色表演 | 可辨头脸/身体姿势，蓄势与释放衔接，附属件跟随并有遮挡次序 | 一张完整图只缩放旋转、耳朵和脸不同步、换姿重影 |

物理感是演出曲线及接触语义，不要求额外修改客户端物理引擎。存在实际玩法碰撞时需另查机制证据。重力值、压缩幅度、偏移帧数、角色 6 倍显示和 120 tick 场地时长都不是全游戏通用常量。

天降与震屏的复用入口见原生先例（历史本地记录）及镜头研究（历史本地记录）：原生 `ShakeCamera` 的1/2/3是档位枚举，不是任意振幅；一次撞击命令放在逐敌循环外，不能因敌人增加而重复震动。区分世界／parts／镜头父层／最终显示坐标；本例1/6再6倍抵消，1080世界宽显示360时的18单位位移是6像素，不能再乘parts.s。原生相机更新先于技能事件，曲线首个非零采样有相位差；预览固定随机轴符号时须明示。震屏和设备马达振动分开查证。落点以真实alpha轮廓核对而非只看父矩阵；柔光与实体头分别测，固定示意视窗中屏外入场不代表任意游戏镜头都在屏外。

### 实战可见性与前后层

收到“不显眼”反馈时，先锁实际候选和显示链：DSL倍率、parts.s、世界到相机/低分辨率画面的换算、透明度、亮核时长及ShowEffect层级。角色的6倍不能直接套给场地。先在同尺寸中央大敌、明暗与复杂背景中比较；没有匹配录像时保留多种可能原因，不把历史源码推导或合成场景称作当前实机根因。

完全被敌人挡住的主核不能靠加粗或提亮修复。原生支持时，把天降主形、短促接触亮核与结果物件分到前景，地面承托/雾/余焰留后景；同时避免白盘长期覆盖角色。多个layout可共用sheet，但需依据实际collector证明推导和去重，parts图像路径必须与完整atlas键精确匹配，不能把`field`随layout名改为`foreground`。新增动画timeline无声，原有有声timeline保留，避免重复SFX。实例池和容器成本另算，贴图不增加不等于性能提升。依据见万圣分层V2（历史本地记录）及其`research/REPORT.md`。

并行人物与特效合并时，只应用声明差异并验证before SHA；不得用完整候选覆盖另一组改动。组合后从最终DSL剥离新增纯表现根命令，证明完整机械AST恢复，再核对共享图集闭合、声音和文字修复。预览必须使用组合候选的新人物，旧占位视频不能改标签后充当最终组合。固定合并实例见组合装配证明（历史本地记录）。这类检查与连续观看、游戏运行和完整战场性能分别验收。

## 本次确认的失败与改法

| 已出现的问题 | 下次制作时的动作 | 对应证据 |
| --- | --- | --- |
| 暗属性直接画成凶兽，偏离可爱角色 | 先审人物气质与原生尺寸素材板，再定能量的色形与表情 | V4 风格记录（历史本地记录） |
| 小图复用只是复制整团/绕圈，显得廉价 | 画出各片如何构成主形、何时换成断片；减少等亮接缝、串珠和同形横排 | 官方层级与构成（历史本地记录） |
| 三次伤害被误做三轮很短的高潮 | 单次完整演出覆盖多次伤害，分别管理三种时钟 | 时长研究（历史本地记录） |
| 只看准备/入手动作或只看特效，忽略战斗人物 | 查看实际主动 DSL 选择的身体入口，连看身体与场地 | 战斗动作研究（历史本地记录） |
| V10 单瓣好看，三瓣持续摆动仍未采用 | 局部选稿后重新看完整节奏，不能把局部批准扩成整体批准；缺乏动作因果时应换主动作 | V12 采用记录（历史本地记录） |
| 落地弯片排成虫串、压扁焰与金环像飞碟 | 少量不同尺寸/角度/速度/出生相位的断片；撞击承托迅速退场，结果物件接手画面 | V12 视觉复核（历史本地记录） |
| 数值锚点正确但狐狸底部偏移 | 用实际像素中的同一语义部位注册，换姿/压缩/落地逐段检查 | V12 构建与核验（历史本地记录） |
| 实物已采用而配方/当前指针还停在旧版 | 采用时同时更新配方、当前指针与 SHA；原生视觉 overlay 与保留的机械 DSL overlay 分开绑定 | 最终候选读回（历史本地记录） |

这些结论解决已观察到的问题，不证明所有火焰都应砸落，也不保证每版都会得到更高审美评价。

## 从选稿到完整离线角色

阶段顺序、交付条件与专题入口见[整角色制作流程](character-production-workflow.md)；以下保留已经积累的详细判断点与历史证据。

完整离线交付须把当前数值、完整人物和主动特效编入同一份候选，再对该候选读回；单独预览通过不能代替总装。保留输入配方快照，并在选稿、候选、回执和当前指针间绑定实际文件身份。数值修订不应重绘已采用素材，旧组件报告也不能自动替代新组合验收。

以已验证的完整候选为基线，仅叠加当前选定组件，先声明覆盖集合，再从最终磁盘候选独立回读；核对每项资源身份、表／row-patch／server／inputs 和未选资源是否保持，不从组件各自 PASS 推定组合正确。原生地址调用既有 `sha1_path`，不自行猜测 salt 或改写哈希公式。表现 DSL 若只增镜头命令，去掉该命令后应完整恢复原树，并另核机械等待／伤害数值；表现修改不隐含玩法变更。候选依赖、最终编码音频、实际原生帧及有限声明集合预算在同一交付身份下绑定；有限装箱不推广为整场战斗。

- 既有角色的头脸风格先在相近脸宽下比较官方原图与小样，再判断线条粗细；不能用全身缩略图对比放大的头像，也不能默认“更细、更多线、更精细”就是更贴近原作。分别看外轮廓、上眼线、内部细线及色块层级，避免为了加粗轮廓连睫毛也拉长。检查虎牙相对嘴宽的大小、与上唇的距离和尖端形状；脸颊饱满度、下脸长度与眼睛大小分开调整，不用放大圆眼代替圆颊。返修要求须实际进入下一轮提示词，互相矛盾的旧描述先删除；指定只用某官方版本时，生成输入清单和预览参照都限于该版本，旧生成图仅作诊断，除非明确允许不得重新作为输入。预览可用 CSS 局部窗口保留原 PNG；仅近似对齐时须标清，不能冒称精确测量。具体年龄感、小牙和线宽取舍留在角色案例，未选稿不作通用审美标准。万圣稻穗的当前头脸选择与剩余范围，从 当前角色制作记录（历史本地记录） 的 selectedFaceReference／appearanceDirection 读取；历史 pendingReviewRevision 不作为最终配方入口。
- 头脸已被明确选定时，原样保存该图并绑定文件身份、选定范围和后续候选；脸部已选与头饰／衣服待改须分别登记。不能仅因配饰不符就把整张头脸判为淘汰，或让后续整图重生稿自动替换已选脸部。换装稿先与已选稿核对脸型、眼形／虹膜、嘴形及线面，再核对服饰；未通过保留旧选稿，不用提示词合规或生成先后代替采用状态。虹膜等特征同时比较主色形状与内部高光的占比，不把增大白色高光当作扩大有色主体。 服装局部调整不自动扩大为眼形、颊弧或下脸重塑；已选脸未被明确推翻时继续约束其实际几何，不能用“成熟／幼态”等抽象标签代替官方比例。面部确需另改时，单独检查眼睑开合、眼角长度、颊弧、眼下留白与下脸收束；只贴回虹膜图案不能恢复眼形。蒙版外像素一致和无接缝属于技术检查，不能据此判定角色相似度通过。
- 人物按原生 frame／timeline／atlas 读回全部动作、时点、锚点、声音与碰撞标记。保留 loop／once／pass／stop 的原生含义；`stop` 的每帧控制和 `pass` 的后续状态不应按网页单段循环重新写入游戏数据。
- 声音覆盖单列台词、战斗喊声、主动特效和入手场景音。按当前选稿的实际调用、原生语音池、timeline／DSL／场景声音表核对；包内存在录音、公共音效闭包非空或旧未引用演出带声音，都不能证明当前演出已配音。新增台词的 `(None)` 要标为待补或明确采用的无声设计，不算素材齐全；复用录音须与实际台词相符。文字／声线、纯音频与同步声画的实际试听、编码响度和游戏听感分别记录；音量明确留待游戏时记 `deferred_to_game`，不要求反复网页试听或冒称批准。逐敌命中层避免重复堆叠场景主音效；静态路径通过不代替发声或听感验收。
- 复用原角色战斗喊声时，核对实际说出的招式、属性与角色语境；原声可解码不代表适用于换装技能。先盘点已有语音模型及能力，再决定是否下载；新合成明确标识，短样音色认可不自动覆盖全部台词的语气、发音与含义。原生语音池和演出音效分别接入，避免把同一 skill／join 录音再次嵌入 timeline。响度与峰值检查最终编码、最终声道的读回音频，并执行[角色语音流程](character-balance-workflow.md)中的固定同mono官方参考差门禁；固定−18目标窗口不能代替对照。预览voice/SFX增益须按实际表与调用解析，不能因视频用了unity而高估游戏音量；ASR 是定位疑点的辅助，不能把近音字或识别通过当作听审通过。
- 语音池连续编号扫描不代表顺序播放，须查实际选择器。本例技能池随机取一条；缩成一句时需处理所有既有槽位，否则旧长句仍可能出现。普通增量覆盖不能删除继承文件，缺少可用计数／前缀表时可将两既有槽绑定相同短句，仍只播放一次。已有音色可在真实停顿处切取时，优先保留原PCM，淡出只覆盖句间静音；独立ASR、编码读回与整句试听分开验收。V13短喊声回执（历史本地记录）记录本例边界，不把其切点或槽数当通用常量。
- UI 资源按实际调用同时核对 medium／small 及双平台图集，不从其中一组存在推定另一组齐全。沿用既有裁切、缩放和平台编码，读回最终候选核对大小、alpha、内容与表引用；small 的比例按当前原生约定确认，不推广本例数值。当前案例补齐了历史适配器未导出的 small 根。
- 普通进化、玛纳节点扣料与额外觉醒系统分别判定。缺少可选 character_awake_status 行是否构成问题，须查实际消费者对 None 的处理以及角色设计；不得为了表面齐全随意增加觉醒属性、任务或奖励。客户端／服务端材料与费用表一致属于离线证据，实际扣料、持久化仍待游戏验证。
- 立绘审查除风格与裁切外，固定各物件语义和角色结构，再分别审全幅构图与手／耳／道具局部。尾数等外形按官方可见尾身与端点追踪，不从“九尾之女”等称号直接推定；区分头发、毛边分叉、狐火和实体尾。除两侧大尾外，还须独立检查耳后／发饰下的大圆团：沿发根到发梢追踪，厚度、末梢及与实体尾的间隙要能明确读作头发，不能仅以命名消除第三尾错觉。官方尾部束饰须表现实际环绕尾身的弧度、接触和前后遮挡，飘过尾前的披风带不能代替。清理多余尾形后还须检查披风／道具遮挡外残留的浅色长尖，避免多一尾或同尾双端的歧义。不能只数到五个指端就判手部通过；须沿手腕、掌缘、拇指对掌、指根／关节与小指比例检查；另将可见指节长度、指根位置及弯曲后的总轮廓与掌长对照，握得住物体也可能有超长食指。持物要看真实接触及遮挡，遮住部分不得脑补验收。狐火脸与南瓜灯脸等邻近主题不能混用；局部修改后也回看双耳数量及其他保留对象。检查脚部与场景关系、进化前后表情／姿态区别；被指出与既有角色雷同时改变重心与动作叙事，不仅改嘴角。用实际官方构图参照，不把台座当引擎规则。既有角色换装的脸部修订，先按官方角色家族／资源代码盘点本地可得变体和进化前后立绘，排除同名 MOD；逐张目检后记录眉形、眼形／高光、脸部比例和表情差异，再作编辑参照。保留来源清单，限定“全部”的数据范围；参考数量和生成成功不能代替修订图与旧图的同尺度局部比较。已有特征与本次新增／调整分开描述。连续改图保留干净的原始质量母版和累计修订清单，不自动把上一生成稿当唯一输入；每轮还要同尺度对照眼部、褶边、深色大面、金边及透明轮廓，检查局部改对但整图退化。记录实际尺寸与人物占画幅比例，分开判断分辨率变化、生成重绘漂移和原图已有的透明彩边；放大／锐化不等于恢复。发现漂移时可从干净母版一次重建所需变更，但须重新检查旧手部错误和其他结构是否被带回。新输出只通过局部目标或审美未确认时保留试稿状态。
- 局部修补的范围须由实际像素验证，不把“提示词未要求修改人物”写成“人物未改”。整图生成即使尺寸不变，也可能重描脸部、线条与色块；PNG文件大小和像素变化比例不是画质分数。已获图层／像素合成授权时，以固定原始PNG作底，生成结果只作补片来源；用覆盖目标且避开保留结构的蒙版合回，记录母版／补片／蒙版／输出身份，检查蒙版外RGBA逐像素相等，并放大复核羽化接缝和邻近结构。外区不一致则不得晋为保真局部修正版；缺少像素锁定能力时明确此限制，不用连续整图生成保证原样。已验证案例与可重放脚本见万圣V6局部合成（历史本地记录）。
- 透明背景先读取实际 PNG 的 RGBA、空白处／主体采样及边缘 alpha，再决定是否需要重新抠图。生成缩略图或查看器可能显示 alpha=0 像素中残留的 RGB，不能仅据所见底色判为不透明；“有 alpha 通道”也不等于边缘已清理。区分完全透明、接近不透明的主体与半透明光效，报告实际数值，不把主体 A=253 写成全体 A=255。白底／深底／棋盘下的实际合成可检查彩边，未看到合成时保留该验证边界；仅修透明度不应重新改脸、服装和姿态。
- 入手演出先按原生 atlas 累计结束 tick 展开适合的官方基底，保留所有画幅与 hold、fx/fy 原点及 land→pose 边界；少量等距截图只作索引，不能冒充逐帧研究。先在固定原点、同原生尺度下看纯人物，再看完整效果。分别记录合成图变化、整数平移、部件模板切换和独立全身绘画；姿势参数组数、RGBA 哈希数均不是重绘张数或质量分数。人物改编以头耳、肩腰、衣摆、双腿和尾身共同换面的轮廓为依据，先制作无特效关键帧检验投影与遮挡，再扩中间画和效果，不能继续往僵硬的头片／线段袖子工厂追加参数。已确认自定义母版时，官方动作参考不授权替换人物身份。先明确继承的是时序、重心、投影与遮挡关系；不能直接沿用官方整个人物像素、仅改色或补衣片，就宣称保留了自定义角色。母版文件未变与新动作仍是同一造型须分别验收：关键正／侧／背／俯仰帧与已确认母版同尺度核对头脸比例、发饰侧别、头发／尾饰、衣袖和裙摆识别特征；不把“保护官方原像素”当成保护自定义身份，也不为保身份冻结正脸或消除合理动态变形。借用官方部件前检查其会否带回原服装、体型或面部；未通过先停在纯人物关键帧，不加FX或编整段。纯人物已目检后仅修改FX时，锁定逐帧人物PNG并只改效果层，随后检查遮挡与完整合成；不能把后续改FX变成再次换脸换体型。旧自定义人物入手V4（历史本地记录）已因无起跳画姿的上下位移及错误眼形撤回；其工程读回通过不能作动作或眼神范例。当前修订证据见V5眼部与腿脚复核（历史本地记录），审美与实际连续播放仍分别待验。以官方为参考时固定来源帧，换装、持物手和饰物侧别逐帧核对；调色板分离只是派生候选，共色残影和被遮挡部位须另查，不能冒称恢复了原始人体图层。人物可在高潮后停住，让效果退散，不用反复摆动填时长。先审人物和特效的因果、高潮及 land→pose 衔接，再决定时长；延长入手不自动延长技能准备或战斗动作。烘焙合成帧中的小素材复用仍须按最终裁片和 padding 计算图集成本，不能当运行时部件复用免计预算。可重放研究入口：四官方全时点与分离边界（历史本地记录）、旧稿绘画方法诊断（历史本地记录）。
- 跳跃须先画屈膝蓄力、脚尖蹬地、腾空收腿、下降伸腿和接地缓冲，再安排整体位移；关键画与每个hold均在同一地面线上检查实际膝、靴和承重关系。不能用dy清零代表接地，下身行数改变也会抬起脚底；记录可见靴底最后像素及其外边界，区分y127的脚像素和y128的地面线。后续站地施法不靠无起跳的整人浮动填活泼感。低分辨率眼睛按每只眼的深浅色格、眼距、眼角残留及头部投影核对；“有青色”不证明双眼正确，倾头造成的整体眼高差也不能误判成虹膜断裂。先显示纯人物正常速度、慢放和可关闭地线，再看FX，静态坐标与姿态格检查不升级为重量、节奏或眼神审美验收。修复范围外未使用的旧方向头仍可有缺陷，不给整库统一通过。
- 人物与入手FX联动先列动作因果：看向／握住道具→侧背转身牵引→回正举臂→停姿交给主FX→收手回待机。每个实际人物hold标出袋口／掌心、前后层、可见性与支撑脚；不能用最右肤色格自动代替持物手，隐藏道具不在前景强行发光。转身须分别审头肩腰裙与双尾，不能把两侧尾团换大小当作尾巴跟转：固定每尾物理身份，跟踪后腰根、中段、尾尖；侧面双尾投影到身后同侧并近遮远，背面从后腰根区分叉，回正时根先到、尾尖稍后收稳。正面根可被裙遮挡，背面应有可读连接；所有尾统一压在身体底层不能表达背腰遮挡。看双尾独立分层板及最后合成轮廓，不以方向名或根坐标存在代替图上检查。固定同一物理侧的饰物与道具，明确换撑或支点，不以所有靴都在同一y证明没有滑脚。先审九向关键画，再补换脚和举臂桥；对已认可前段可逐tick锁定原PNG。绕身FX按深度拆前后层，释放起点跟随实际袋口，举臂完成后才接大特效；高潮结束保留可识别主体缩小／碎解桥，不突然用一组无关碎条替换。最终合成再核眼格未被火星遮挡，不能只验证纯人物。局部修尾以原绘图所有权建立旧尾、新尾与非尾保护层，允许范围在合成前确定，不从最终差异反推蒙版；核对非尾像素、脸眼手袋脚、已认可前后段及特效时点保持。参考官方连续帧因果研究（历史本地记录）和V6限定复核（历史本地记录）；实际连续播放、审美采用和游戏仍分开确认。
- 游戏 stored PNG 的小写 `png` 伪签名必须先解码再提供浏览器预览。候选保留原生编码，预览记录源编码 SHA 与解码输出 SHA；实际解码图片，不以文件名或复制成功判为可显示。
- 举臂的肩／肘／腕坐标只作绘图引导，细线骨架不是可交付袖臂。先在原生格子画可读的短上臂、弯肘、袖体、袖口与肤色手，再逐hold检查低／中／高位和收回；不能只用手袋连通或锚点存在证明衣袖完整。最终叠层必须再读实际掌位像素，排除发饰遮手、袖口吞掌和掌心光点盖手，同时核对眼格。手位变更只重算有具名来源的袋口连接／掌心效果，旧来源重放匹配后以预先确定的所有权范围保护固定FX，不把整幅效果平移。案例：袖臂局部重绘及保护核对（历史本地记录）。其静态与原生资源检查并未证明动态审美或实机通过。
- 预算分别记录角色自身 sheet、声明的角色资源集合、具体完整战斗。收集未知不可作零，动态装备／敌人等未选场景不伪称闭合；有界角色集合装箱通过仍不等于任意编队、GPU或设备通过。
- 控件静态／stub、浏览器播放、审美采用、游戏运行分别记状态。浏览器工具拒绝本地协议时遵守限制，交付可手动打开文件，不用HTTP或其他浏览器绕过，也不补造浏览器验收。

可复用的实际入口先由 CURRENT（历史本地记录） 定位配方及相应检查器；同身份的已有有效结果可以复用。以下保留 V3 的历史复现入口：V3 完整配方（历史本地记录）、最终候选读回（历史本地记录）、声明集合预算（历史本地记录）、预览导出（历史本地记录）、预览静态核对（历史本地记录）和独立离线核验（历史本地记录）。新组合须针对最终候选检查覆盖顺序、未声明行、声音指针、普通动作保护及 land→pose 接缝。推进指针时同步配方、预算和预览身份，不能留下两个不同版本的当前预算。旧 V1/V2 入口亦仅作历史基线，不能拿其检查器验证新配方。入口仍含本角色参数；下一角色须更换配方、素材与范围，不能直接复用数值常量。

## 每次制作如何留下增量

收尾只记录这次新增的有效信息：什么视觉问题、实际改了什么、对应输入/结果、适用条件与仍待验项。优先修正既有方法与工具；没有新经验就不追加一份重复提醒。出现重复失败时调整步骤或检查器，不靠增加参考数量、日志长度或“下次注意”解决。

已采用版本固定源码、原生资源、预览和回执身份；新试稿写新目录。将可重放的方法加入案例目录，将当前角色参数留在该角色配方，不写成全局限制。工具变动后用一个真实案例重建，并针对实际失败点做负例；不因改文档重跑游戏或全部历史工程。

后续批量制作可以共用参考库与工具，但每个角色独立持有角色代码、素材来源、参数、预算、检查和采用状态。失败角色不混入通过批次；不得自动复制账号、发布状态、万圣角色的 ID/机制/专属素材。下一角色的实际结果才是跨角色收益证据。

V12 和 V3 选定组件（历史本地记录）保留历史采用记录；实际当前组件从 CURRENT 指向的配方和采用回执读取。候选独立读回与有限声明资源装箱通过，不代表浏览器连续播放、新组合审美、游戏声音联动、具体完整战斗、设备或发布通过；统一预览的静态／浏览器状态分别读取最新回执，文字／声线、编码响度与游戏音量分别记状态。
