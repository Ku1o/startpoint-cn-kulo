# 角色 UI 裁剪与外框遮罩

用于头像缺口、角色 UI 裁切或换图复核。按当前原生资源名与尺寸匹配；不改已选立绘或把历史拟合半径当引擎常量。

1. 先区分**面板外框**和**原人物透明区**。复用既有 canonical 配方（历史本地记录）及遮罩目录（历史本地记录）：其外框来自三名官方角色各两形态。圆角／圆形／指引板／连锁轮廓分别匹配，不将单张人物 PNG 的发间、脸侧或背景透明缝乘到新图。
2. 仅修遮罩时，保持原 source、source crop box、缩放与裁剪 RGB；用正确外框约束源 alpha。medium 修后按当前原生 small 比例与滤镜重新派生，不能留下旧 small；未受影响文件保留原字节。需要换取景则另列审查，补透明洞不等于补全耳尖。
3. 外框几何匹配、bbox 合法和 `outsideMaskNonzero=0` 只证明没出框。还须检查 canonical 内部：源裁剪本来可见、按 canonical 应保留，却被结果 alpha 压掉的像素。以源 alpha 与正确外框所得预期 alpha 为基线，记录错误消失区；不强行填实源图本来透明的部位。阈值与抗锯齿边缘分别标明，不能混用不同计数口径。
4. 实际查看 medium 与 small 的白底、深底合成及原生小尺寸，重点看顶部／侧面缺口、轮廓断裂、五官与裁边。仅修遮罩时核对源框/裁剪RGB一致；调整取景时核对母版原字节、已认可的裁框与最终编码读回。静态尺寸或遮罩外零像素不能代替内容保全与视觉核查。

## 预览覆盖：不能只列几个常用缩略图

1. 从最终候选资源索引枚举实际 `character/<code>/ui/`，以 `root + logical` 为键建立“原生资源→展示文件／明确处理方式”清单。两种形态、medium/small 分开登记；技能指引、技能连锁、主位、副位、升级图、头像、切入、切换立绘等按实际资源名归类。未知资源必须补分类或说明，不能因首页没有对应卡片就静默遗漏。数量由当前候选推导，不沿用历史固定计数。
2. 首页面向常用场景，另提供完整检视入口。每个 PNG 槽位都应能找到对应画面及原生尺寸，支持两形态、大小版本、白/深底和原生 1:1。没有 small 的资源标明缺失，不临时缩图冒充原生 small。切换立绘按 atlas 的 cell 与逻辑框还原；平台纹理单列现有验证与对应 PNG，不把 PNG 展示称为平台重新读回。
3. 名称/槽位数与独立画面数分别统计。多个剧情表情名如果共用一张静态图，可以去重展示，但须保留逐槽位映射并明确独立表情尚未制作。不能把文件齐全作为表情内容齐全的证明。
4. 独立从最终磁盘候选读回，核对资源键集合无遗漏、展示 PNG 的尺寸及 RGBA 像素、atlas 还原、形态/大小切换、链接和实际叶文件身份。加入能检出“原生资源存在但页面遗漏技能指引”的覆盖检查；页面控件 VM 通过只代表对应静态行为，不替代浏览器显示和游戏验收。只补展示时保持候选原字节，更新预览、配方及台账映射，不无故重建游戏包。

万圣稻穗 V8 的反例是：V7 总览只显示四类 UI 缩略图及完整立绘，原生技能指引等资源已经存在。补全展示后对本候选97个UI条目逐项归类，92个PNG槽位与原生读回逐像素相同；其中21个剧情槽位在各图片版本内仍共用一张静态图。数字只适用于本候选，未作新裁剪或游戏验收。见覆盖核验与缺失清单（历史本地记录）、独立检查脚本（历史本地记录）；脚本为本例参数化前的实现，复用时替换实际候选及资源分类，不能把硬编码数量当规范。

## 取景调整：头脸被裁得太紧时

1. 将**外框形状、源图内部透明区、取景构图**分别检查。外框正确、没有误删人物，并不代表头脸取景合适；先辨别是哪一类问题，避免修好遮罩后继续沿用不合适的旧裁框。
2. 从实际官方资源中选择相同用途、相近角色和姿态的样本，固定原生尺寸并排看，不用整幅立绘自行裁出的图片冒充官方 UI。记录资源名、形态、来源与尺寸；找不到官方 small 就明确缺失，不把 medium 缩略派生图称为官方 small。官方样本中的裁切习惯属于参考，不直接升格为引擎限制。
3. 原立绘没有缺陷时，优先尝试移动裁剪框，保持已认可的脸部尺度；按两种形态的姿态分别调整横向和纵向位置，必要时再比较轻微缩放。检查额头、双眼、下巴、侧发与下方衣装的整体分配。是否容许耳尖、帽顶超框由官方同类参考和当前采用方向决定，不硬套“所有头饰必须完整”，也不把人工估读的眼位比例变成通用硬指标。
4. 用同尺度的“当前／建议／官方”对照确认，再同步生成两形态 medium 与 small；保留 canonical 外框和源图自身 alpha。取景变更允许裁剪 RGB 改变，保护的是立绘母版原字节、明确的裁框/滤镜参数及未涉及资源；不能套用“仅修遮罩时裁剪 RGB 不变”的断言。最终原生编码解码须与认可稿逐像素一致，最终预览从候选资源读回，不只替换网页上的图。
5. 采用后，更新当前配方、候选索引、预览和实际叶文件台账；限定实际变化集合，独立核对其他资源原字节及旧版保留。验收报告绑定候选资源、行补丁和预览实际文件，配方再引用报告，避免互相嵌套 SHA 造成循环。仅同尺寸裁框变化且图集/布局/声明集合未变时，可凭这些身份与几何证据复用原有限定预算结果，不由此推定游戏显示、GPU性能或整队容量通过。

### 窄长技能指引先查同用途构图

`battle_control_board` 不沿用方形头像的脸部裁框，也不把源图等像素宽度直接当最终面板的取景宽度。先抽取跨角色、两形态的真实同用途资源，统一原生尺寸比较头脸、眼位、衣领和躯干分配；外框正确但只剩一条放大的脸，仍是构图未完成。常见做法是把头脸放在上部宽处、下方留衣领和上半身；具体缩放与两形态偏移按姿态分别定，不能把该观察升格成所有角色的固定比例或完整头饰要求。

爱丽丝离线返修已比较96个官方角色、192张技能指引，提供同尺度旧版、三种裁框和官方对照，原生候选仅换两形态×medium/small四项。B方案仍待审美确认，不能称采用稿。参考样本来源与身份（历史本地记录）、裁框方案（历史本地记录）和最终原生读回（历史本地记录）。

### 缩小清晰度与采样检查

1. 分开核对源立绘、最终原生PNG和网页实际显示。记录图片的 naturalWidth/naturalHeight 与实际显示宽高；网页按原尺寸显示，仍可能暴露生成图片时已有的锯齿。先比较两形态原生1:1，再看固定整数倍的最近邻局部放大；放大图只用于查断线、毛边，不能代表游戏实际观感。
2. 大比例缩小时从高分辨率母版按浮点裁框一次重采样。此案例的 `Image.transform(AFFINE, ..., BICUBIC)` 在约2.6—2.9倍缩小下产生明显锯齿；同源、同裁框、同尺寸改用 `resize(..., LANCZOS, box=...)` 后，眼睛、发丝与衣领线条更平顺。结论针对这一调用和缩小条件，不泛化为所有 BICUBIC 用途都有问题。

   ```python
   x, y, crop_w, crop_h = rect
   cropped = source.convert('RGBA').resize(
       (target_w, target_h),
       Image.Resampling.LANCZOS,
       box=(x, y, x + crop_w, y + crop_h),
   )
   # 再按已确认的本尺寸 canonical 外框约束源 alpha。
   ```

   `box` 须在源图范围内；需越界取景时先透明补边并平移裁框，不能直接截断裁框改变构图。保留原母版，不对已经产生锯齿的旧缩略图仅作放大或锐化。small 按该角色已有的原生小图流程同步派生、核对，不能留下旧采样的小图。
3. 保持裁框、尺寸、蒙版和源图一致做新旧对照，在白底/深底、原生1:1与局部放大检查五官、细线和透明边缘。最终候选编码后须重新解码读回；PNG无损编码、尺寸正确或几何检查通过，均不能代替清晰度检查。修改实际生产工具和候选后，再刷新预览、配方及台账，不能只换网页图片。
