# StarPoint CN 整角色制作：阶段编排

用于从原稿、已选素材或局部返修推进到可独立读回的完整离线候选。本页管理阶段、输入身份和交接；专题细节沿用现有流程。离线制作不授权写源仓、资源链、服务、账号、客户端或发布，游戏接入须另有授权。

## 开始前锁定一份台账

1. 读取任务的 CURRENT／productionBrief／declarations，解析当前配方、候选和验收回执；名称含 final、最后修改时间和历史 PASS 均不决定当前选稿。缺少当前选择时先列缺项，不猜测采用状态。
2. 列出本轮允许修改的组件、保护对象、输出目录和完成范围。记录原稿、干净母版、官方来源、已选组件及配方的路径与 SHA；当前对象与条件未变时复用有效检查，重新生成或组合后补受影响检查。
3. 新角色用[整角色台账工具](../scripts/character_production.py)生成空阶段单、音频计划、`preview-spec.json` 和可直接打开的 `preview-start/index.html`，再填入真实输入快照和证据；续作不重新初始化，具体角色配方继续由其既有工具维护。以下从技能的 `scripts` 目录执行，先运行 `--help` 核对当前参数：

   ```powershell
   python -B character_production.py init --out <workspace>/work/<新任务目录> --character-code <角色代码>
   python -B character_production.py check --manifest <新任务目录>/character-production.json --report <新报告路径>
   ```

   schema 1 的九阶段为 `brief / mechanics / illustration / ui / pixel_motion / active_fx / audio / assembly / preview`，各自分 `content / offlineChecks / review`。顶层 `inputs` 锁定素材、spec、候选资源索引及相关实际文件身份，声音计划的 `audio-plan.json` 列出必需槽位并作为 hash 输入保护。候选／预览索引须展开实际叶文件登记，stage 快照按影响输入范围绑定，不把全部输入绑定全部 stage；报告本身变化不等于内容变化。检查回执同时绑定台账和检查器身份，防止旧回执冒充当前结果；完成项绑定输入快照及证据；只锁报告不会自动保护其底层资源，工具仅检查实际登记的完整性和 SHA 是否仍对应。空阶段单、登记 done 或组件旧 PASS 不等于事实验收。它不生成美术，也不替代原生编译、解析器、审美、最终候选独立检查或游戏测试。

## 默认提供离线预览

后续 MOD 角色制作默认交付可直接打开的离线预览，并随制作进度更新，供分阶段确认立绘、UI、动作、特效、声音和数值；不必等全部做完才展示。制作中、离线内容完成与游戏已验证分别标注，缺项留在清单中，不静默隐藏或沿用旧角色内容。

现已提供[通用离线预览模板 V1 与命令](character-preview-template.md)。固定五栏目与通用控件，由每个角色的 `preview-spec.json` 填入标题、形态、实际素材、动作范围、视口、缩放、音频、数值和检查状态。UI 和动作栏目从最终资源清单对账；特殊形态、召唤物按清单扩展。普通动作复用逐帧播放器，特殊技能 V1 展示完整视频，需要专门交互时保留对应案例播放器。实际素材用相对路径随文件夹交付，便于离线查看及分享；不将制作过程的私人记录或凭据混入分享包。

新角色制作从此入口开始；`init` 自动产生可审阅的缺项页，后续每个审阅阶段运行 `character_preview.py build --spec <清单> --out <新版本目录>`。生成器按文件身份及资源到展示映射检查，缺项不静默隐藏，历史预览不覆盖。万圣稻穗旧页面继续保留，模板适配示例不替换其当前采用稿。模板统一审阅方式，不保证一键生成角色、跨角色美术质量或游戏验收；入口静态/受控验证与未来自然任务复用分开。

| 交付与游戏待验 | 配方、候选、预算、预览和交接引用同一身份；说明已做、未做及仍需决定的项。按实际运行环境核对资源版本后，再由另行授权的游戏任务接续。 | 获取／进化／玛纳／存档、战斗机制、连放／中断、声音与设备验收分别列明；离线完成保留 `gameIntegrated=false`、`deviceVerified=false`、`releaseReady=false`。 |

预算在编排时先估、原生输出后实测，分别给主动子集、人物图集、角色声明资源集合和具体战斗加载范围。未知依赖不得按零计，含 margin 的实际图集或有限集合装箱不证明完整队伍、Boss、GPU或设备容量。方法见[原生预算规则](client-cdn-resource-safety.md#character-battle-atlas-packing-budgets)。21×20、6倍显示、特定帧数、伤害时点、参考响度及预算比例均属案例参数；新角色重新确认。

母版采用前先过**同场景人物体量**检查：对原型及邻近官方角色做同动作、同原点/脚底、同原生缩放的比较，单列纯人物可见框、着色量和耳尾/脸/衣服范围，并合成组队列表格子与获取台座视图。仅看原生1:1、网页放大或表面满足scale6都不够；若同场景显著压过官方主体，应在扩全套动作前重设计。动作展开与FX外框不受待机同一bbox硬裁；19×16等个例不是统一尺寸上限。尺寸变更要同时审normal、special、技能caster替身和脚手/道具锚点，不得只换待机。参考已确认尺寸失配与原生证据（历史本地记录）。

获取/进化全文交付前读取最终speech转义原文，禁止固定字符数断行；结合原生SpeechBalloon字体/宽高和自动折行检查，字数估计不替代首次获取画面。异常硬换行优先最小删除，保留原词句与录音，核其他行/角色压缩记录不变；进化同控件需回归。具体例证见获取文本修正（历史本地记录）。

### 完整动作预览须有清单对账

从最终原生 `normal / special / multiball` 实际时间轴生成动作清单，对账每个序列、范围与原段帧数，再提供单段选择、逐帧和连续查看入口。待机、正反移动或获取演出几个页面不能代替完整动作预览；技能就绪、倒地、灵魂出现/待机、复活和完整胜利序列也须能查。固定胜利选帧与整个胜利序列分开展示。连续查看中为看清短段而延长停留时明确标出，单段仍保留原始时长；不能将网页延长的帧数写成新增原生动作。

同时核对原稿独立像素画面是否实际进入原生图集，区分文件数、重复画面、槽位数与独立绘制的连续动作。两张人偶姿态复用六个槽位，不等于六套独立动画。浏览器逐项选择与帧数检查、全部原生帧读回、审美和游戏运行分别记录。已验证方法见动作入口检查（历史本地记录）与原生帧覆盖（历史本地记录）；后续角色仍从其 CURRENT 解析实际集合。

## 工程收尾与临时产物

角色内容交付、Git 工作树退役与整个制作任务收尾分别判断。schema 1 的九阶段通过只覆盖所登记的内容和证据，不包含临时产物已处理的结论；移除一个工作树、整理 CURRENT 或交付包校验通过，也不证明整个角色工程已完成收尾。

1. 从 CURRENT 和既有任务记录列出本角色实际涉及的制作目录、输出目录及临时工作树；逐范围核对，不能只处理当前 PR 的工作树便停止。仅检查本任务路径及必要引用，不扩成全工作区扫描。小修或局部交付按本轮范围，不重复清点未变化的整个角色工程。
2. 按现有任务收尾与产物退役方法（历史本地记录）处理自产临时物：先固定正式素材、当前预览依赖、重建输入、必要回退和证据；再检查重复构建、解包、抽帧、测试副本和缓存。旧目录仍被重建脚本引用时保留；不能因要保留历史稿，就跳过混在同一工程内的可退役中间物。执行沿用该方法链接的清理技能及当前授权；只读、暂停、共享材料与用户数据边界不变。
3. 在同一份任务收尾记录简要写明各范围的实际结果：已检查并清理、已检查后保留及原因、尚未检查或处理受阻。核对实际移除结果及受影响的保留项后，才报告对应清理完成；存在未检查范围时明确尚缺哪项，不能仅凭内容完成或局部 PASS 宣称整个工程收尾完成。不新增后台扫描、推送钩子或独立检查平台，也不重跑无关构建与游戏验收。

## 状态与失败处理

- 阶段分别记录工程检查、实际查看／播放、审美采用和游戏验证。专题验收记录可以写 fail／不适用及理由；schema 1 台账不支持 fail／NA，存在错误或尚未处理的不适用项时，相关 `content`／`offlineChecks` 保持 `pending`，在 `review.reason` 及引用证据中说明，不自造状态或登记通过。其完成状态分别为 `done`／`pass`，review 为 `approved`；`audioVolumeReview=deferred_to_game` 允许按声明完成离线工作，只表示音量听感已明确延后到游戏，不抵充听审批准或游戏通过。工具永不认定 `game_testing` 通过。
- 发现身份、造型或运动错误时回到最早失效阶段；原生读回和预算通过不能覆盖人物不像、没有起跳、尾部假转身或物理因果错误。局部采用不能推广到全段，旧稿的有效工程证据可保留，失效美术不作采用模板。
- 修改已认可人物后重新看实际 PNG 与最终合成；只改 FX 时锁住人物，仍检查效果是否挡眼、遮手或从隐藏道具发出。检查器不能以哈希数、姿态参数数、颜色数量代替绘画与正常速度判断。
- 台账校验只证明证据结构与身份符合其约束。一个角色的回放通过不能宣称一键全自动制作、跨角色批量质量或游戏可玩性已验证；下一角色实际结果才是复用收益证据。

## 万圣稻穗案例怎么读

由CURRENT-PRODUCTION（历史本地记录）读取当次实际路径和身份，再读其 recipe、acceptedComponents、acceptanceReport、offlineReport、budgetReport 与 previewReport。不要在通用入口固定某版为“当前”。历史 V1 检查器不验证 schema 2；旧 V3／六句记录保留其原有范围。

本次编排依据是 V6 配方（历史本地记录）、总装验收记录（历史本地记录）及最终候选独立读回（历史本地记录）：该版本仅校正9个声音资源，保护其余264资源、17表及既有玩法／人物／UI。七条文字与声线认可和编码响度检查属于各自证据；旧记录的 pending volume listening 不要求补做网页批准，音量听感按当前完成范围记 `deferred_to_game`。V6仍是冻结基线上的离线候选，未证明目标测试服覆盖、完整战斗、游戏听感或设备通过。

可照着填写的实际台账示例（历史本地记录）及本次身份核对回执（历史本地记录），是人工登记既有 V6 工程结果后，对实际登记输入及证据文件做 SHA 新鲜度检查；本次没有重新执行这些原生工程检查，工具也不读取报告的 PASS／FAIL 含义。回执的 `contentComplete=true`／`offlineEvidenceComplete=true` 表示登记完整；音量仍 `deferred_to_game`，`gameVerified=false`，不能据此批准听感或游戏验收。
