# 角色改动素材提交指南（给素材提供者）

这份指南用于别人委托“修改已有角色”或“基于已有角色制作新角色”时准备材料。

提交者只需要提供**创作内容、明确需求和不能由现有资源推导的源素材**。不需要理解 CDN 哈希、
AMF3、atlas、ATF、PNG 混淆、MP3 存储格式或补丁版本；这些技术产物由制作方生成、转换和校验。

可直接发给提交者填写的空白表见[角色改动委托包模板](角色改动委托包模板.md)。
制作方在对方动手前应先按[角色专用参考包模板](角色专用参考包模板.md)导出对应角色当前版本的只读参考包。

允许两种提交方式：

1. **最小源素材包（推荐）**：只交需求单、立绘母版、真正改动的像素帧/语音/特效源素材；
2. **原始完整导出包**：如果已经像本次泳装希尔媞一样拿到完整资源导出，可以原样提交，不要自行删除
   JSON、拆分帧或预览文件，也不要重新压缩 sheet。制作方会分类、比较并决定哪些是权威输入。

## 0. 先提供角色专用参考包，不能只发通用模板

不同角色之间存在实际契约差异，不能让所有人照同一套文件名和数量盲改：

- 稀有度不同：★4/★5 获取演出需要 `special_land/special_pose`，低稀有度的使用方式可能不同；
- 普通和特殊像素动画的帧数、去重 cell、sheet 尺寸、偏移和时间线不同；
- UI 图集的实际尺寸与 cell 布局可能不同；
- 主动技能可能有不同数量的等级/进化行、不同 ActionDsl 和一个或多个特效引用；
- 部分角色有第二形态、`switched_action_skill`、独有状态图标或额外客户端补丁；
- ally/battle/home 的语音文件名和条数按角色模板变化；
- 剧情表情、横幅和剧情电影不是所有角色都拥有或使用。

因此流程应是：

1. 委托者先只提供“目标角色、修改原角色还是新建、想改哪些部分”；
2. 制作方从当前 CDN 终态导出该目标/模板角色的只读参考包，并记录资源版本与摘要；
3. 参考包提供人类可读的数据、拆分像素帧、预览动画、UI尺寸、语音槽位和主动技特效引用；
4. 委托者只修改参考包中的 `return/` 区域，或提交自己的原始完整导出包；
5. 制作方把回收内容重新编译、重定向、与当前终态比较并发布。

参考包中的 `reference/` 是只读基准，不能让提交者直接覆盖 AMF3、atlas 或表二进制。需要改数值时，
应填写人类可读的改动表；需要改美术时，提交透明源图或与参考帧同名的替换帧。

## 1. 所有委托都必须先写清楚

无论是否附带图片或压缩包，都应提供以下信息：

1. **目标角色**：角色名称和角色 ID；不知道 ID 时提供游戏内名称与截图。
2. **改动方式**：修改原角色，或以原角色为模板新建独立角色。
3. **模板角色**：希望复用谁的动作、技能结构、特效和语音槽位。
4. **改动范围**：数值、立绘、头像、像素小人、技能切入、主动技特效、语音、剧情分别是否修改。
5. **基础/进化状态**：两套都改、只改一套，或允许两套暂时共用同一素材。
6. **复用决定**：哪些内容明确沿用模板角色，尤其要单独说明主动技能场上特效是否复用。
7. **准确需求**：数值、触发条件、持续时间、叠加上限、目标、冷却等应写成确定值，避免只写“加强一点”。
8. **素材来源与授权**：说明原创、授权、开源许可或可使用的来源；没有授权的真人声线不能用于克隆。
9. **参考包标识**：填写制作方提供的参考包名称、资源版本和角色 ID，避免基于旧版本回传。

角色 ID、`code_name`、资源逻辑路径和补丁编号可由制作方检查冲突后分配，提交者不必自行决定。

## 2. 不同改动需要提交什么

| 改动项目 | 提交者必须提供 | 可以不提供，由制作方处理 |
|---|---|---|
| 只改数值/能力/技能 | 目标角色、精确改动说明、适用基础/进化态 | orderedmap、CSV 行、技能 DSL 二进制、客户端/服务端镜像 |
| 新建角色数据 | 名称、称号、属性、种族、性别、定位、模板角色、技能与能力设计 | 新 ID、`code_name`、表键、玛纳板编号、文本表格式、包清单 |
| 立绘与全套 UI | 基础与进化各一张透明全身母版；只有一张时说明允许复用 | full-shot 尺寸适配、头像、圆角头像、缩略图、战斗 UI、连锁 cut-in、插画图集 |
| 技能 Cut-in | 默认可从母版派生；若要求特殊构图，提供独立透明源图或构图示意 | 1024×512 裁切、Android ETC1 ATF、iOS ETC2 ATF |
| 像素小人只换配色 | 目标配色表或清晰参考图，并指定模板角色 | 从模板提取帧、调色、重打 sheet、atlas/frame/timeline 路径重定向 |
| 像素小人更换服装/轮廓 | 每个变化帧的透明像素 PNG，或明确接受近似重绘；同时指定模板动作 | 去重、排版、sheet/atlas 重建、AMF3 编码、GIF 校验 |
| 主动技特效复用 | 明确写“复用某角色的主动技特效” | 原特效路径检查、技能 DSL 引用与存在性校验 |
| 主动技特效换色/重皮 | 模板特效、目标颜色/纹理参考；最好提供一张目标效果样张 | 在保留原 parts/timeline 的前提下处理贴图、重建图集和改路径 |
| 完全原创主动技特效 | 游戏可用的 parts/timeline/PNG/atlas 四件套，或指定一个可复用骨架并提供新贴图；仅有概念图或 GIF 不足以制作全新 Flatomo 动画 | 技能 DSL 接线、路径重定向、引用检查和真机验证 |
| 更换语音 | 已授权的逐条音频，并说明对应槽位；自定义台词时同时提供台词表 | 裁切、响度处理、重命名、CBR MP3 转换、游戏存储编码 |
| 剧情与表情 | 剧本文字、出场顺序、需要的表情原图和横幅源图 | 文件命名、尺寸转换、资源发布与剧情数据接线 |

如果某一项明确沿用模板角色，就不必重复提供该项素材。制作方会直接从当前游戏终态提取，不能要求
提交者重新打包游戏中已经存在的文件。

## 3. 两张立绘母版可以派生什么

推荐提交：

```text
masters/base.png       # 基础状态
masters/awake.png      # 进化状态
```

要求：

- 透明背景、完整全身、人物和武器不要被画布截断；
- 推荐使用无损 RGBA PNG，分辨率尽量不低于 1440×1920；
- 两张图应是同一人物，脸、发色、服装关键特征保持一致；
- 如果只有带背景的参考图，应另外说明允许抠图或重绘，不能保证与原图逐像素一致。

有这两张母版后，制作方可以确定性派生 full-shot、技能 Cut-in、各尺寸头像、升级/编队缩略图、
战斗控制板、成员状态图、连锁 Cut-in 和插画切换图集。因此默认不需要提交二十多张重复裁切小图。

如果某张 Cut-in 或头像必须使用特殊表情、姿势、文字或构图，则单独提供该张源图，并在需求中标明
“禁止从母版自动裁切”。

## 4. 像素动画怎么交最可靠

只改颜色时，不需要提交 sprite sheet。提供模板角色和目标配色即可。

服装、武器、发型或轮廓发生改变时，推荐提交透明拆分帧：

```text
pixelart/normal/<模板帧名>.png
pixelart/special/<模板帧名>.png
```

拆分帧应保持模板动作的姿势、画布边界和透明定位；文件名最好对应模板 atlas 中的帧名。制作方可以
负责去重、排版和重新编码，因此不要求提交者制作 packed sheet。

如果动作顺序和模板完全相同，只需写明模板角色；atlas、frame 和 timeline 可以从模板提取并重定向。
如果新增或删改动作，则还要提供一份普通表格，写明：

- 动画名称；
- 帧顺序；
- 每帧持续时间；
- 循环/单次/停留方式；
- 相对角色中心的偏移。

预览 GIF 可以附带，但只用于确认观感，不能代替透明原始帧和时间信息。

## 5. 主动技能场上特效必须单独选择

像素目录中的 `skill_ready` 只是技能蓄满动作；`special_land/special_pose` 主要是高星角色获取演出。
它们都不是主动技能的独立场上特效。

主动技能特效位于 `battle/effect`。委托者必须在需求中选择一种：

1. **复用**：写明复用哪个角色，最省材料；
2. **重皮**：写明模板特效并提供目标配色/纹理；动作和时序保持模板不变；
3. **完全原创**：提供可用四件套，或至少指定可复用骨架并提供与其 cell 对应的新贴图。

完整四件套的逻辑形态是：

```text
battle/effect/<目录>/<效果名>.parts.amf3.deflate
battle/effect/<目录>/<效果名>.timeline.amf3.deflate
battle/effect/<目录>/<目录名>.png
battle/effect/<目录>/<目录名>.atlas.amf3.deflate
```

制作方能够修改技能 DSL 的数值、条件和资源路径，也能够对已有特效贴图换色或重皮；但仅凭一句描述、
一张概念图或一段 GIF，不能可靠生成全新的 parts 骨架、时间线和 SFX。

## 6. 语音材料怎么交

如果沿用模板语音，不需要提交任何音频。

如果更换语音，推荐按用途分目录：

```text
voice/ally/
voice/battle/
voice/home/
voice_map.csv
```

可以提交 WAV、FLAC 或高质量 MP3，不要求预先转换成游戏格式。`voice_map.csv` 至少写“文件名、用途、
台词”；若沿用模板文件名和槽位，可以省略映射表。制作方负责转换为游戏要求的 44.1 kHz、单声道、
固定码率 MP3，并进行编码往返检查。

零散的 `voice/words/` 通常是剧情/NPC 语料，不属于普通角色换包的必需项；只有剧情明确引用时再提交。

## 7. 不需要提交的技术产物

下列内容通常由制作方从模板提取或从源素材生成：

- 新角色 ID、`code_name`、逻辑路径和 CDN SHA-1 文件名；
- manifest、补丁版本、文件大小与 SHA-256 清单；
- PNG 游戏存储态、AMF3/raw-deflate 编码；
- Android/iOS 的技能 Cut-in ATF；
- 从两张母版裁出的头像、缩略图、状态图和 Cut-in；
- 未改动作时的 pixelart atlas、frame、timeline；
- packed `sprite_sheet.png` 和 `special_sprite_sheet.png`；
- `animated/*.gif`、`animated.zip`、`*_resized.png`；
- 游戏要求的 MP3 转码、零填充修复和存储编码；
- 客户端表、服务端镜像、发布包和回滚包。

提交者可以附带这些文件作为参考，但制作方会重新校验和生成，不能把它们当作权威源覆盖当前终态。

## 8. 推荐压缩包结构

只放本次真正发生变化的源材料：

```text
角色改动委托包/
├─ request.md
├─ references/                 # 可选：设定图、颜色、构图参考
├─ masters/                    # 改立绘/UI 时提供
│  ├─ base.png
│  └─ awake.png
├─ pixelart/                   # 改像素轮廓时提供
│  ├─ normal/*.png
│  └─ special/*.png
├─ effect/                     # 改主动技场上特效时提供
│  ├─ effect_request.md
│  └─ source/*
├─ voice/                      # 改语音时提供
│  ├─ ally/*
│  ├─ battle/*
│  ├─ home/*
│  └─ voice_map.csv
└─ story/                      # 有剧情需求时才提供
```

没有改动的目录不要创建，也不要复制模板角色资源来“凑完整”。

## 9. `request.md` 可直接复制的模板

```text
目标角色名称：
目标角色 ID（不知道可留空）：
改动方式：修改原角色 / 基于模板新建角色
模板角色名称与 ID：

基础状态是否修改：
进化状态是否修改：

数值与技能改动：
立绘与 UI 改动：
像素小人改动：复用 / 只换色 / 更换轮廓和服装 / 新动作
技能 Cut-in：从母版派生 / 使用单独源图
主动技能场上特效：复用（角色：___）/ 重皮（模板：___）/ 完全原创
语音：复用 / 更换
剧情：不做 / 提供剧情和表情

允许复用的内容：
明确不能改动的内容：
期望的精确数值、触发和持续时间：
参考资料说明：
素材来源与授权说明：
其他验收要求：
```

## 10. 本次泳装希尔媞压缩包的示例结论

本次包里有 25 张核心 UI、65 张新版像素拆分帧、6 份像素元数据、269 条语音、17 张可选剧情图，
同时还有旧 packed sheet、GIF、resized 预览和语音旁车文件。

如果以后按本指南重新提交，实现同类改动真正需要对方给出的主要是：

1. 目标角色与改动说明；
2. 希望精确采用的新立绘母版，或明确允许继续使用包内已经裁好的 UI；
3. 服装和轮廓已经变化的像素拆分帧；
4. 确实要替换的逐条语音；
5. 要启用剧情时的表情和剧情材料；
6. 主动技能场上特效选择“复用、重皮还是原创”。

不必要求对方同时提供 25 张派生 UI、packed sheet、ATF、AMF3、GIF、resized 图和补丁清单。本次包也
没有新的 `battle/effect`，所以其主动技能场上特效只能继续复用原版希尔媞；这应在委托说明中明确写出，
而不是从 `special_sprite_sheet` 猜测。

本次转换已经完成以下处理：角色内部路径统一重定向、普通/特殊 sheet 与 atlas 由拆分帧重建、MP3
规范化、Android/iOS Cut-in 独立生成、可选剧情资源单独发布。委托方真机测试目前未发现问题，因此可
将以下经验作为以后收包的默认规则：

- 原始导出包可以整包交，不要求提交者先理解或筛选技术文件；
- 制作时必须逐项分类，不能默认顶层 packed sheet 比拆分帧新；
- 拆分帧能结合 atlas 偏移还原预览动画时，应把拆分帧作为权威美术源；
- GIF、resized 图和旁车 JSON 可作为校验证据，但不直接当生产资源；
- 所有内部 `source_code` 都要重定向到角色表实际使用的 `target_code`；
- 主动技能场上特效必须在需求单中明确“复用、重皮或原创”，不能从 pixelart 文件名推断。
- 下一次若由制作方先提供角色专用参考包，应把目标路径 `wind_spgirl_swim`、来源路径
  `wind_spgirl`、当前技能特效复用关系和每套像素帧契约直接写进参考包，避免提交者靠目录名猜测。
