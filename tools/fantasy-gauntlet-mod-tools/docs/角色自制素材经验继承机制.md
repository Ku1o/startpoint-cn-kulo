# 角色自制素材经验继承机制

本机制用于把一次性的角色美术加工沉淀成以后能够重复使用、自动核验并安全发布的工程经验。它覆盖
立绘/UI、像素动画、技能切入、主动技场上特效、语音和剧情图片，但不把任何离线预览冒充成真机结论。

现有《角色改动素材提交指南》《新建角色资源包模板》负责说明“应该提供什么”和“怎样转换”；本文补充
“如何保存一个成功案例，以及什么时候允许把它当成后续角色的基线”。

## 1. 每个重要案例必须留下四层产物

1. **权威源素材**：保留原始压缩包或母版的 SHA-256、授权/来源说明、角色 ID、源路径与目标路径；
2. **可复现源规则**：用专用模块或声明文件记录路径映射、替换 cell、缩放/旋转、平台编码和音频规范，
   不能只留下最终 PNG、ATF 或 ZIP；
3. **自动校验**：固定输入哈希、atlas/frame/timeline 结构、输出哈希、ActionDsl 引用次数及“不应改变”的
   内容；任何漂移都应失败关闭；
4. **可视与真机证据**：保存逐帧/GIF 对比、客户端版本、测试场景、截图或录像以及验收结论。

最终发布物只是上述规则的派生产物，不能反过来成为唯一源头。`work/` 中的候选可删除、可重建，经验本身
必须留在工具规则、案例声明和测试中。

## 2. 案例状态必须分级

| 状态 | 含义 | 是否可作为正式复用基线 |
|---|---|---|
| `draft` | 只有素材或设计，还不能稳定构建 | 否 |
| `offline_verified_device_pending` | 可重复构建，静态结构、预览与自动测试通过，但尚未完成真机验收 | 否 |
| `device_accepted_reusable_baseline` | 指定客户端版本完成真机验收，行为与性能均无异常 | 是 |
| `superseded` | 已被更新的规则/素材替代，仅保留历史追溯 | 否 |

状态升级必须来自真实测试记录，不能因为用户确认设计、GIF 看起来正确或构建哈希稳定而自动升级。

## 3. 主动技能自制特效的最低门禁

- 三档/全部形态 ActionDsl 的特效引用均被枚举，每档只改预期次数；
- 独立路径的 PNG、atlas、parts、timeline 四件套闭包完整；
- atlas cell 数、逻辑帧尺寸、`fx/fy/fw/fh`、旋转标记与边界均通过校验；
- 时间轴、音效路径与触发次数有明确的“保留”或“修改”声明；
- 视觉层变换与命中框、伤害、移动、持续时间等玩法层变换分开记录；
- 预览统计只称为“可见 sprite 实例”，不得误写成 GPU draw call；
- 离线渲染器能递归绘制同一子组，不代表客户端 `PartsAnimationImageProvider` 已为重复实例分配足够对象；
  复制 Flatomo 子组前必须逐帧扁平化根动画并同步重算 `parts.a`，否则默认禁止同时复制；
- `parts.a` 与 `parts.i` 一一对应，含义是每张图片预分配的显示对象池容量。修改分组、段、循环、矩阵或
  时间轴后，必须满足 `a[i] >= 图片 i 在所有根帧中的最大并发实例数`；透明度为 0 但已经实例化的命令
  也必须计入，不能只数肉眼可见对象；
- 不允许只看“总实例峰值”判断安全。总峰值用于性能观察，`fetchDisplayObject()` 是否越界取决于每张图片
  的独立池容量；复制或克隆组也不能替代全局 `parts.a` 扩容；
- 对象池修正必须取 `max(原容量, 新并发峰值)`，禁止自动缩小原容量；输出报告应列明每个图片索引、cell
  名、修改前容量、所需峰值和修改后容量；
- 真机至少覆盖三档技能、单人、多人、连续施放、边界位置与低性能场景；
- 若修改增加贴图尺寸、atlas 面积或并发资源加载量，必须单独检查打包矩形/显存风险。

## 4. 149996 窄 X 主动技案例

保守回退方案的机器可读声明位于
`examples/149996_active_skill_effect.recipe.json`；完整双分支方案位于
`examples/149996_active_skill_effect_full_x_pool.recipe.json`。源规则位于 `wf_spgirl_effect.py`，通用池容量分析
位于 `wf_flatomo_preview_render.py`。

本案例已经固化的经验：

- `wind_spgirl` 是模板角色的内部资源路径，149996 的独立终态路径必须重定向为
  `wind_spgirl_swim`；路径映射不是改文件夹名字，而是同步修改资源内部命名空间与三档 ActionDsl 引用；
- 用户提供的 8 个透明部件只替换 atlas 对应 cell，保留原逻辑画布、锚点和其余 17 个 cell；
- 最初用 `±15°` 同时复制“角色残影轨迹”子组的方案虽然离线预览正常，却把可见实例峰值从 191 提高到
  238，并在 Android 真机触发 `F1125 / RangeError #1125`。堆栈首个业务帧是
  `PartsAnimationImageElement/fetchDisplayObject()`；后续复核确认并不是角度或 238 这个总数本身有问题，
  而是双分支让 12 类叶图片的并发需求翻倍，`parts.a` 仍停留在单分支容量；
- 原版 25 项 `parts.a` 与逐帧计算出的每图片并发峰值逐项完全一致，确认其对象池语义。完整 X 方案将
  `f/g/h/i/p/q/r/s/t/u/v/w` 的容量分别从 `3/5/12/3/14/15/2/2/3/2/2/7` 调整为
  `6/10/24/6/28/30/4/4/6/4/4/14`，总容量 `297 → 367`；
- 完整 X 保留 44 groups、25 image records，变为 226 segments、705 matrices；上下两条分支仍为
  `±15°`、夹角 30°，中心特效和音效各 1 次。97 个根帧全部扁平化后，每图片峰值均不超过新池容量；
- 修正后的完整 X 与最初 X 候选的动画预览 SHA-256 完全相同，二者视觉图、分组调用和矩阵相同；相对旧
  报错候选，决定性修复只有 `parts.a`。不能把“换了一个近似 X 外观”误写成根因修复；
- 运行安全方案把 `w` cell 的两条 `±15°` 视觉分支直接烘焙进 60×60 逻辑帧，运行时仍只有 1 条动画
  分支；parts 与原版严格保持 44 groups、225 segments、703 matrices、25 image records，除图片命名空间外
  逐字段一致。该 1.4.89 方案继续保留为已知可回滚的单分支保险方案；
- 中心特效与音效仍各 1 次，timeline 明文语义保持，玩法判定不变；
- 两种方案都会先锁验输入与编译哈希，只回收 8 个确认过的透明 cell，并从原版骨架重新构建。完整 X
  发布器只允许相对 1.4.89 写入 atlas、PNG、parts 三个逻辑资源，timeline、音效、ActionDsl 和角色数值
  必须保持不变；
- 1.4.90 已完成一次用户确认“很好”的真机冒烟测试，因此可确认视觉与即时释放正常；完整的三档、单人、
  多人、连续施放、边界位置及低性能记录尚未逐项登记，案例状态仍为 `offline_verified_device_pending`。
  只有完成案例声明中的全部真机门禁后，才能改为
  `device_accepted_reusable_baseline`，再供后续角色生成器或整合发布器默认复用。

## 5. 新角色管理面板不得遗漏

新角色“客户端能显示、游戏能发放”并不代表管理面板已经可用。管理面板的邮件发放和玩家详情还会读取
`docs/generated/character_table.json`，因此每次新增 `character_id` 都必须同时完成以下门禁：

1. `assets/character.json` 及角色专用服务端表已按键语义合并，禁止整表快照覆盖；
2. `docs/generated/character_table.json` 与同目录 CSV 都有相同 ID、名称、称号、稀有度和属性；
3. `/api/lookup/characters` 回读能找到新 ID，邮件发放下拉框和玩家详情均显示正确名称；
4. TypeScript 构建后同步 `out/routes/web_api/lookup.js`，本地运行镜像必须重启再做浏览器冒烟测试；
5. 发布验收应比较“本批新角色 ID 集合”与管理面板 lookup 集合，任何缺项均失败关闭。

管理面板接口还应以 `assets/character.json` 作为安全兜底：静态说明表漏更时，新角色至少要以服务端名称、
稀有度和属性出现在后台，称号留空，不得凭空编造。兜底用于避免角色完全消失，不能替代补齐正式说明表。

## 6. 真机通过后的提升动作

1. 在案例声明中登记测试客户端、资源版本、设备、单人/多人测试结果和证据路径；
2. 把状态改为 `device_accepted_reusable_baseline`；
3. 将最终输入哈希、输出哈希和已接受的性能边界加入回归测试；
4. 让后续整合发布器显式调用源规则，禁止直接复制 `work/` 候选；
5. 若以后需要修改角度、素材或声音，创建新修订并重新走真机门禁，不覆盖旧验收记录。

这样保存的不是“149996 的一套图”，而是一套可以迁移到其他角色、又不会把偶然成功当成通用结论的
资产加工能力。
