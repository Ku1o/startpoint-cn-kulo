# 角色专用参考包模板（制作方发给素材修改者）

本模板由制作方使用。收到“想修改某角色”或“基于某角色新建”的初步请求后，应先从**当前游戏终态**
为该目标/模板角色导出一份只读参考包，再让素材修改者动手。

通用提交模板只定义交流格式；真正的文件名、数量、尺寸、动画和技能引用，以这份角色专用参考包为准。

## 1. 为什么必须逐角色导出

不同角色可能在以下方面不同：

- 基础/进化立绘尺寸、UI 图集尺寸与 atlas 布局；
- 普通/特殊 pixelart 的帧数、cell 数、偏移、旋转标记和动作区间；
- 稀有度与 `special_land/special_pose` 获取演出要求；
- 主动技能内层行数、进化差异、program path 和 ActionDsl 命令树；
- `battle/effect` 引用数量、共用贴图方式和命中/SFX 时序；
- 是否拥有第二形态、switched skill、独有状态或额外客户端补丁；
- ally/battle/home 的实际语音槽位和文件名；
- 剧情表情、横幅、剧情电影和场景引用。

因此不能从另一个角色复制一套“37个空文件”让提交者填，也不能只发一张立绘却要求其猜像素帧和技能
特效结构。

## 2. 参考包应记录的身份快照

根目录放 `REFERENCE_INFO.json`，至少记录：

```json
{
  "format": "wf-character-reference-v1",
  "generated_at": "YYYY-MM-DDTHH:mm:ss+08:00",
  "resource_version": "当前资源版本",
  "character_id": "目标或模板角色ID",
  "code_name": "角色表实际code_name",
  "rarity": 5,
  "base_character_id": "如为新建角色，填写所用模板ID",
  "source_code": "原始导出包内部路径；没有则与code_name相同",
  "target_code": "回收后应使用的实际路径",
  "reference_sha256": "除本字段外的参考包内容摘要"
}
```

必须同时附 `README.md`，用普通语言说明：这次允许改什么、默认复用什么、哪些素材必须按参考帧同名
回传，以及主动技能特效当前是独立还是复用其他角色。

## 4. 人类可读数据怎么给

素材修改者需要的是“看得懂、改得明白”的参考，不是 orderedmap 或 AMF3 二进制。至少提供：

- 角色名称、称号、属性、稀有度、种族、性别、定位、武器；
- 基础与进化状态、HP/ATK 等级断点；
- 主动技每个内层行的名称、描述、槽需求、program path 和主要行为摘要；
- 六能力、队长技、玛纳板节点和实际生效范围；
- 独有状态、图标与技能引用；
- 所有语音槽位的逻辑路径；
- 主动技引用的每个 `battle/effect` 路径，以及是角色自有还是复用其他角色。

允许提交者在 `return/request.md` 或单独的 `*_changes.csv` 中写改动。`reference/data_readable` 永远保留
原始快照，便于制作方做前后比较和判断遗漏。

## 5. 美术参考怎么给

- UI：提供解码后的两张 full-shot、两张 skill cut-in 和一张 contact sheet；不必把25张小图全塞给对方。
- Pixelart：应把 packed sheet 按 atlas 拆成去重透明帧，并附 frame/timeline JSON 与逐动作 GIF。
- Active effect：列出 DSL 实际引用，提供贴图/cell、元数据和可生成的预览；必须注明这是技能场上特效，
  与 `skill_ready`、`special_land/special_pose` 分开。
- Voice：默认提供槽位和台词清单；确需替换声线且有权分享时再提供音频样本。

如果提交者只做颜色或纹理重皮，应要求其保持参考包的帧名、cell 边界和透明定位。若要修改动作结构，
则必须在回收包附新的帧顺序、持续时间、循环方式和偏移，不能仅交一个合成 GIF。

## 6. 发出前检查

- 角色 ID、`code_name`、资源版本来自当前终态，不从旧 ZIP 文件夹名猜测；
- 参考包中没有服务端环境变量、数据库、日志、账号信息或其他运行时私有状态；
- 所有参考文件有大小和 SHA-256，ZIP 无绝对路径、路径穿越、重复名和大小写碰撞；
- pixelart 拆分帧能按 atlas/frame/timeline 还原预览；
- 每个 ActionDsl 的 `battle/effect` 引用已列入清单；
- 语音槽位以该角色真实表引用为准，不按另一个角色的固定数量猜测；
- `return/request.md` 已预填目标角色、模板角色、参考包版本和默认复用项；
- 没有要求提交者制作我们能够生成的 ATF、AMF3、CDN 哈希、派生 UI 或发布包。

## 7. 回收后的制作方职责

提交者回传的是创作源和改动声明，不是可直接覆盖生产环境的补丁。制作方仍需：

1. 固定回收 ZIP 的 SHA-256并做安全分类；
2. 将回收内容与 `reference/` 逐项比较；
3. 以拆分帧/母版等权威源重建派生 UI、sheet、atlas、AMF3 和双端 ATF；
4. 把内部 source path 重定向到目标角色实际 `code_name`；
5. 校验 ActionDsl、主动技能特效、语音槽位和全部表引用；
6. 通过离线检查后再进入真机测试和发布流程。

本次泳装希尔媞包证明“完整导出包回收后重新分类与编译”可以稳定工作；下一步把角色专用参考包固定为
前置步骤，可以进一步避免旧 packed sheet、错误 `code_name`、漏交主动技特效和语音槽位不匹配。
