# 服务端有效数据源校验清单

游戏内容经常同时存在客户端表、服务端基础 JSON 和 `_cnmod.json` 扩展。发布验收必须检查运行时最终值，不能只证明其中一份文件写对。

## 发布前

1. 搜索运行时加载器，确认基础文件与扩展文件的合并顺序以及最终获胜的数据源。
2. 对重复 ID 同时更新所有镜像；若它们应当一致，增加深度相等断言。
3. 使用实际玩法调用的读取函数回读，而不是只检查生成脚本、客户端表或审计报告。
4. 概率池同时核对档位概率、池内总权重、目标权重、唯一 ID、票券入口和最终综合概率。
5. 通过确定性边界检查或大样本离线抽取确认目标条目可达。

## 交付前

1. 从已提交终态生成运行文件，不能从混有其他修改的工作树直接取材。
2. 本地运行镜像和云服覆盖包必须包含运行时最终获胜的扩展文件。
3. 重启后再次从构建产物调用实际读取函数，并比较源码、运行镜像和覆盖包成员哈希。
4. 客户端展示概率与服务端有效概率必须分别取证；两者一致才算通过。

## 990001 深渊池专项门禁

`assets/gacha.json` 与 `assets/gacha_cnmod.json` 中的 `990001` 必须完全一致。运行时由 `gacha_cnmod.json` 覆盖同名基础池，因此任何只修改基础文件的发布都应当失败，而不能继续启动并静默使用旧池。
