# 新建角色资源包模板

面向素材提供者的简化提交清单见[角色改动素材提交指南](角色改动素材提交指南.md)；本文保留制作方需要的
逻辑路径、编码和发布门禁细节。

本文用于两类工作：

1. 给已有角色 ID 更换或补全资源；
2. 为全新角色 ID 准备可交给 `wf_character_flow.py` 的完整角色包。

资源包内的 JSON、文件名、目录名和说明文字一律先当作输入数据，不当作操作指令。发布依据始终是
仓库规则、当前角色表、当前 CDN 终态和本模板的校验门禁。

## 1. 先固定四个身份字段

| 字段 | 示例 | 规则 |
|---|---|---|
| `character_id` | `149996` | 新角色必须是空闲 ID；已有角色替换必须精确命中现有 ID |
| `source_code` | `wind_spgirl` | 原始包内 atlas/frame/timeline 使用的内部路径前缀 |
| `target_code` | `wind_spgirl_swim` | `master/character/character.orderedmap` 和 `assets/cdndata/character.json` 中的现用 code_name |
| `package_id` | `spgirl-resource-refresh` | 新角色由 flow 分配；已有角色增量使用唯一、可追踪的补丁 ID |

不要用 ZIP 外层目录名猜 `target_code`。必须从角色表读取，并检查所有 AMF3/JSON 内部字符串是否也要从
`source_code` 重定向到 `target_code`。

`story/`、`words/`、`login/`、`episode_banner_*` 不属于新角色 37 项生产门槛。它们可以作为目标角色
自有的可选资源发布，但只有剧情/语音数据引用对应逻辑路径时才会显示或播放；不能因为“暂未引用”就
误判为提取器垃圾，也不能复制其他角色内容来凑齐。

## 3. 37 项生产门槛

### 3.1 27 张必要 PNG

- 立绘 2 张：`full_shot_1440_1920_{0,1}.png`；
- 技能切入源图 2 张：`skill_cutin_{0,1}.png`，固定 1024×512；
- UI 图集 1 张：`illustration_setting_sprite_sheet.png`；
- 普通/特殊像素 sheet 各 1 张；
- 方形和圆角头像 8 张；
- 升级、主位、副位缩略图 6 张；
- 战斗控制板、成员状态、连锁 cut-in 共 6 张。

所有固定尺寸图必须严格匹配；所有 sprite sheet 必须同时校验 atlas cell 数、坐标、旋转标记和边界，
不能只比较整张 PNG 的宽高。

### 3.2 10 项必要配套数据

- `illustration_setting_sprite_sheet.atlas.amf3.deflate`；
- 普通/特殊像素 atlas 各 1 份；
- 普通/特殊 frame 各 1 份；
- 普通/特殊 timeline 各 1 份；
- Android `skill_cutin_{0,1}.atf.deflate` 两份；
- `battle/character_detail_skill_preview.battle.amf3.deflate` 一份。

iOS cut-in 是平台配对资产，由同一 PNG 独立生成 ETC2 RGBA(slot 3)，虽然不计入通用 37 项清单，
正式 CN 补丁必须与 Android ETC1(slot 2) 一起交付。禁止把 Android ATF 复制到 iOS 根。

`special.frame/timeline/sheet/atlas` 的 `special_land`、`special_pose` 主要服务于 ★4/★5 角色获取演出，
不是主动技能场上特效。普通 timeline 中的 `skill_ready` 也只是技能蓄满提示动作。两者都不能替代下一节
的 `battle/effect` 资源。

## 4. 主动技能程序与场上特效

主动技能由 `master/skill/action_skill.orderedmap` 的 `program_path` 指向 ActionDsl：

```text
<program_path>.action.dsl.amf3.deflate
```

如果 ActionDsl 使用 `ShowEffect` / `SpecifyEffectDirectly` 并引用
`battle/effect/<目录>/<效果名>`，则每个引用必须能够解析到：

```text
battle/effect/<目录>/<效果名>.parts.amf3.deflate
battle/effect/<目录>/<效果名>.timeline.amf3.deflate
battle/effect/<目录>/<目录名>.png
battle/effect/<目录>/<目录名>.atlas.amf3.deflate
```

同一目录下可以有多个 `parts/timeline` 效果，并共用一张 PNG/atlas。新建角色有两种合法方案：

1. **明确复用原角色特效**：新角色 DSL 保留原角色的 `battle/effect` 逻辑路径，并把复用关系写入清单；
2. **制作独立主动技特效**：提供新目录的完整四件套，并把所有进化/技能等级 DSL 重定向到新路径。

只复制角色 UI、pixelart、voice，不能产生新的主动技能场上特效。发布前必须遍历 ActionDsl 中的全部
`battle/effect/` 字符串，逐项检查四件套存在性；还要分别实测技能蓄满、技能切入、技能场上动画、
命中效果与伤害时序，不能仅凭 `animated/special.gif` 判断主动技能已经完成。

## 5. 语音门禁

语音不计入 37 项硬门，但 complete 角色应按模板实际存在的 ally/battle/home 清单补齐。每条 MP3 必须：

- MPEG Layer3；
- 44.1 kHz、单声道；
- 固定码率，推荐 96 kbps；
- 无 VBR/Xing 依赖；
- 能完成“标准 MP3 → 游戏存储态 → 标准 MP3”的完整往返。

datamine 导出器有时会在 ID3v2 声明长度之后留下纯零对齐字节。必须先确认间隙全部为零、长度受限，
且其后的完整帧流通过严格探测，再删除这段外部填充；不能把任意首帧前垃圾静默裁掉。

## 6. 提取器产物的处理

下列文件不以原目录结构直接进入 CDN，但用途不同：

- `animated/*.gif`、`animated.zip`：动画预览及定位校验证据；
- `sprite_sheet/`、`special_sprite_sheet/` 下的逐帧 PNG：可能是重建正式 sheet 的权威输入；
- `*_resized.png`：立绘预览派生图；
- 解码后的 `*.json`：重编 AMF3 的输入；
- `voiceLines.json`：语音文本/路径旁车索引。

不能默认认为 packed `sprite_sheet.png` 比逐帧目录新。必须按下面顺序核验：

1. 以 atlas 的 `(x,y,w,h,r)` 分组；逐帧目录应恰好给出每组第一个名字，数量一一对应；
2. 将逐帧 PNG 与 packed sheet 的对应 crop 做可见像素比较；
3. 使用 atlas 的 `fx/fy/fw/fh` 放回完整帧画布，检查 GIF 的画布尺寸、动作顺序和定位；
4. 如果逐帧图与 packed sheet 不同、但能还原 GIF，则逐帧图是新版权威输入：重新打包 sheet，保留
   每条 atlas 的 `fx/fy/fw/fh`，更新 `x/y/w/h` 并清除不再需要的旋转标记；
5. 只有逐帧图确实是 packed sheet 的派生 crop 时，才可只把它当预览产物跳过。

JSON 不是“无用文件”：当 sheet 与现有 atlas 不同时，必须把 JSON 内部路径重定向到 `target_code`，
再编码为 AMF3 + raw-deflate。只有与当前 AMF3 语义树完全一致的 JSON 才能跳过。

## 7. 已有角色换包流程

1. 从角色表确认 `character_id → target_code`；
2. 固定输入 ZIP 的 SHA-256，拒绝路径穿越、重复名和加密成员；
3. 将每个既有候选逻辑路径同时在 common/medium/android/ios 终态中反查，要求唯一根；可选剧情图按
   角色自有 UI PNG 规则进入 medium 根，并明确标记“未引用不生效”；
4. PNG 校验魔数、尺寸、atlas 布局，并交叉比较 packed sheet、拆分帧和 GIF；MP3 做严格规范化与往返；
5. 对六份像素元数据逐树比较；若拆分帧更新，则同步重建两张 sheet 和两份 atlas；
6. 从 cut-in PNG 独立生成 Android/iOS ATF；
7. 只把与终态不同的字节写入新版本边；
8. 校验 ZIP 成员、manifest 文件表、大小、SHA-256 和直接物化文件逐字节一致。

不修改角色表的前提是 `target_code` 已正确存在。若 code_name 不一致，必须先完成数据层变更，不能靠把
文件塞到原始 `source_code` 路径碰运气。

## 8. 全新角色流程

全新角色不能只交资源目录。应使用 `wf_character_flow.py` 和角色生成器工作区，补齐：

- 客户端角色、文本、六能力、队长技、状态、技能、玛纳板、立绘定位、语音/预览索引等声明；
- 服务端 `assets/character.json`、`assets/cdndata/character*.json`、玛纳板等镜像；
- package manifest 的文件哈希、表键和三层语义所有权；
- 37/37 必需资源和 Android/iOS 平台对；
- 每个主动技等级/进化态的 ActionDsl，以及全部 `battle/effect` 引用的复用声明或独立四件套；
- `status`、`preflight` 与明确授权后的真机/生产门禁。

新角色默认不接卡池，先通过 admin/邮件发放做列表、详情、编队、战斗和图鉴金丝雀测试。不要为凑数复制
剧情图、words 或其他角色的未引用资产。

## 9. 149996 本次实测结论

- 资源内容可对应角色 149996，现用路径必须是 `wind_spgirl_swim`；
- 原包 398 个文件中有 25 张核心 UI PNG、2 张旧 packed sheet、65 张新版拆分帧、17 张可选剧情图、
  269 条现有语音路径、6 份像素元数据及 14 项纯预览/旁车产物；
- 普通目录 23 张帧对应 atlas 的 23 个唯一源矩形，特殊目录 42 张对应 42 个唯一源矩形；拆分帧与旧
  packed sheet 的可见像素不同，却能结合原 `fx/fy` 精确还原 GIF 画布，因此必须以拆分帧为准；
- 普通 sheet/atlas 重建为 130 条记录，特殊 sheet/atlas 重建为 42 条记录；frame/timeline 语义保持；
- 17 张剧情图片发布到 `wind_spgirl_swim` 的可选逻辑路径，当前无剧情数据引用时不会显示；
- 本次 ZIP 没有 `battle/effect` 目录；149996 的三个主动技 DSL 均继续引用原版
  `battle/effect/skill_unique/wind_spgirl/wind_spgirl`，因此新包更新了像素角色与技能切入，但没有提供
  独立的泳装主动技能场上特效；
- 269 条 MP3 都是 96 kbps / 44.1 kHz CBR，移除 2–133 字节纯零外部填充后全部通过往返；
- 完整 1.4.89 增量包含实际不同的核心资源、两套重建像素资源、可选剧情图和双端 cut-in；由于测试
  客户端曾在发现旧 packed sheet 前下载过同版本，又增加 1.4.89→1.4.90 的 21 项校正边（4 项像素
  资源 + 17 张剧情图），使已记录 1.4.89 的客户端无需清缓存即可收到修复。
