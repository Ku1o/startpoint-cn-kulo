# CDN 增量手动检查工具

`cdn-http-probe.cjs` 用于实际下载/版本故障排查、受影响 HTTP 路由或准入改动验证、没有客户端但确需确认下发、或明确要求的 HTTP 验收。普通新增量与普通开服均无需运行；客户端正在实际下载并验收时，不重复下载同批资源。

工具从当前 manifest 读取版本边、包名、大小和 SHA-256，新增量无需修改脚本或重写探针。不启动、停止或重启服务，不改变 manifest、准入配置或资源文件。

在仓库根目录执行：

```powershell
# 默认：只查看最新已启用边，本地运行，不发 HTTP 请求
node tools/cdn-http-probe.cjs

# 按需：查询 Android/iOS 更新清单，不下载 ZIP
node tools/cdn-http-probe.cjs --check

# 需要模拟跨版本更新时，填入已知客户端资源版本
node tools/cdn-http-probe.cjs --check --from <RES_VER>

# 明确需要下载验证时才使用；每个共享包只下载一次
node tools/cdn-http-probe.cjs --download
```

默认范围是最高已启用版本的最后一条边。`--from` 才将范围扩展为指定基线到最高已启用版本，要求 manifest 中的边连续并具有完整大小、哈希元信息；不会请求该基线之前的历史版本或完整包。禁用的记录不参与选择。

最新边的 `depends_on` 是发布边起点，不代表设备当前已下载的资源版本。模拟指定设备时，`--from` 取该设备实际请求的 `RES_VER` 或明确提供的资源版本；未知时不猜测。APK/IPA 制作基线不能替代 `RES_VER`。`<RES_VER>` 是说明占位符，执行时替换成实际版本字符串。

`--check` 校验两平台 get_path 的目标版本、版本边和包清单、地址与声明大小；不代表下载哈希已验证。`--download` 在上述检查后流式下载所选范围内的包并核对大小、SHA-256，不保存 ZIP。下载地址固定请求本机 8001，避免跟随返回地址访问其他服务。

HTTP 模式复用现有 `.env` 和准入配置。新进程没有可复用票据时，使用当前启用的本地凭据完成正常握手；凭据、证明和票据只保存在内存，不写入输出或修改配置。请求支持原生 Base64 MessagePack 与 JSON 返回。

整个 HTTP 操作默认最多 10 秒，没有自动重试；大增量可显式传 `--timeout-ms`。服务未运行、清单不符或下载不符时直接失败，不开另一个测试服务，也不扩大到全链检查。

需要保存结果时使用 `--output <任务目录>/cdn-http.json`。结果区分 `offline`、`metadata` 和 `download`，记录实际下载次数；不把清单通过当作游戏内验收。若随后由真实客户端正常下载并验收，无需再重复使用工具下载同一批资源。
