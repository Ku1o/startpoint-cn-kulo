## 验证边界

`prepare_content.py` 只向指定工作区写入，并要求卡池仍处于融合前的基线；已经应用后不要直接在同一个目录重跑准备。重建需使用记录的融合前快照并重新比对最新有效资源链，不得覆盖现有候选。

`validate_content.py --work <工作区>/content` 校验 SHA、有效前像、严格 PNG、DSL 签名及回读、直接引用。该命令成功只表示这些检查通过，不表示可发布。

`audit_five_boss_terrain.py --work <工作区>/content` 在发布前使用严格检查器和 terrain_closure.py 核验地形。Single 参考点仅在独立证明每次创建一个对象后按一次回调分析，其他队形仍拒绝不明次数；召唤物递归检查正确等级、动作、状态和地形依赖。另补“同一地图两边都缺落点”的检查，避免只做移植等价比较时误判通过。repair_terrain.py 修复前，检查确实拒绝作者缺失落点的地图；修复后 22 场景通过。发布后当前清单已改变，不要直接重跑要求 .101 前像的准备/修复/发布入口。

运行服务端测试必须显式设置 `DATA_DIR` 到本任务临时目录。新测试自身创建隔离目录，但部分旧 TCP 测试会直接打开默认数据库。卡池客户端一致性测试在候选阶段需设置 `LENS_RESOURCE_CANDIDATE=<工作区>/content`；不设此项时当前旧 active 链与新服务端候选不一致，发布检查应失败。不要跳过这一差异。

`compare_clients.py` 已修正解码接口及常量池归一化，重新分析无解析错误。全量归一化差异包含死跳转等历史重写，不能直接当作应全部移植的玩法差异；Android 使用独立方法白名单、分支证明和 FFDec 回读保护累计基线。
