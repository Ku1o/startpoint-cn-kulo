# 数据继承服务端说明

## 行为

- 玩家在游戏内设置 8–64 位继承密码（必须同时含大写字母、小写字母和数字）。
- 标题菜单可直接输入玩家序号和密码，不会先创建临时账号。
- 若玩家已经进入游戏并生成了临时账号，再执行继承时，临时账号及其存档会在同一事务中删除。
- 被继承账号继续使用原 `account_id`、`viewer_id`、存档、账号备注和继承密码，只替换设备 ID 与客户端 UDID。
- 旧设备继续使用旧 UDID 请求时返回客户端原生错误码 `516`，不能再使用被继承账号。
- Google/平台账号入口返回客户端可处理的“不存在”结果，不再是 H404；本服只实现玩家序号 + 密码。

## 数据库迁移

第一次以新版服务端启动时会自动：

1. 给 `accounts` 增加 `admin_note`、`takeover_password`、`takeover_udid`。
2. 将旧 `device_bindings.name` 备注迁移到账号。
3. 每个账号只保留 `last_seen` 最新的一条设备绑定，并创建唯一索引。
4. 创建轻量 `account_transfer_audit` 审计表，最多保留最近 5000 次继承。

部署前仍建议使用管理面板创建一次完整数据库备份。

## 管理面板

- 备注改为账号级备注，换设备后不会丢失。
- 账号列表显示继承密码是否已设置、最近继承时间和被废弃的临时玩家序号。
- 管理员可生成一个仅显示一次的新继承密码；账号列表不会返回已保存的明文密码。
- “删除未备注账号”会在真正删除前再次检查账号备注、当前活动账号以及清理开始后刚完成的继承，避免竞态误删。

## 建议联调顺序

1. 先在管理面板给测试账号填写备注，并记下玩家序号、名字、等级和资源数量。
2. 原设备：游戏菜单 → 继承 → 设置继承密码。
3. 完全退出原设备客户端。
4. 新设备不要点击 `Touch to Start`，从标题菜单打开数据继承，输入原玩家序号和密码。
5. 确认预览显示的是原账号后执行继承。
6. 验证新设备存档与资源正常，管理面板备注仍在、设备 ID 已更新、存在继承记录。
7. 再启动原设备，预期被拒绝，不能同时使用同一账号。
8. 最后再测一次“新设备先进入游戏生成临时账号，再从游戏内继承”，确认临时账号和临时存档从管理面板消失，继承记录显示被废弃的玩家序号。

## 已执行验证

- TypeScript 服务端编译和管理端生产构建。
- 旧设备备注迁移为账号备注。
- 错误密码不修改账号或设备绑定。
- 游戏内继承删除临时账号及其存档、保留目标备注和密码。
- 标题页无当前账号直恢复，`abolished_viewer_id = 0`。
- 旧 UDID 返回 `516`，新 UDID 正常访问。
- 完整 HTTP + Base64 MessagePack 启动冒烟测试。
