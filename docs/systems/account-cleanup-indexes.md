# 账号清理：离线补齐级联删除索引

后台“删除未备注账号”会先检查所有 `ON DELETE CASCADE` 外键的子表支持索引。缺失时任务在删除之前停止；这次清理不会删除账号或存档。索引让 SQLite 根据关联列定位子记录，避免级联删除反复扫描整张表。索引齐全仍不保证单个大账号能在固定时间内删除。

已有数据库启动时只检查，不在线自动补齐。新建空库、首次新建相关空表时可以建立索引。已有大表须在停服维护窗口使用本页的独立入口。

## 只读预览

在实际项目根目录使用现有 `.env` 和 `DATA_DIR`，执行已构建的入口。以下是 Windows PowerShell 命令：

```powershell
node --env-file=.env out/cleanup-index-maintenance.js preview --project "$PWD"
```

省略 `preview` 也只做预览。输出实际数据库绝对路径、基础版本、维护锁是否存在，以及每个缺失项的 `table`、`columns`、`indexName`。只读取 schema 元数据；不清理账号，不备份、不计数扫描玩家表、不创建索引，不调用整套存储维护。

维护入口要求现有 `wdfp_data.db` 与匹配的 `.version` 文件，不新建空数据库。表名和列来自目标实际 schema，不按示例硬编码索引清单。

## 停服后应用

先核实目标项目并停止其服务、数据库工具及其他读写连接。这个入口不负责停服、启动或部署。`--offline` 表示已建立维护窗口；工具还要实际取得数据库独占锁。服务尚未关闭或仍有 WAL 读连接时可能拒绝，不能把参数本身当作已经停服的证明。

将预览返回的 `database` 原样填入确认参数；不要套用本机数据库路径操作另一台机器：

```powershell
node --env-file=.env out/cleanup-index-maintenance.js apply --project "$PWD" --offline --confirm CREATE_CASCADE_DELETE_INDEXES --confirm-database '<预览返回的实际数据库绝对路径>'
```

实际执行范围：

1. 核对目标、版本、旧维护状态和确认参数，取得 `storage-maintenance.lock`。该锁也阻止业务数据库重新启动。
2. 取得独占数据库连接，读取缺失项。已有索引完全满足时直接结束。
3. 在一个事务中只添加缺失的非唯一索引，并重新读取 schema 确认已补齐后提交。冲突或失败时回滚本批新索引。
4. 保存结果，关闭数据库，再核对锁身份并只释放本次取得的锁。

此入口不创建数据库备份、不计算备份哈希、不运行 `quick_check` 或 `integrity_check`。不执行存储结构迁移、不删账号或存档、不清领取历史、不运行 `VACUUM`，不改表字段、外键、账号归属或存档格式。新增普通索引不改变 V2 存档的列结构指纹。不要用现有 `maintain-cn.bat` 替代这条命令：其全套维护还包含迁移、历史清理和空间回收。

## 记录、失败与人工审核

结果状态位于实际数据目录的 `cleanup-index-maintenance-state.json`。此入口不创建备份目录，不替换真实数据库。

已有维护锁不会被接管或删除。旧存储维护没有结束、数据库路径不匹配、前次索引维护状态不明确时拒绝应用，原记录保留。正常失败且确认没有 DDL 提交时记录失败并释放本次锁，可以修正原因后重试。

进程突然退出、提交后记录失败、锁身份变化等情况会保留阻断或要求审核。SQLite 回滚未提交事务；已经提交的索引不会因进程退出自动消失。不要直接删锁或调用另一套维护恢复命令处理索引任务。先核对锁中的任务标识、状态中的 `phase`/`ddlCommitted` 与当前 schema，确认没有仍在运行的维护进程，再处理对应的解锁或继续步骤。

## 本地验证

针对性测试使用隔离临时合成数据库，不读取项目真实玩家库：

```powershell
node tools/run-isolated-check.cjs --test tests/admin-cleanup-index-maintenance.test.cjs
```

覆盖两种复合主键中 `player_id` 不在首位的实际结构、非空数据保全、只读预览、重复执行、确认参数和版本、旧锁与旧维护、禁止调用备份及整库完整性扫描、索引名冲突、DDL 回滚、WAL 连接占用、提交后错误及事务中进程退出。测试结果不能替代云服大库的耗时、磁盘空间与实际停服验收。
