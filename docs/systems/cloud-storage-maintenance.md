# Windows 云服一键维护

适用环境：Windows Server，通过 `start-cn-production.bat` 启动。2026-09-08 已完成实现、独立副本验证和用户授权的实际本地试运行，用户随后确认仅本地提交并制作云服包，不推送 GitHub、不操作云服。准确发布版本和包哈希以随包清单为准。

## 使用入口

发布时将三个引导 BAT、`scripts/maintain-cn.ps1`、`scripts/set-cn-temp.ps1` 和带校验清单的更新包按原目录层级放到云服项目根目录，也就是 `start-cn-production.bat` 所在目录。默认将更新包命名为 `storage-update.zip`。

**ZIP 由工具暂存、校验和应用，不要先手工覆盖解压。** 这样才能在更新程序前备份旧文件。包内仍使用项目相对路径，不增加额外项目外层目录；`_maintenance/manifest.json` 记录逐文件 SHA-256。

| 入口 | 作用 |
|---|---|
| `maintain-cn.bat` | 预检、停服、更新程序、备份数据库、迁移、清理、回收空间、恢复生产启动和验收 |
| `maintain-cn-preview.bat` | 只读检查数据库路径、大小、可用空间、保留规则和预计清理条数 |
| `maintain-cn-recover.bat` | 按上次维护的持久化阶段恢复；重新开放写入前可回滚，开放后继续启动验收并保留新进度 |

更新文件已经应用时，可以不带 ZIP 直接运行维护入口。重复运行跳过已完成的结构迁移；相同版本的程序按哈希确认一致后不重复覆盖、备份。暂存目录按包哈希复用。

正式交付的外层 ZIP 包含引导文件、中文说明和内层 `storage-update.zip`。将外层解压到项目根即可；内层保持 ZIP，不再手工解压。不能只上传 BAT 就当作完整升级，程序源文件、编译文件与入口按文末清单配套交付。

首次上传后，可先双击 `maintain-cn-preview.bat`。它自动从 `storage-update.zip` 暂存维护程序并读取云服数据库，不停止服务、不覆盖业务程序、不修改数据库；确认显示的数据库路径和空间信息后，在维护时段双击 `maintain-cn.bat`。预览和正式维护都不需要手工解压更新包。

## 首次执行

1. 从云服实际 `.env` 和 `DATA_DIR` 定位数据库，核对基础数据库版本 9，读取实际大小及空闲空间。版本文件缺失或不匹配时中止。不会导入本机拷贝或覆盖 `.env`、数据库目录、CDN、依赖目录。
2. 验证包成员路径、清单、SHA-256 和必需运行文件；拒绝受保护路径、越界、重复、缺项或校验错误。逐文件备份并用同目录临时文件原子替换。
3. 使用进程记录、启动时间、Node 命令与监听端口共同识别本项目的服务进程，不按名称批量终止 Node。维护临时目录沿用生产启动器的稳定项目目录。
4. 创建维护锁及独占数据库连接，通过 SQLite 备份 API 保存完整快照，检查备份并记录 SHA-256。
5. 任务定义提取到共享字典，计数引用整数 ID；玛纳节点、羁绊表使用紧凑主键布局。逐字段核对迁移前后数据，保留外键和有用索引。
6. 退役旧任务快照的在线物理表，其原内容保留在迁移前备份中；现行 `players_periodic_snapshots` 保持不变。
7. 按最近 7 天且每人最多 500 条清理领取历史，每次事务最多删除 1000 行；整理文件并检查数据库完整性。
8. 按现有生产参数恢复服务，核对新进程就绪记录、实际数据库路径和存储版本，再标记完成。

推荐编队同批修复：只读同一副本的真实通关快照，取消“曾通关玩家当前高战力队伍”补位，检查幻想装备适用范围。快照不足时返回实际数量或空列表，不需要清空推荐池或让所有玩家重打。

## 持久化

| 内容 | 位置和规则 |
|---|---|
| 永久进度、真实通关快照 | 云服现有 SQLite 数据库，后续换装、重启和程序更新不覆盖 |
| 存储版本 | `server_storage_migrations`，数据校验成功后在事务内记完成 |
| V2 兼容结构 | `server_storage_archive_schema`，存档仍携带完整文本键，整数定义 ID 不跨服携带 |
| 保留规则 | `server_maintenance_settings`，初始化只补缺失配置，默认 7 天/500 条/每日 04:30 |
| 清理状态 | `server_maintenance_jobs`，记录最近完成时间、处理统计、错误和互斥租约，不逐次无限追加记录 |
| 数据库维护记录和备份 | 实际数据目录中的 `storage-maintenance-state.json`、`maintenance-backups/` |
| Windows 控制器和程序备份 | 项目根目录 `.storage-maintenance/` |

自动清理使用真实时间；默认每日服务器本地时间 04:30。启动时检查上次成功时间，遗漏批次约 10 秒后补执行。失败或中断不记为完成，会重试；租约防止多进程重叠执行，进程退出后可到期回收。

现有 `RECEIVE_HISTORY_RETENTION_TIME` 继续生效。若 `.env` 的 `RECEIVE_HISTORY_RETENTION_ENABLED` 已关闭，预检会提示并中止应用，避免声称已启用长期维护；不会悄悄改写原开关。

数据库维护备份保留三份已结束任务的备份，并保留最近一份成功迁移前的原结构基线。未结束、无法识别或含额外文件的备份不自动删除。程序备份按实际更新版本保留；重复同版本维护不新增程序副本。

## 兼容和恢复

压缩后 `players_mission_counters` 是逻辑兼容视图，实际数据位于 `players_mission_counter_values` 与 `mission_counter_definitions`。新增、累计、最大/最小计数按新结构写入，查询及 V2 导入导出保留原始键和字段。

旧 V2 指纹继续可用，导入时重新关联当前数据库的定义 ID。退休的 `players_mission_counter_snapshots` 以空逻辑视图维持格式，旧存档导入通过 `skippedTables` 明确报告跳过。旧全量快照写入接口报退役错误，不会重新生成副本。

启动不会重建旧表；未知存储版本、版本标记与实际结构不符、初始化失败会阻止业务服务启动。维护锁存在期间同样拒绝启动数据库业务连接。

预检失败时尚未停服或改数据库。维护中断后使用恢复入口，不手动删锁或覆盖本机存档。服务重新开放之前，可以校验并恢复完整数据库和旧程序；进入启动阶段以后可能已有新结算，恢复入口只继续启动/验收当前版本，不自动回退数据。

WAL/SHM 在 SQLite 独占连接中检查并切换日志模式，确认 WAL 已回收后才处理残留临时索引。程序原子替换保证维护脚本自身在断电时仍为完整旧版或新版；迁移事务和完整备份分别覆盖迁移中断、后续清理/整理中断。
