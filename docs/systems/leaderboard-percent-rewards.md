# 排行榜百分比奖励

深渊连战的五档奖励依次覆盖前 2%、超过前 2% 至前 5%、超过前 5% 至前 10%、超过前 10% 至前 20%，以及其余有效上榜玩家。百分比对应的是各档累计截止人数，不是各档单独占比。

## 结算和展示

- 每赛季、每个玩家只保留有效完整通关的最佳成绩。百分比榜先排除已删除玩家，并按 `excludeBots` 配置排除机器人，再计算人数和连续名次；默认排除机器人。用时相同按完成时间、记录 ID 排序。
- 各档截止名次为 `ceil(有效人数 × 累计百分比 / 100)`，下一档从前档截止名次加 1 开始。整数百分比通过整数运算换算，避免浮点边界误差。有人上榜时第一档至少一人；无人上榜时不发奖；小人数导致的空档不展示、不发奖。
- 管理配置使用 `fromPercent` / `toPercent`，从 0 连续覆盖到 100。客户端仍接收 `fromRank` / `toRank`，最后一档非空时 `toRank: null` 表示末位。客户端不需要更新程序；重新获取排行榜数据后，报酬一览显示换算后的具体名次。
- 空榜时，报酬一览使用“按100人参榜预览”的明确标题展示五档奖励；真实人数仍为 0，结算档位仍为空，不会因预览产生奖励。有人上榜后自动切回真实人数换算的名次。空赛季结算后使用保存的规则快照预览，并标注“本期无人获奖”，不读取后来调整的奖励配置。此预览只用于客户端展示，不改变后台实际名次范围或结算计算。
- 游戏排行榜、玩家自己的名次、按名次查询队伍、报酬一览和后台使用相同人数与过滤口径。客户端 500 人显示上限不限制参与人数和结算人数。
- 已有 `1 / 2 / 3 / 4–15 / 16–末位` 五档配置首次读取时转换为百分比，逐档保留原有道具、数量、称号和图片。例如已在后台调整为 `5 / 4 / 3 / 2 / 3` 的数量不会被默认值覆盖。之前四档官方兼容配置仍按原有升级规则迁移。
- 已保存的 `1% / 5% / 10% / 20% / 100%` 五档配置读取时幂等更新为 `2% / 5% / 10% / 20% / 100%`，仅改变首档截止和第二档起点；奖品、后三档、截止开关及时间保持。其他自定义百分比不覆盖，已结算赛季继续使用原快照，不重算或重发。
- 原有其他固定名次配置仍可使用，但不能在同一组中混用固定名次与百分比。

以 200 人为例，五档分别为第 1–4、5–10、11–20、21–40、41–末位；100 人（含空榜预览）为第 1–2、3–5、6–10、11–20、21–末位；50 人则为第 1、2–3、4–5、6–10、11–末位。只有 2 人时，第一档为第 1 名，第二至第四档为空，第五档为第 2 名。

结算事务保存最终规则、换算档位、人数和逐人奖励；重复结算不重发。结算后的报酬和榜单读取已保存结果，后续调整配置、增加成绩、删除玩家或换季回看不会重新计算旧赛季。旧版结算没有档位快照时，从已保存的逐人奖励恢复其实际名次范围。

## 截止时间、独立冻结与自动发奖

后台的“到时冻结”和“自动发奖”共用一个“截止时间（北京时间）”。到时冻结可以单独开启；开启自动发奖时会同时开启冻结，不能单独关闭冻结。关闭自动发奖会保留冻结开关的当前值，两个开关都关闭后才停止定时操作。仅保存时间不会触发动作。

客户端仍使用已有排行榜状态栏，获取最新排行榜数据后更新，无需 APK 或 CDN 修改：

| 当前状态 | 状态文字（客户端另拼接“ / 共 XX 人”） |
| --- | --- |
| 开放中，未设置时间 | 实时更新 |
| 设置了时间，但两个开关都关闭 | 未启用定时结算 |
| 只开启到时冻结 | 截止：09-13 23:59 |
| 开启自动发奖 | 结算：09-13 23:59 |
| 冻结后尚未发奖 | 已冻结，待结算 |
| 已完成结算 | 已结算 |

冻结/已结算状态优先于时间显示。客户端为状态栏预留宽度，不再追加“（北京时间）”；后台仍明确标注北京时间。后台输入和服务端显示共用 `src/lib/leaderboard/schedule-time.ts`，明确按 UTC+8 解析和格式化，不受浏览器或服务器所在时区影响。

成绩开始和完成入口、排行状态查询都会检查截止时间，到点即停止接收新成绩并作废尚未完成的排行挑战。截止前开始、截止时或之后提交的挑战不再入榜，已完成成绩保留。定时任务每 60 秒检查一次，服务启动时立即补检查；只开冻结不会发邮件，管理员可审核后手动结算。自动发奖在定时检查时执行；邮件失败不会解除冻结，恢复后重试不会重复发奖。手动结算也先冻结当前赛季，再发放最终奖励。

重复间隔仅用于自动发奖计划；成功后推进到未来时间，但不自动换季或重新开榜。冻结模式保留当前截止时间，等待管理员处理。修改时间或关闭定时开关不会自动重新开放已冻结的排行榜；应更新/关闭过期计划后手动开启。已结算赛季必须先换季才可开榜。空赛季到期或结算后显示本期零人状态，避免误展示上期结果。

旧库启动时幂等补充 `leaderboard_settlement_configs.freeze_enabled`：原 `auto_enabled=1` 的配置继承冻结，原来关闭自动结算的配置保持冻结关闭，保留奖励、时间、重复间隔和邮件内容。
