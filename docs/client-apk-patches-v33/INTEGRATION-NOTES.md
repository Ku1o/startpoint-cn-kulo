# 采用范围与执行限制

本目录按历史补丁档案及功能移植参考收录。归档中的“最终”“主交付”“正式方案”描述来源批次，不表示当前生产入口或验收结果。当前客户端开发基线以 `client-patch/AGENTS.md` 及其指定的 Android、iOS accepted registry 为准；收录本档案不制作、替换客户端，也不采用归档中的 R4 构建结果。

## 已知限制

- **R4 资源模块仍有三项已识别回归。** #106 保留排队文件关闭可能丢写入且缺少完成通知、Context3D 恢复标记延后导致背景透明风险、轻量 decode 受 heavy 额度限制导致吞吐退化的问题。109–111 的超限 r2 没有修改这些资源路径，不能视为加载修复。
- **历史构建脚本尚不能按默认配置直接重放。** 归档缺少流水线默认读取的 `patch-list.json` 及对应 `r4-src` 输入；原路径和依赖也需要适配。部分脚本还在加载时导入 `quiet_process.py`，但该文件未收录。补齐这些依赖不能消除 R4 回归。
- **versionCode 不能替代 AIR 缓存身份。** 归档 v34 封包流程增加 versionCode 并替换 SWF，保留原 AIR 提取身份。后续修改 Android SWF 时，必须按现行客户端流程分配新的 `uniqueappversionid`，并核验最终包中 SWF、身份及签名；清除玩家数据不能作为正常升级步骤。
- **应按功能移植并补齐配套。** 归档 P-code 可能包含多个累计功能，不可逐条整方法覆盖当前载荷。应核对目标方法、调用约定、字段布局、数据和资源依赖，保留当前累计修复与存档兼容。iOS 另需核对原生/AOT 执行与配套关系；归档离线结果不代表当前载荷兼容或设备验收。

历史源码与构建记录用于定位实现及来源。实际采用某项功能前，需针对当前基线完成适配与对应验证；缺少全量重建材料不等于单项功能无法移植。
