# 结算归属保护、Rush 重试与请求诊断

觉醒任务可能保留未拥有角色的历史进度，固定编队也可能包含玩家未拥有的角色。结算入口和旧进度解锁入口按当前玩家角色表校验归属：未拥有角色的进度保留，奖励阶段保持待领取，不创建角色、不写入不存在父行的觉醒解锁。获得角色后可正常领取；已领取的消耗品奖励不重复发放。其他数据库写入异常仍抛出并回滚事务。

Rush 选层对相同活动、相同已选层返回成功，重复请求不修改队伍、回战、奖励或选层数据。不同层仍被拒绝，普通深渊无尽兼容与 EX 解锁门槛保持原有规则。选层参数须为正安全整数。

以上变更不新增数据库表、列、保存 ID 或存档格式，不迁移或批量修复玩家数据。既有 V1/V2 存档路径保持兼容，不需要客户端或准入配置更新。

## 诊断输出

`ROUTE_PERF_SUMMARY` 和 `ROUTE_PERF_INTERVAL_MS` 继续控制原有 `[PERF]` 汇总。启用时每个窗口增加一条 `[REQUEST-PERF]` JSON，不保存每个请求的完整记录。`ROUTE_PERF_SLOW_MS` 设置慢请求阈值，默认 2000 ms，最小 100 ms。

- `n`：本窗口结束的请求数，包括响应完成、请求中断与超时；同一个请求仅计一次。
- `statuses`：完成请求的实际 HTTP 状态码，以及中断/超时类别；游戏内拒绝仍可能是 HTTP 200，应结合 `outcomes` 查看。
- `outcomes`：有界原因分类，包括 Rush 重放、冲突、身份/参数/活动缺失、EX 门槛，以及外键、数据库忙和解析错误等。未识别异常合并为 `unclassified_error`。
- `top`：按累计墙钟耗时选择的最多 12 个路由。`failures` 另外保留最多 12 个有 HTTP 4xx/5xx、中断或超时的路由；全局状态和原因统计不受这两个显示截断影响。
- `p50UpperMs`、`p95UpperMs`、`p99UpperMs`：固定时间桶的分位数上界，不是精确分位数；最高桶显示 `>120000`。空窗口为 0。
- `slow`：最多 5 个慢请求、500 响应或中断/超时样本，包含路由模板、请求 ID、状态、阶段与字节数；其余仅累计 `omittedSlowSamples`。不包含原始 URL 查询参数、请求体、IP、凭据或玩家设备资料。
- `awake.skippedUnownedMissions`：未拥有角色的觉醒任务/解锁尝试被保留待结算的次数，不代表错误数或独立玩家数。最多保留 3 个任务与角色 ID 例子。

路由统计最多 256 个键，额外路由进入 `<overflow>`；未知地址使用固定键，不按原始路径扩张。窗口结束即释放明细，关闭 Fastify 时停止监控定时器及事件循环监测。

## 阶段含义

| 字段 | 边界与限制 |
| --- | --- |
| `receiveParse` | onRequest 至 preValidation，包含请求体接收、解析和此前 hooks。解析失败或提前返回时可缺失。 |
| `application` | preValidation 至 preSerialization；字符串等不经过 preSerialization 的响应计至 onSend。包含校验、守卫、业务处理和其间调度。 |
| `serialize` | preSerialization 至诊断 onSend，包含框架序列化及其间 hooks；某些响应没有此阶段。 |
| `customEncoding` | CN 服务自定义 onSend 的 MessagePack、Base64、可选压缩及其间异步等待。 |
| `sendRemainder` | 诊断 onSend 至响应完成，减去已测自定义编码时间；仍包含其他 onSend hooks、调度和发送等待，不是纯网络延迟。 |

所有阶段都是墙钟时长，不是 CPU 时间。当前只有已知字符串或 Buffer 响应统计 `responseBytes`；它是编码后负载大小，流式响应可能为 0，不含 HTTP/TCP 头且不代表对端确认收到。新诊断不改变请求超时或游戏重连宽限，不尝试根据一次极值自动调参。
