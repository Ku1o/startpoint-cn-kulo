# MOD 新角色制作复盘：中秋嫦娥“稻穗”

日期：2026-09-22

补充整理：2026-09-24

这份记录总结第一次从角色设计稿到本地可运行验收的完整制作过程，供后续作者填写、制作方核验和角色制作工具设计使用。文档只记录已经观察到的制作事实与稳定检查项；单个角色的临时数值不作为通用模板默认值。

上游作者的制作经验、实现依据和适用范围另见 [MOD 角色制作：上游经验与本地适用范围](MOD-CHARACTER-UPSTREAM-LESSONS-20260924.md)。该记录固定来源提交，区分上游案例、代码依据和本地已确认结果；旧方案中的限制不自动成为当前角色的限制。

## 换皮与全新角色如何使用本记录

- 换皮先确定是替换原角色外观，还是新增可独立持有的角色。新增角色即使复用原角色素材，也要分配独立角色 ID 和资源代码，并接入对应的成长、玛纳板、文本与显示资源；不能覆盖原角色的共享资源来实现新角色外观。
- 换皮优先继承已验证的动作时序、定位点、图集结构和可复用语音，再调整服饰、配色及指定特效。进化前后立绘和各页面裁图仍需分别制作；无需因为换皮而重做全部资源。
- 全新角色可以参考官方同类角色的资源规格与机制。按角色资料、进化前后立绘、页面裁图、像素动作、技能/PF 表现、语音、技能音效、数据接入逐项记录“复用 / 新制作 / 不适用”。这些是制作清单，不代表每项都必须原创。
- 稿主提供自然语言能力设计和美术、声音参考；制作方负责 ID 分配、原生机制判断、数值单位、ActionDSL 和资源绑定。不要让稿主猜底层字段，也不要把原生不支持的设想直接写成已实现。
- 先完成可运行的最小版本，再逐项替换美术与声音并预览；最终确认过的版本要有明确来源。制作清单和经验记录不需要转化成服务端或客户端新增运行时校验。

## 这次实际跑通的范围

- 角色有进化前、进化后两个形态，使用原角色的部分像素资源和官方战斗表现作为基础。
- 完成了角色资料、立绘/缩略图、像素小人、主动技能与 PF 的本地资源接入，完成了能力、队长技和状态图标的本地数据接入。
- 能力追击的飞行弹道最终复用官方光属性弹道并做外观调整，命中特效单独调整；PF 近身月光装饰因高速场景不可辨认而放弃。
- 语音经历了多次音色、音量和拖音调整；最终仍应把进化前后主城语音成对处理，不能只制作进化后语音。
- 在练习战中完成了实际运行检查。技能预览和静态图像检查不能替代练习战验收。

## 推荐的生产顺序

1. 作者填写角色概念、进化前后设定、能力文本和资源清单。
2. 制作方核对官方同类角色的字段、原生机制、可用伤害类别和资源尺寸。
3. 先锁定进化前/后立绘、缩略图、像素小人和图标，再制作技能/PF 帧集；角色语音与技能音效分别安排。
4. 将能力与技能文本转换为原生数据或 ActionDSL；显示文案和执行数据分别核查，同时明确施放停球时长、恢复移动方式、表现位置与声音事件。
5. 生成资源补丁，检查图集尺寸、帧序、压缩、透明度和版本链。
6. 在已指定的本地测试实例中，用练习战和匹配机制的队伍完成验收；需要临时角色数据时使用隔离实例，记录触发、数值和冷却证据。
7. 记录人工确认项和未完成项，最后再合并为云服增量包；本地开发版 CDN 不直接当作云服正式版本。

## 作者只需要填写的内容

### 角色基本信息

- 角色名、称号、属性、职责、种族、稀有度。
- 进化前名/进化后名、形态说明，以及两种形态是否共用技能和能力。
- 角色概念、外观关键词、招牌动作、色彩和特效关键词。
- 基础攻击、生命、成长方向、培养消耗。获取方式可暂留空。
- 角色 ID、文本 ID、资源 ID 由制作方分配或核对，作者不需要填写内部数据库键。

### 能力与技能文本

每一项只填写自然语言：

- 队长技：战斗开始、共鸣、Fever、回血、连击等触发条件和效果。
- 主动技能：动作、目标、范围、伤害/回复、持续状态和希望看到的特效。
- PF：PF 等级、伤害/辅助效果、是否全屏或近身、希望出现的拖尾/粒子/扩散效果。
- 能力 1–6：主位限制、触发条件、作用对象、次数/上限、冷却、持续时间和效果。
- 任何“不确定是否原生支持”的效果单独标记为疑问，不要求作者写 DSL、乘区或底层枚举。

制作方再将自然语言拆成段数、倍率、单位、对象、独立乘区、状态 ID 和 ActionDSL 节点，并把“原生支持 / 需要客户端适配 / 待核实”返回给作者确认。

### 资源与语音清单

- 进化前/后详情立绘、角色缩略图、队伍卡片图、主城/详情插图。
- 像素战斗小人、待机帧、移动/弹射帧、技能动作帧；透明背景和实际显示尺寸。
- 主动技能帧集：起手、飞行/弹道、命中、全屏或场地扩散、结束定格帧。
- PF 帧集：弹珠移动伴随效果、命中效果、场地扩散效果；同时记录图集宽高、帧数、压缩和同时在场预算。
- 角色图标、状态汇总图标、独立状态图标、减益图标、PF/技能图标。
- 进化前/后主城语音、获取/详情/强化/进化、战斗开始、技能、PF、胜利、失败/受击等类型。
- 每条语音记录日文文本、关西腔/音色参考、是否复用官方、音量、时长、文件名和游戏要求的编码/封装格式。
- 主动技能音效单独列项：起手、蓄力、飞行、命中、结束等声音事件与帧点、音量、循环次数、是否复用官方或新制作；技能喊声/准备语音不能代替技能音效。

状态可选“作者待提供 / 复用官方 / 新制作 / 待核验 / 不适用”，工具不得把缺失内容显示成已经完成。

## 已确认的问题与防错规则

| 问题 | 这次表现 | 以后检查 |
| --- | --- | --- |
| 立绘、插图为空 | 文件存在但客户端页面没有有效图像 | 逐页面检查实际读取路径、manifest、平台资源和透明度；不能只看源文件存在 |
| 详情立绘尺寸不合适 | 角色在队伍/详情界面被裁切或比例不自然 | 按官方详情槽位和缩放规则预览，分别检查进化前后 |
| 白背景遮住像素腿 | 白色腿与白底混在一起 | 透明背景；预览工具默认用深色棋盘或深色底检查 |
| 技能/PF 预览报错 | 预览只覆盖了部分动作或引用了不存在的帧 | 所有引用帧、图集边界、进化前后动作和结束帧做闭包检查 |
| 图集溢出/过大 | 早期特效超过官方专用图集预算 | 先统计实际图集宽高、帧数、压缩和同时在场部件；超预算时先删冗余帧，不靠盲目放大解决 |
| 弹道和命中特效混淆 | 自制弹道不流畅且和官方光属性难区分 | 优先复用官方弹道并做安全的颜色/材质调整；弹道与命中特效分别验收 |
| 反复改图导致外观漂移 | 连续修改后出现饱和度变化、服饰结构变形和手势不自然 | 保留确认过的母版；局部修改从母版或最近确认版出发，先看整图再看局部，不把失败改稿作为下一版基础 |
| 特效只在单独预览中好看 | 月亮在实战中遮挡敌人，位置和大小与场地不合适 | 明确特效跟随角色、跟随目标还是固定在场地；按实际场地尺寸、HUD 和伤害数字观察大小与遮挡 |
| 技能演出遗漏运动衔接 | 停球时长及施放后的移动方式没有在早期设计中单独确认 | 起手、伤害帧、结束与恢复移动一起设计；全屏伤害也要明确动作结束后的速度与方向规则 |
| PF 近身月光看不见 | 高速弹珠和身上 Buff 同时显示时几乎不可辨认 | 不再默认制作贴着弹珠的小月光；优先方向明确的拖尾、命中反馈或场地扩散 |
| 状态图标和描述不自然 | 黑底图标突兀，技术说明破坏官方图表化视图 | 汇总状态使用一个专属图标，独立计时状态（例如月行）保留独立图标；客户端描述沿用官方图表化布局，不把实现说明塞进角色文案 |
| 隐藏增益时间不受延长 | 原生强化时间延长不影响隐藏状态 | 若采用隐藏状态，固定时长必须和图标同步；需要受延长时改用原生可延长状态 |
| 状态图标与实际效果不同步 | 隐藏增益清理、独立月行触发不能仅凭汇总图标推断 | 分开管理各状态的作用对象、时长、刷新和移除；本角色的月满丰穰/月行采用固定 20 秒/8 秒，不能把此选择当作所有新角色的默认规则 |
| 提示文字被当成冷却失效 | 弹珠旁反复出现 SKILL 提示不足以证明某条返充突破 CT，队友效果会干扰判断 | 观察实际技能槽变化和触发间隔，区分该角色、队友、武器和自动技能；先定位来源再改能力数据 |
| 伤害类型与触发边界含糊 | PF、能力伤害、队伍攻击力、连击累计等自然语言容易被误解 | 先写清伤害类别、攻击力来源、段数、发动者、CT 归属与重置条件；连击清零和每 45 连击触发后的继续计数分别处理 |
| 伤害入口与客户端版本不匹配 | 早期客户端未接入作者分类规则；只改脚本名称不能改变伤害类别 | 当前作者机制客户端使用原生 629 调用 ActionDSL 并显式指定分类；旧客户端仍需适配。具体规则与证据边界见下方 2026-09-24 补充 |
| 语音 C8105 | 普通 MP3 直接放入 CDN 不满足游戏读取格式；缺少进化前语音也会报错 | 记录原始格式到游戏封装格式的转换；进化前/后语音清单成对预检 |
| 音色和音量不一致 | 生成语音拖音、气弱、音量小或不像原角色 | 以官方同角色全部语音作为参考，单独检查音量、时长、语尾和方言；新生成语音与复用语音做响度对照 |
| 技能喊声与技能音效混淆 | `skill_0`、`skill_1`、`skill_ready` 属于角色语音；本角色未配置专属技能音效事件，因此这项遗漏没有表现为缺失资源报错 | 交接表把角色语音和技能音效分成两栏；若需要专属音效，记录资源路径、事件帧、音量和复用/新制作来源；未配置事件与引用了不存在的音频是两种情况，不能混淆 |
| 退出训练场 H400 | 恢复弹窗取消请求可能没有 `play_id`，活动记录未清理导致下次登录重复恢复 | 以持久化活动战斗记录为权威接受缺失/空 `play_id`；非空不匹配仍拒绝；取消删除和历史写入保持事务回滚 |
| C3212 与服务端错误混淆 | 错误存档/客户端状态可能触发 C3212 | 先区分存档损坏、客户端资源版本和服务端请求错误，不要把所有错误都改成服务端兼容 |
| 测试方式不可靠 | 技能预览未真正开战，或使用错误测试队伍造成误判 | 使用已指定的测试实例、练习战与正确队伍；没有现成角色时用隔离夹具验证机制，不把某次模拟器编号固化为所有任务的默认值 |
| 临时资源链未回收 | 8011 代理曾通过临时 ZIP 提供高版本资源；实际测试成功的内容没有自动进入正式 8001 资源链，最终包会漏掉已经验证过的效果或语音 | 测试代理和临时 ZIP 只能作为取证来源；终态发布前必须盘点所有实际生效资源并合并到唯一的 8001 active 包，禁止保留第二条运行时资源链 |
| “测试包”标签掩盖了有效资源 | 旧包中有 12 个能力/技能特效文件和 7 条最终语音只存在于后续视觉补充包，按包名筛选时容易被误删 | 以角色数据/资源清单和运行时下载结果为准，不以“测试”“视觉补充”等名称判断是否保留；最终包逐项记录新增、替换和保持不变的成员 |
| 客户端资源常量与 CDN 不一致（仅限客户端同步任务） | 客户端确实改过资源版本或逻辑路径时，APK/SWF 与 active ZIP 不一致会造成缺少数据或预览报错 | 只有客户端资源常量发生变更时才对照 APK/SWF；普通角色数据或 CDN 资源更新不校验客户端本体。所有任务仍核对 manifest、逻辑路径、文件格式、图集闭包和 8001 实际下载结果 |
| 合并错误被误归因于缓存 | 旧数据覆盖或漏掉实际生效资源，即使清空存储重新下载也不能修复；同版本换包另有复用旧缓存的可能 | 先看本地日志、8001 实际返回和包内数据，查清来源与覆盖顺序；已有重新下载证据时不能反复归咎缓存。已发布更新按新版本推进；未发布包合并与缓存问题分别处理 |
| 源码与运行目录不一致 | 只修运行目录会使后续打包重新带入旧数据 | 在源码仓库修改，以明确文件清单定向同步到运行目录；运行目录保留本地状态，不作为发布源，不整树覆盖 |
| 内外网包被误当成功能基线 | 从较旧内网成品继续制作会漏掉后来验收的累计功能 | 涉及客户端修改时，从最新已验收功能版本派生内外网包，网络地址只属于打包配置；普通 CDN 更新无需重做客户端 |

## 工具必须提供的核验结果

- “作者填写页”：只显示自然语言、参考图和文件上传项。
- “制作方核验页”：显示原生字段映射、ActionDSL、伤害类别、单位、段数、倍率、冷却、状态和客户端限制。
- 身份核对：角色 ID、角色代码、文本/资源引用和技能唯一 ID 对齐，并确认没有占用已有角色 ID。
- 资源闭包检查：引用文件存在、进化前后成对、帧索引不越界、图集和压缩符合预算。
- 音频闭包检查：角色语音类型齐全、进化前后成对、封装/编码正确；技能音效另行检查声音资源、时间轴事件和复用/新制作来源，不能把技能喊声当作技能音效完成。
- 文案检查：普通视图和图表化视图都保留官方结构，能力图标、主位/属性标记和段落不被纯文本替换破坏。
- 导出/导入检查：旧工程可读取，新字段有版本和默认值，导出再导入不丢失作者文本、资源清单和语音状态。
- 发布检查：生成补丁前列出 CDN 起止版本、角色数据/资源清单引用的文件、测试状态和未完成项；云服正式基线与本地高版本缓存分开。

## 已实现扩展与剩余范围

- 早期 [通用伤害入口](../../client-patch/generic-damage/README.md) 保留为历史实现参考。2026-09-24 的当前方案已统一为 [作者伤害规则](../../client-patch/author-unified-damage/README.md)：原生触发条件 → 629 → ActionDSL 指定伤害类型，稻穗弹道、命中特效和必要预载独立保留。Android 单人验证、内网版本验收与 [iOS 原生移植的离线检查](../../client-patch/author-public-release/README.md) 分别记录，不能互相代替。未具备对应机制的旧客户端不能仅靠 CDN 获得此能力。
- 已确认的语音版本已并入角色包。进一步优化音色属于后续质量调整，不应误记为全部语音尚未接入。
- 主动技能专属音效仍未配置；需要补做还是保持无专属音效应独立记录。复杂自动施放决策和正式获取流程按后续实际需求处理，不能扩展成所有换皮角色的必做项。

## 本次新增复盘（2026-09-23）

这次终态合并补充了一个此前没有写清楚的发布边界：本地测试中真正生效的资源来源可能不止正式增量包，还可能来自代理、临时高版本 fixture 或后续视觉补充包。只把正式包按文件名合并，不能证明角色闭包已经完成；必须以角色数据/资源清单、实际下载内容和练习战结果共同确定最终资源集合。

本次最终包因此明确记录了 12 个补充特效、7 条最终语音和 142 个保持不变的正式资源，并把资源合同、合并报告和回归测试放入源码。离线回归测试用于防止本次合并遗漏：它会检查补充特效、最终语音、图集闭包以及 manifest 与 8001 active 包是否一致；只有客户端资源常量确实发生变化时才额外对照 APK/SWF。这些检查不进入服务端运行时，也不改变游戏内判定。以后不再通过 8011 代理或隐藏 ZIP 作为正式测试链，所有实际客户端测试都使用同一套 8001 服务、manifest 和 active 资源。

本次还确认了一个不会直接报错、但会造成交付不完整的遗漏：角色 ID `159991` 和角色数据已经进入正式角色包；中秋稻穗的 `skill_0`、`skill_1`、`skill_ready` 已作为技能喊声/准备语音接入，但没有单独登记主动技能音效资源及声音事件。以后必须在角色 ID 核对之外，单独确认技能音效是否复用官方、是否需要新制作，以及起手、蓄力、飞行、命中和结束事件的绑定；没有专属音效时也要明确记录为“不适用/复用官方”，不能因游戏不报错而默认为完成。

## 作者机制与角色返修补充（2026-09-24）

以下经验来自作者十二角色接入、稻穗调整、芙拉菲回槽修复及资源合并。版本号、角色 ID、列号和数值均用于定位本次证据；以后以实际有效资源链和对应客户端解析器为准。

### 原稿修订需要与当前实装做三方对照

作者可能以较早的设计稿继续修改。先对照“原稿、修订稿、当前实装”，提炼本轮明确变化；稿件与当前实装的所有差异不能直接当作待改清单。数值、新增效果、表现文本和原有适配分别判断，保留已存在的技能强化、PF 动作、状态生命周期、媒体及必要修复。

本次稻穗的普通弱化免疫沿用现有 `DebuffPrevent` 语义，没有扩展成对强制赋予也免疫。治疗触发、独立乘区、主副位等同样要看实际执行分支；一名角色的处理选择不成为所有新角色的默认规则。生成器应检查前置状态并拒绝不认识的输入，避免从旧表重建而覆盖后来的实装。

### 回槽无效与 C7050 是两种不同的目标字段错误

| 案例 | 已查明的原因 | 后续检查 |
| --- | --- | --- |
| 芙拉菲的回槽限制完全不生效 | 客户端已有 423 限制逻辑，但 `ability` 键 `1499872` 的规则行把可选目标筛选写成空字符串；该字段需要明确的无筛选值 `(None)` | 同时核对规则是否注册、作用对象是否命中、回槽来源是否正确。不能只见表里有 423 就认定数据有效，也不能直接判定 APK 漏做功能 |
| 稻穗进入详情触发 C7050 | 从贯通行复制并改成 `SkillGauge`（211）后，原效果忽略的目标字段仍为空；`LeaderAbilityValues.parseAt45 → parseAt46` 读取必填枚举时失败 | 更换效果编号后，按新解析分支补齐参数；本例必填目标为 `0`（Myself），并非 `(None)`。空值和合法但错误的全队目标都要进入回归 |

当前编码下，芙拉菲修复只改零基行 3、列 111；稻穗修复只改零基行 15、列 46。它们说明“空字符串、可选值 None、枚举 0”不能互换，不授权全表替换空字段。行宽正确、中文说明正确、ZIP CRC 通过，都不能证明原生解析可用。角色详情可能提前解析整组能力，因此没有进入战斗也会暴露执行字段错误。

回槽验证按来源分开：开场充能、移动充能、技能回槽、能力回槽，以及自身与队友提供的效果。对这次限制，应拒绝战斗中的技能/能力正向回槽，保留开场和移动充能；扣槽、零增量、嵌套调用恢复上下文也分别核查。能力来源、触发它的角色与最终获得回槽的角色不能混为一个对象。

证据与复现：[调整生成器](../../tools/inaho-integration/build_redesign_118.py) 的 `check_gauge_filter` / `check_combo_gauge`、[真实空目标夹具与回归](../../tools/inaho-integration/test_leader_target_119.py)、[实际客户端字段解析回放](../../tools/inaho-integration/verify_native_master_fields.py)。修复既有数据错误时，如果已验收客户端具备相应能力，用 CDN 修正数据即可。

### 能力排版不能改变主副位可用性

稻穗能力 1 同时包含主位限定效果与副位可用的治疗/Fever 效果。原生逻辑会用首行决定整组副位可用性，单改逐行显示标志可能把原有主位效果一起放开。此次允许整组进入副位计算，再以 `OwnerIsMain`（202）保留原七条主位限制；`Leader`（42）表示队长，不能代替主位。

显示侧沿用作者角色的专用分段说明入口：相同条件合并成段，条件、对象、上限和冷却保留；主位/属性图标通过原生替换表生成，不写死在自由文本中。普通文字与图表化模式分别检查；排版改动与战斗条件改动分开对比。实现见 [分段文本生成器](../../tools/inaho-integration/redesign_descriptions.py) 及上述调整生成器。

### 触发方式、攻击力来源与伤害分类分别设计

新角色采用作者规则：原生触发条件 → 瞬时能力 629 → 普通资源路径的 ActionDSL。当前扩展根标记 `101/102/104` 对应技能/能力/直击，`131/132/133` 对应 PF1/PF2/PF3；这些是已接入客户端的规则，不能假定所有原版客户端都认识。脚本显式分类优先于环境转换。

直击命中可以触发脚本并造成 PF 类伤害，但不等于发动一次原生 PF。攻击力取谁、PF 等级与加成、触发次数、CT、是否额外通知能力攻击，都要明确；不隐式改取队长攻击力或补发计数通知。移除旧伤害方案前扫描最终生效资源的完整引用，涵盖压缩脚本；将稻穗特效选择及预载拆到 `InahoAbilityVisuals`，避免删除旧分类入口时丢失有效表现。

没有正式角色承载新组合时，可以用隔离测试数据建立“直击命中 → 629 → PF 追击”夹具。此次 Android 单人验证使用非队长发动者区分攻击力归属，并逐次记录有效命中、被 CT 阻止的命中、PF1/2/3 伤害、加成与是否递归。仅观察伤害数字或技能提示不足以证明这些边界。夹具沿既有 8001、active ZIP 和 manifest 发布；测试后恢复原链与隔离环境，不把测试角色/脚本带入正式合并包。详见 [统一规则及设备证据](../../client-patch/author-unified-damage/README.md)。

### 扩展满槽语音必须接通三个入口

额外语音文件齐全，只能证明资源存在。扩展满槽语音还需要同步接入战斗轮播、战斗预加载、角色详情试听列表，并检查缺文件回退、原生无可选语音及其他角色保持原行为。

本批杰拉尔为 6 条、特克托为 3 条、斩铁为 4 条；斩铁四槽循环中的前两个槽保留原生选择，后两个使用新增语音。不能把新增文件数量理解成自动新增播放槽，也不能为了扩展语音覆盖原生条件分支。这些数量是本批配置，不是引擎上限。实际字节码验证见 [语音三入口回归](../../client-patch/author-content-1043/rules/tests/test_voice_port.py)。编码可解读、播放路径可达与人工听感分别记录。

### 资源合并要同时证明终态和实际下发范围

本批原 1.4.117/118/119 已合为 `1.4.116 → 1.4.117`，按原链顺序保留每个成员最后生效的字节。2,072 个成员逐项比较，稻穗目标修复、芙拉菲筛选修复、分段文本、既有特效及语音均保留；临时战斗夹具排除。详见 [最终资源合并记录](../../assets/asset-patch/audit/session-consolidated-1.4.117-20260924/README.md)。历史版本号只用于复现，不作为下次追加起点。

磁盘上保留旧 ZIP 时，服务端不能把目录扫描结果直接当发布清单。实际下发的自定义分包必须受 manifest 中启用的 `archive/chain` 约束，下载列表与总大小使用同一筛选结果。仅从 manifest 撤掉旧条目还不够，需核对真正的资源接口以及 Android/iOS 返回；否则旧包可能重复下载并覆盖终态。对应 [资源接口](../../src/routes/cn/asset.ts) 和 [残留旧包回归](../../tests/asset-manifest-publication.test.cjs) 是资源合并的服务端依赖。

### 客户端能力、平台移植与验收证据分开记录

CDN 提供表和资源，客户端提供解析与执行能力。先确认目标 APK/IPA 是否已有 423/424、伤害分类及扩展语音实现，再决定是改数据还是适配客户端；资源包同时含 Android/iOS 图片，不等于两个客户端机制都已完成。

iOS 移植还要保留原生字段偏移、构造默认值、原方法/闭包入口及 AOT 表配套。此次 `__enum__=true` 需要在编译 hook 中显式初始化，不能仅凭 Android ABC 的执行结果推断原生构造行为。具体实现见 [iOS 移植记录](../../client-patch/author-public-release/README.md)，不把某次布局偏移硬编码成其他版本的规则。

证据边界：直击触发 PF 追击有 Android 隔离单人实测；C7050 有真实坏数据和实际解析字节码回放，覆盖两角色相关 62 行、85 个方法，但替身包装不等于完整客户端运行；新公网 IPA 完成离线检查，没有新增 iOS 真机或多人验收结论。记录每项验证覆盖的机制与平台，不能把某个版本整体验收泛化为全部新组合均已验证。
