# CN 响应重复发送修复

部分入口接口在异步处理函数内调用 `reply.send()`，却没有返回 `reply`。编码计时包装增加了 Promise 等待边界，使处理函数先于发送钩子完成；Fastify 随后自动发送空响应，与原响应争用响应头，可触发 `ERR_HTTP_HEADERS_SENT` 并导致进程退出。关闭统计开关不能消除包装本身的异步边界。

编码耗时改为在现有 `onSend` 钩子的 `finally` 中同步记录，保持原有编码和压缩流程。入口中的 MessagePack 辅助函数返回 `FastifyReply`，调用它的九个接口和三个诊断接口均返回发送结果，明确响应的完成时机。

未改变响应数据、MessagePack 整数兼容、Base64、压缩协商、数据库结构或存档格式，无存档迁移。

`tests/cn-response-lifecycle.test.cjs` 从实际编译入口加载编码钩子、辅助函数与相关接口，在独立子进程中使用真实 HTTP 连接验证，避免以简化的测试钩子掩盖发送时序。覆盖监控开关、额外异步发送钩子、gzip、Brotli、压缩异常回退、空响应及并行响应，检查载荷和每个请求的响应头写入次数。测试隔离生产数据库、准入配置与后台任务。

此验证不等同于云端部署或真机登录、关卡结算验收。崩溃前邻近的关卡恢复日志不能单独证明该关卡接口就是重复发送的来源。
