## 无模拟器的客户端代码验收

客户端回包、重试、库存、EX 恢复、乐享入口等业务修改，先复用仓外 [client-air-test 固定入口](../../../../tools/client-air-test/README.md)。后续任务从任务效率表或本条目进入；明确实际源码/worktree、目标 SWF 和新输出目录，按改动选择 suite/groups。已有案例直接运行，只有新行为或实际缺口才补案例；不要求每次重写、不默认全量回归。

收尾验收先沿用已选层级；非实机AIR代码验收不因没有设备自动升级为手机或部署前提。结算拾取、强化点与真实回包选择 `--suite common --groups battle`，该显式组不纳入默认/all。入口先执行native拾取累计与finish请求，送入指定源码的真实隔离路由，再执行native公共状态更新；计数到obtainedMana之间若为手工桥、依赖为类型壳、专用finish parser/UI或完整restore未执行，须分别明示。显式battle夹具必须包含固定三业务及必需步骤，空／缺组不能退化成旧synthetic后仍报通过。源码故障注入与native解析分层对账，完整回包和原play/余额/经验事实同验。依据见本轮收尾（历史本地记录）与工具README。

- `queue` 测身份与重试；`common` 测公共更新；`flows` 测业务专用回调；`ex` 测 EX 完整 load 与教程/正常恢复；`gacha-entry` 测券、日期及实际运营条件；`crazy-flow` 测乐享候选/保存/选择及跨进程恢复；`mail-ex` 测邮件差分及补偿展示数据；`mvp` 单独测评分、MVP 选择、统计载荷及其真实源码结算。具体未覆盖项与命令以工具 README 为准。
- 消费、体力、经验和玛纳修复使用独立的 `--suite common --groups purchases`，不加入默认/all。先以 `queue` 核对选定 SWF 的请求身份冻结，再由指定当前源码的真实路由及生产编码器生成六类业务的成功/重试回包；期望余额、库存和角色状态在调用前独立计算。四个消费入口跨新进程核对持久回执和玩家表不变；玛纳学习/觉醒保留当前状态刷新语义。该组拒绝旧夹具重放，核对源码和完整回包身份，AIR 连续消费两步而不重置玩家。公共更新覆盖货币、体力、经验、物品和角色；`expectedManaNodes` 只是服务端节点断言，专用回调、节点场景流程及完整 UI 未执行，须保留 uncoveredFields。已验证范围见消费回包 AIR 记录（历史本地记录），后续按本轮实际源码和客户端重新选输入。
- 回包由指定源码在隔离数据库中通过真实路由及编码器生成，保留一份 schema2 `steps[].response`。显式重放旧回包只算客户端回归，不能证明当前服务端修复；不启动真实服务或监听端口。
- 从选定 SWF 按必需类唯一定位 ABC，导入真实方法/闭包；保存后回读代码、异常、参数 flags/defaults、栈与 activation traits。必需方法缺失即失败。不能把导入体数量当作运行覆盖，也不能把受控依赖替身当真实场景执行。
- `run.py` 已包裹既有 client-background，在后台桌面执行 AIR cmd 模式；不截图、不点击。每轮输出不可覆盖，ADL 退出 0 仍需检查新结果、必需案例/步骤、断言和目标分支。失败或超时停止，禁止换旧输入、降级断言或裸跑 ADL。
- 完整 load 必须按实际执行的步骤 ID 对账，公共解析和其他业务组通过不能代替目标恢复分支。重试差分保留原请求前快照；补偿展示同时核对真实客户端主表、实际到账量及逐封归属，区分展示元数据缺失与奖励数量规则差异，不靠更改输入求绿。
- MVP 案例先从指定 SWF 执行真实评分与统计方法，再将生成的载荷送入指定源码的隔离 start/finish 和真实编码器，核对事实计数及实际任务进度。用高治疗贡献但非 MVP 的场景区分两套评分；有效 true/false、字段缺失、非法值、双端倒序、同 play 重试及实际 writer 故障回滚分别验。双方须各自真实 start；result_code=1 也可能是 stale acknowledgement，须核对原局登记和任务变化。依赖替身、常数绑定、真实方法与服务器执行分别留证，不把 JSON 读取当成原生回包解析。案例与边界见本轮记录（历史本地记录）。
- 一轮共用一份输入 SWF 和完整回包；SDK 复用不复制。保留最终执行物、身份、结果及必要证据，验证后按工作区规则退役可重建中间物。不要为每次小改复制 APK、SDK 或资源树。

运行证据见落地记录（历史本地记录）与第二批业务验收（历史本地记录）。这些记录是样本而非后续固定输入。桌面 AIR 仅证明所列真实代码分支与状态；画面、GPU、ANE、真实网络、手机及 iOS AOT 仍按实际任务另验。

## 选测试对象与层级

- 派生内容索引不仅验证生成器的可选片段，还要验证仓库实际交付的canonical/runtime：逐项核对全部sourceInputs及manifest/presentation/catalog原始字节、精确projection和真实reader关联搜索。改业务源后先重新抽取获胜资源/配置片段，再merge/projection；不手填新SHA掩盖旧片段。actual-artifact回归不依赖可选私有输入，因此不能因缺fragment环境而跳过。正式生成等所有绑定源码固定后进行；AIR的业务树身份检查还须等新增测试文件固定，输入漂移导致的失败必须保留，不能将内部native绿当整轮通过。方法与红绿例见索引和兼容修复（历史本地记录）。
- 工具入口：自动测试说明（历史本地记录）。先核对当前 APK/登记身份、服务来源、分辨率和允许操作的实例；旧 C8016 v3 及早期服务只作工具校准证据。已授权安装登记客户端和启动源服务时可推进，不把校准阶段的临时禁切换当永久禁令；保护应用数据和 accepted registry。
- 结算、并发和故障注入优先隔离数据库及协议测试。回环 TCP 三玩家不等于三台游戏设备；受控夹具、完整服务真实端口、真实客户端、云服/公网是不同验收层级。HEAD 不单独代表采纳的未提交运行实现，必要时按明确路径做源字节核对。
- 历史 7 步 Android 冒烟是重启、保存会话恢复登录确认、标题页、主页、商店、返回主页等实际步骤；未出现的推广弹窗不计运行通过。该流程复用正常登录后的保存会话，不证明自动输入密码或会话过期恢复。
- 有效结果应有最终状态断言，不能以最后一次点击成功收尾。战斗支付需核对原 play、唯一回执、实际数据库奖励及 active 清除；画面 SS、战斗结束日志或最终主页不能单独证明支付/恢复。

代表证据：独立验收（历史本地记录）含真实源服务、APK 安装身份和单人回执；双端实测（历史本地记录）覆盖两真人普通合作；后续双机结果（历史本地记录）覆盖普通三局与原房再战，并有旧 play/进度表保护核对。以上对象均是历史限定样本，不固定为当前测试输入。

## 大型 JSON 与派生索引的有界核验

状态：**已验证**，限 Windows 本地离线索引核验；不代表云服或游戏设备验收。出现数十 MB 索引、批量对象差异或曾发生内存耗尽时，先复用受限执行器（历史本地记录）与分阶段核验（历史本地记录）的方法，按当前对象调整明确路径，不能重放历史批次命令。

- 大对象或长字符串不能直接交给会自动生成完整差异的断言。已核对 Node 24.19.0 的失败断言会先完整展开值，再保存 Myers 差异轨迹，自定义 message、console 截断或外层 catch 均发生得太晚。先比较布尔结果或用双流逐 token 比较，首错只留路径、类型、长度或摘要，禁止把整棵失败子树放入错误数组。
- 每阶段独立进程、串行执行；先挂起创建，再加入禁止脱离的 Windows Job，设置进程树提交内存限制、超时和关闭时终止，确认安装成功才恢复执行，失败无裸跑回退。V8 heap 参数不等于进程总内存限制。任务结束核对终止返回值、查询成功且剩余进程为零；不能把查询失败的初值零当清理成功。
- 大原件用分块 SHA 与逐文件/逐记录比较；投影、实际 reader 与汇总分阶段。先用微型正常、故意失配、内存申请被拒及超时子进程案例验证保护，再处理真实输入。Job 峰值记录可能包括被拒绝的申请，不能仅据峰值与配置比较声称严格实测阈值；保留实际退出和拒绝证据。
- 绑定刷新保留原报告逐项结构、审核状态、reason 与键序。历史 compact child 与详细 matrix 可以表达不同证据层级，不能用完整 matrix 全量覆盖历史 child，也不能顺手将旧未审核状态提升为可用。只更新能从同 key 原/新输入精确证明的身份；核实际 runtime 是否消费该字段。
- 消费者核验按真实投影契约比较：canonical 全量保全与 runtime 必需字段完整性分别验证。若 runtime 明确省略诊断字段，不能强求两种表示完全相同；省略字段需源码证据与明确白名单，其余字段仍失败。

证据见恢复记录（历史本地记录）。旧进程没有保留分配堆栈，历史峰值的精确触发语句仍未知；已确认的结构扩写、错误投影比较及保护效果分别留证，不能将推测补写成运行事实。

## AIR 页面与操作安全

UI Automator 在该 AIR 客户端只见全屏 stage，不能定位游戏内按钮。固定区域模板选静态标志，避开闪烁“点击开始”及动画；使用两帧稳定匹配、操作前重采、一次输入，陌生页面停止。页面、预留或结算超时变化后重新采集，不按旧截图继续点击；长日志分析移交后台，连续操作先准备完整步骤。

该 Android 15 环境的 `dumpsys window windows` 未提供 `mCurrentFocus`，`dumpsys window displays` 可取实际窗口焦点；`mFocusedApp` 不足以证明可操作窗口在前台。ADB 端口从 MuMu 管理器动态查询，实例 0 排除。敏感/未知登录页不保存截图，访问敏感状态后不采 logcat；凭据只在本地受限文件，不进入报告。

历史一次 C8601 在游戏内清资源缓存并从既有 8001 资源链重下后恢复，损坏来源未明；不能把清缓存变成日常自动重试，更不能清应用数据代替诊断。

## 入房、倒数与原房再战

- `select_room` 建立有期限预留，`prepare` 不保证刷新；应按当前源码/配置取 TTL，显式 `MULTI_ROOM_ADMISSION_TTL_MS` 覆盖默认。历史默认从 15 秒改为 60 秒，因此不沿用旧 15 秒操作预算。选房、boost 弹窗和握手连续完成，过期后重查房/重选。
- `not_reserved_missing` 与到期 prune 相容，但 missing 还可能来自其他释放，不能直接等同 expired。结算页历史默认 60 秒超时回主页，续页前核对实际页面。
- 两真人仅自动准备，双方成功 Enter 同房/当前代且准备后由房主手动 Start；三席位（含 COM）须全 Ready、Host 自动开始 ON、装备/续战名单门禁通过才倒数。Notify8 按当前连接/代际及广播开关处理，Guest 切换不重启 Host 已有倒数。
- 历史双方各自开启自动再战 ON 后，结算自动 retry 回原房，无需 Resume；Continue 属于退出。自然晚返数秒不能直接归因网络或结果页操作，也不外推三真人/COM 组合。

服务端门禁修复的回归/完整应用冒烟见入房结果（历史本地记录），该批 UI 未复测；真实双机再战见上列双机结果，两类证据不可互换。

## 换场、五王及活动房间覆盖

历史真实单人覆盖一个已通关剧情关、一个深层域双场景；普通双人 BothBoss 覆盖第一场→加载→第二场、双方各 sceneReady=2/LevelNext=1/Finalize=1 和回执。只证明这些场次，不外推全关卡类别或全部多层关卡。录像与结算快照分别覆盖画面和支付。

两批五王只进入初场，随后 GAME OVER 或双方 abort，均无 LevelNext/Finalize/专用 clear receipt；仅计初场/退出清理，不计完整换层、终局或奖励通过。五王完整多段及最终结算转云服待验不等于软件故障。相关日志见多模式证据目录（历史本地记录）。

代码 `lounge` 对应限时“大家一起选角色”三人活动集合房间，不能泛指普通领主大厅。历史资源链 campaign 1/2/3 已到期，普通测试账号没有可用入口，残留未兑换资格入口未实测；协议回归不替代活动客户端验收。资源名、item_lookup 与[官方说明](https://www.taptap.cn/moment/558635384314006299)是该术语定位依据，活动当前可用性另取证。

## 活动恢复的服务端契约与隔离流程

以下服务端路径已有定向回归和完整 out 入口非设备冒烟，见活动恢复结果（历史本地记录）与完整活动冒烟（历史本地记录）：

- 防幽灵座位、未 Enter 租约、旧 socket 控制和房主席位问题；重复 Start/prepare 不回退。阶段 97 房主合法 Bye 或旧房淘汰不得取消慢队友。
- 历史 LAN AS 状态 1/2/3/4 分别为未参与/券已决定/已抽/已兑换；状态2主页自动 multi_draw 只需 campaignId，合法第一期状态2/null/无券不能过滤，SinglePlay 是合法入口。
- Start 在同一事务重查三名既有资格并预定状态2与有效券，提交后才通知，不发库存、不创建缺失资格。第二名保存失败须整组回滚；旧状态3仅从本期唯一实持券恢复，歧义保留 DB 并过滤坏下发。不完整4/5、未知活动/use_case 或非法体拒绝；HTTP/TCP 同资格门禁，失效 restore 正常返回99。
- 完整隔离服务跑严格准入/登录、真实 HTTP base64/msgpack、三条回环 TCP：建房→加入→Ready/Start→并发/重复领取→兑换→load；跨进程复用隔离 DB 后重新登录，保持原身份/预定券，restore99/port0，并发续领只得原券一份。
- require 完整入口前须重映射硬编码 ready/current 的 fs 读写/stream，同时隔离 DATA_DIR、seeds、TMP 和 worker 显式 DB 路径；只改 cwd 或端口可能碰真实 ready。核对两阶段退出与端口释放及真实源/ready/运行进程未变。默认新库虚拟时钟不证明当前日历入口可用，重叠测试数量不相加。

客户端边界：设备 `lounge_restore_data` 含未知 campaignId 时，历史 GlobalLoadingTask 在 HTTP restore 前就构造缺 master 的 Logic；服务端过滤/load/99 无法先行修复它，需客户端守卫或针对设备恢复。现有防坏状态下发不等于清理所有历史本地坏记录。历史匿名聚合没有待恢复/坏票行，不足以倒推历史登录原因。双登录冒烟和三回环 TCP 不证明三真人完整活动、iOS/公网或云端通过，也不授权改日期、资格、CDN 或客户端。

## active 断网/重启：先确定有效故障窗口

1. 先确认真实发射、计时推进、Boss 存活；重启/load 时 Host 仍在原战斗，原 play 尚未 finish。脚本事件名、文件名或 active 行不单独作为阶段证据。
2. 短关/高输出队伍可能在恢复前自然 finish。历史八岐大蛇超级+（category2/quest1020004，非基础超级1020003）能在现有完整队伍上覆盖窗口；不是固定等待或 AUTO 开关保证。先准备完整连续步骤，再执行门控、注入、登录和观察；两端 AUTO 曾改善 Peer 生存。必要时采用合法低输出队伍或游戏内复活，再实际验证窗口。
3. 提前通关、GAME OVER 或退出导致原战斗未延续时记未覆盖；门控失败应阻止 force-stop，不能编造原因。同步用例无需通关，原 play 支付防重另跑正常短关。
4. 每次注入前确认独立恢复控制路径。本机裸 ADB `svc wifi` 曾卡住，MuMu 管理器 sh 断网后仍可执行；恢复后曾需 adb disconnect/connect 才重新取证。这只是本机实证，不是所有设备保证。
5. 同时看 TCP Established/新握手、双方实际关卡/贡献/进度和原 play 回执；无弹窗、画面继续或系统重传不证明恢复。退出后确认 WiFi/wlan0、双 active 清理及余额/回执符合预期；未通关零支付只算清理，不算支付验收。

## 恢复根因、修复范围与仍未通过项

早期 active 重启回主页与 WiFi 后各自结算均未同步恢复。`member_not_in_battle` 曾发生在 Host 结算前，大厅 Bye 早于 force-stop；当时 handleBye 先无条件移除成员并过滤冻结名单，因此不能把删除起点归到重启或默认 8 秒 grace。原局缺删除返回值/内存名单采样，只提供定位线索；后续隔离先失败后通过才确认正常 StartBattle 后/旧代 Bye 会破坏冻结身份。

修复先检查 phase/generation，非当前 LOBBY 只释放 transport；restore_room 只在非 BATTLE 覆盖 raising_state，保留 BATTLE=4。正常双端贡献/唯一回执通过，但此名单修复没有完成 active 同步恢复。默认 8 秒 grace 仅适用加载 barrier，不能作 active 通用重入保证。

历史登记 LAN SWF 的实际 AS/P-code确认 socket 错误不进行 active 重连，Playing 转隔离并永久 Leave；本地日志 Restore 不建战斗 TCP，重放结束亦转隔离。保留名单或重发 Connected/BattleStart 不足以恢复，后者在 Playing 可报 C5706/C5707。完整实现还需客户端恢复状态、同座位协议、有界缺失事件补发/快照及追帧，须另行开发和验证，不能靠服务端回执宣称完成。

八岐有效战中补测中，重启 Peer 本地重放后落后、无该房新 TCP；WiFi 恢复后无 F2032 但 TCP 已断、双方 Boss 标示分叉，两项同步恢复仍未通过。录像未跨端校准或全程逐帧，缺 guest/load 响应和 terminal telemetry，不推报精确 raising_state、冻结名单或准入数。恢复修复及审查（历史本地记录）、实际客户端审查（历史本地记录）、有效战中补测（历史本地记录）保留证据；旧未执行脚本不计通过。
