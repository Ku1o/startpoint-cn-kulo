# SP-MOD-001 · 累计伤害比例机制与静态 ActionDSL 边界

## 适用与何时读取

适用于 `<workspace>` 工作区内 StarPoint CN 的战斗机制、ActionDSL、SWF/ABC 可行性调查；实际代码根为 `<repo>`，不自动套用于工作区外项目。要求按时间窗口累计队伍对敌伤害再按百分比结算，或计划仅改 CDN/角色表实现动态累计值时读取。

状态：**已验证（调查基线静态调用链）；待验证（候选实现与运行边界）**。调查使用 Android SWF SHA-256 `9418137820c007b52a11ad0d7955c102795d8dd903213670577bf3407ed709f7`；新载荷或新增命令出现时，只复核受影响类，不将旧结论冒充当前所有版本的限制。

## 当前方法

### 分清伤害事件、阈值触发与动态读值

- 调查基线的 `EnemyImpl` 调用 `enemyDamageCountUp(category, actualDamage)`，类别 1/2/3/4 分别对应技能/能力/强化弹射/直击；计入实际伤害并排除过量部分。
- `BattleAbilityTriggerImpl` 有添加/移除伤害 handler，`ModifierField` 使用 `DamageToEnemy` 达阈值解除领域。这证明已有事件和阈值消费者，不能据此推定 ActionDSL 可以读取累计值。
- 已查相关命令及能力表使用静态数值。精确“累计伤害 × 35%”需客户端 SWF/ABC 路径，不能把 CDN 静态改表称为实现。

### 先复用定向导出，再设计候选

先匹配平台登记与实际调查输入，读机制交接（历史本地记录）第 3/5/7 节及其定向导出类，检索既有调用点；不默认全量反编译。旧 `news-decomp-all2` 树仅作参考，不能替代当前载荷证据。

候选设计是用新状态类开窗、订阅伤害事件、到期经 `FixedAttack` 结算，并防止结算伤害回灌。它仍是设计，实施前需明确目标、时长、上限、次数、伤害类别和队友口径。运行验收应覆盖联机队友、毒/滑落、跨 zone、屏障、过量伤害及能力乘区。

### iOS AOT 例外与布局约束

新增状态优先放独立类；不能仅凭追加 trait 推定 AOT 偏移不变。静态槽和实例字段布局都须按实际 ABC/原生访问核对，见[静态槽 F1009 记录](../../../../client-patch/IOS-STATIC-SLOT-F1009-20261004.md)。这是保持既有 AOT ABI、验证受影响调用者的要求，不是永久禁止所有字段修改。
