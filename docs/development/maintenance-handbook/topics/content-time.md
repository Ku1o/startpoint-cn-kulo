# SP-TIME-001 · 常驻内容、真实时间与手动运营

适用：StarPoint CN 服务端、配套日期资源和双端动态状态；涉及常驻内容、活动开关、旧 offset、EXP checkpoint 或旧局迁移时读取。状态：部分已验证；隔离实现和部分离线能力有证据，实际切换、客户端页面完整同步及设备验收须另核对。

## 目标与有效入口

切换前实际可玩的内容及进度应保留，内容持续开放后再采用真实时钟；管理面板可检索历史卡池和活动，资源及规则闭合者才可手动开关。主流程是后台一键发布/下线、统一通知重登、玩家原生页面读取新快照；不据此新增玩家历史菜单、手动选期或客户端运营开关。日常开关通过持久状态和游戏 API 下发，新增资源仍正常交付。有限期限平移不满足常驻目标，历史 disabled 142 候选不可重接版本链后启用。

先读[时间口径策略](../../time-base-policy.md)与常驻目标校正（历史本地记录）。后台发布、统一重登及Android被动适配的隔离工程证据见当前修正结果（历史本地记录）；较早探索见phase2 结果（历史本地记录）。这些均不证明源服务、正式数据库、云端或手机已验收。保留 player-time-compat / battle-clock-compatibility 及既有玩家、旧局保护；旧自动迁移和未知旧局终止候选仅供历史恢复，不自动采用。

## 目录、证据和业务接管

- logical 路径对齐 src/lib/assets.ts 的分类 accessor：story/ranking 用 *_single_quest，world_story 普通和领主分表，不统一拼 type+_quest。目录与 runtime master 不同须重新导出核查。
- 定义匹配、参考日期、可玩证据分开。实际 CDN 获胜链与权威规则可以支持离线可玩判断；日期、文件存在、terrain 或 native 构造表单独存在均不足。未审 porter 不能反判原生实现损坏。
- 固定历史日须由原始 start/end 重新计算父活动、普通卡池及每个子关卡窗口，不能沿用当前日生成的 windowCandidate 或把父开放泛化为全部子开放。按原生列表、外传和文件夹保留入口归属；运营目录只过滤原生条目，不把全目录追加到活动页。全族清单、精确允许/排除范围和服务器实际定义分别闭合，数量不能互作分母。
- 已验证的单期页面约束：历史关卡资料逐项可用，不代表所有期数能同时进入同一原生列表。幽玄域显示与参与须为同一期完整10关，崩坏域同页最多一组深渊之兽；编辑及重新发布均校验，正常下线和已登记旧局的结算/放弃继续保留。修正只改精确动作范围，禁止清首通、合并同名不同ID或重建实例；已过期、blocked、内容指纹失配及其他人工关闭动作不能借范围修正重新认证。核对完整下发范围及原生页面实际数量，不能以全历史并集计数代替页面验收。隔离实际目录、事务回滚与旧局HTTP依据见本次修正产物（历史本地记录）；云服应用与手机页面另验。
- **已验证（服务端隔离回归与本地控制读回）**：单期关卡修复须同步核对商店，父活动和商品的布尔开放不代表商品属于当前期。深渊之兽按父 `visible.questKeys` 选期，沿原生关卡开始日期与商品原生销售日期关联；最后常驻期另按业务时钟筛当时月批。兑换跟显示期而非参与期，停止参与仍可兑换；列表、入手方法、选购分组、单买、批量及排队后事务复验共用 `shopContentDecision()`。缺失或多期显示范围关闭该商店。保留原商品ID、购买数、库存规则和活动实例，切期不重置记录；不改 `assets.ts`、`content-shop-rules.ts` 等已纳入身份哈希的加载器来添加无关助手。源码已纳入不能证明真实目标库已修正，单独核对目标控制范围和业务时钟。方法、旧测试夹具限制及本地修正依据见商店修正记录（历史本地记录），手机与云端另验。
- readiness/evidence/scope 仅保存核查资料；显式 flags 才接管已接通动作。controlled=false 保留旧策略，不伪造关闭指令。受控条目缺定义、能力或状态损坏时关闭；普通卡池只有 start/end 差异可由人工已核查运营状态覆盖。
- 父活动开放不能重开未核查单品，父子任一关闭均拒绝。每日/月库存或频次缺持久规则、special/StartDash 缺闭合交易路径的候选保持 unsupported；已验证既有票券兑换只开放 exchange，不推定购买或入场。主线和普通领主不因目录核查自动接管。
- 关闭任务停止事实计算，不新建 snapshot/login baseline；日周重置保留关闭任务及已领取阶段。claim-only 保留历史超目标 progress，不按 finalTarget 截断。抽取证据不自动覆盖兑换；whole-row 接管保留原可用动作，合成 exchange=false 不构成关闭既有兑换的依据。
- 普通任务查缺按原生 enable/show 两套日期、display_tags、等级与完成/领奖分别核对；每周可并入活动页，专属标签任务不追加到普通页。远期结束年份不能单独判断是否历史限时：精确核实原生核心任务后只恢复其 visible/enter 默认回退，继续保留未知目录、显式关闭/坏控制优先和原 claim。用完整目录动作差异确认没有扩大其他历史参与。
- “全部每日完成”按该代主表声明的精确依赖求值，只使用当期可计数依赖；历史 claim-only 的已完成进度不能代替今日条件。复现覆盖历史已领/未领完成、当前全零、当前逐项完成和旧超目标值，并验证历史原进度/领奖保持。合成 HTTP、实际编译模块与有界客户端证据见每日与资料常驻（历史本地记录），设备另验。
- 管理插件自身保留会话认证，不能只依赖 CN 全局 guard；V2 reset-active 清会话与关闭塔后保留已登记旧局是两项独立契约，不为错误夹具修改进度保护。
- 业务门禁沿实际注册路由追到末端写事务，generic single/multi start 不能代表 Raid 专用 start/select_folder/reset、剧情首次 finish/skip 或首次花费 unlock。关闭需在写前及排队后的事务内复验父和精确子范围；已登记 play、已完成剧情重放、既有解锁及已获奖励另作保留断言。真实 HTTP 状态/余额前后比较才证明这些专用路径，静态父族覆盖数不能替代。隔离复核入口见本轮修复记录（历史本地记录）。

## 历史内容补齐与离线接管

- 历史玩法核对沿原生构造器、最终有效 getter、具体业务事务和客户端原有入口闭合。清单同时覆盖父项及关卡、任务、商品成员，保留原生文件夹与关联箱池跳转。商品的单次购买上限、累计限购、每日限购和首件装备持有限制分别读取；缺个人资格的项目保留既有权益，缺商品资料的空商店列为明确缺口，不能补造奖励或资格。
- 个人资格商品先与当前明确恢复的普通兑换逐项并排比较：按实际kind、角色版本/目标ID、价格、奖励条件、持有拒绝与限购语义判定，不能只凭名称或个人池外键宣布额外开放、要求关闭。若当前全量同价同权益重合，记录旧ID兼容与未来失效前提；用两个购买顺序验证跨ID不能重复扣款/发奖。资格分支未检查是代码事实，是否扩大玩家可得范围是另一层结论；新增或不重合商品仍须独立核实。该方法已有全量数据对照、独立路由复核及合成HTTP反例，见星碎重合复核（历史本地记录）；不提升为真实资格或生产验收。
- 既有控制接管分为精确身份重绑定、补齐已有核查、准备新历史控制三个阶段。计划绑定当前 revision 和旧状态原文散列，以明确离线入口放入同一个外层事务；正常嵌套事务门禁继续保留。提交前逐表比较非运营数据的 schema/行散列，核对原实例、有效权益、运营人员自定义范围和有限期限，新参与默认关闭。实际迁移工具及反例见历史补齐记录（历史本地记录）。
- 编译后验证绑定全部实际运行输入及生效适配器；源代码辅助检查单独标注。旧用例遇到默认关闭、个人资格或原生箱池策略拒绝时，先核对夹具是否显式准备了真实 store 和完整政策，保留拒绝及回滚负例。定义核查和合成 HTTP 交易证明各自覆盖范围，不代替逐项设备实战。
- 事务预算先区分一致性读事务与实际写，不把BEGIN次数直接称为写次数；按维护、快照、成功确认等真实归属断言，并保留关闭内容不复活的负例。原生任务的节点类型和个人资格须由实际主表确定，不能用任意节点或回归任务充当普通修复夹具。计数器未覆盖的RETURNING/get/all或多语句exec，以及额外旧局清理分支，不能由有限成功场景推广，见load预算核对（历史本地记录）。
- 真实库演练用 SQLite backup 捕获 WAL，并携带实际版本旁文件和持久时钟；完整元数据迁移、正常启动即停、在线运行分别留证。初始化新增空表列明允许清单。正常调度产生的维护时间戳差异，须逐字段确认仅时间/耗时、租约及错误不变、业务计数全零，保留严格差异再给出限定结论；玩家表仍精确比较。崩溃恢复以当前进程、端口和完整性检查证明停止状态，不伪造优雅停服记录。

## 一键发布与统一重登

- 发布位与逐动作核查分离：旧有效状态缺发布位按已发布兼容，下线屏蔽入口和新参与/新售卖，重新上线恢复同一实例的原动作、范围与期限，不自动核查、不重置进度，也不抹除已获得的领取/兑换资格。
- 重登用持久全局epoch及每viewer成功load的ack；load只确认它开始时捕获的epoch，失败或过程中又有新信号不能误清。现有鉴权先于重登门禁，引导/资源/load仍可进入；TCP owner只枚举实际连接，DB parent复验归属和ack。空闲HTTP客户端只能在下一次请求获知通知，不能把它写成即时推送。
- 原生日变更提示可以作为被动通知复用，不能靠伪造跨日/调整servertime触发。专用后端消息须精确识别，并在原请求队列取消和错误通知完成后进入原生弹窗/确认回标题路径；普通维护和其他登录错误保持。验证原生方法是否仅用日期参数拼诊断，避免无意写Clock、执行日常或新增热跳转。
- 主动断线前保护实际在线、当前且已committed的精确play；CAS发布与DB身份复验/保护同事务。后续load对受保护但不可恢复的play保留登记、隐藏无效恢复入口，不伪造recoverable；未知孤儿仍按原规则处理，正常finish/abort资格不变。只证明断线当刻未删除不足，必须实际走后续load。
- 多玩家协议夹具必须区分viewer与数据库playerId，且每个客户端独立取得admission grant。grant会在注册/登录后绑定该session，共享grant造成516并非并发load故障；先定位拒绝层和身份，再改夹具，不关闭鉴权来造通过。

## 大厅与跨 owner 授权

受控新入口的 prepare 不清旧房或接受救援，pending nonce 不能 TCP claim。HTTP 收到 prepare 后同步复验，精确 commit 才是授权点；lease 限 5 秒、256 项，取消只匹配原未确认 attempt。已授权提交及原 confirmed/claimed/returning 保留，新 battle 另在最终事务守门；stale 占位最多 5 秒且 TCP 拒绝。owner 不引入数据库，也不把每个后续 RPC 等待都当作撤销条件。见 LOBBY-ENTRY-ATTEMPT（历史本地记录）。

## 时钟、存档与旧局保护

- 支付/领奖事务在排队及取得写锁后捕获时刻，窗口在事务内重读；writer 协议隔离旧偏移协议。UTC+8 05:00 业务边界与 TTL 毫秒时长分别处理；旧后台调时、玩家 offset 编辑不作为新运营通道。
- 历史迁移设计按来源处理：EXP 仅用保存的玩家 offset 换算 checkpoint，缺失/无效基准保留余额并从持久化统一切换点计时；真实体力时间、混合 lastLogin、账本和累计不整表减 offset。日周锚点独立，离线首登不重造保护期；先迁移再做邮件、日周维护和 EXP。采用该历史设计前，须重新确认它与现有兼容层及旧局保护的关系。
- 旧局只在有可靠全局偏移区间或五王真实成员起点时转换；未知免费旧局终止、未知票券/续关成本阻断迁移是旧候选，不能自动执行或猜退款。新局时钟标记写回多人稍后冻结的原对象；放弃/续关事务重新匹配 playID，失败时余额与登记同回滚。
- V2 时间和日邮来源元数据不弱化指纹与目标身份门禁。保留本地领取和关联邮件；旧 V2 缺来源标记不能按标题猜去重。精确回滚核对所有关联状态，已有新进度时拒绝盲目回滚；普通存档导入不替代运营回滚。
- V2 跨库导入须区分物理列序和真实结构差异：相同完整列集合可按来源列序，用目标真实 name/type/notnull/default/PK 重建既有兼容指纹；指纹精确命中后按名称验证和写入，恢复校验也须按名称稳定比较。不能改写原存档指纹、丢字段或跳过类型门禁。运行库副本复现应保留 `.version` 并恢复同一持久时钟到进程内存，避免夹具重复初始化或时钟不匹配。见列序兼容复现（历史本地记录）。
- 只通过 SQLite backup API 读取正式库。隔离 CLI 路径保护覆盖 Git 登记的所有工作树及真实路径别名，无法解析则拒绝；隔离修复未合并时不能假定源工具已安全。整合只取相对接手基线的新增差异，不整树复制。

## 管理面板的日常操作视图

日常主列表只放父活动、卡池、任务/通行证和奖励箱/兑换；名称、中文分类、类型筛选和搜索统一读取同一展示数据，保留历史条目，不能把数万条子关卡、商品和任务键混进主列表。原显式成员类型查询或 `includeMembers=true` 保留技术查询兼容。默认按可操作状态排序，状态改变后须修正越界页码。

配图应来自当前获胜资源链的真实横幅，游戏编码图片须先还原为标准 PNG；不改游戏原图，不伪造图片或建立另一条 CDN 测试链。管理页需要减少图片体积时，可离线生成内容哈希命名的 WebP 缩略图，等比缩小且不放大，编码参数和库版本保留在生成配方。索引精确绑定获胜资源链及展示数据摘要、原 ZIP 成员身份与原始字节 SHA、导出 PNG SHA，以及输出 WebP 的内容 SHA、尺寸和大小。生成前验证全部输入和真实输出路径，拒绝保护源仓库、任何 `.cdn` 及原图导出目录；源链、展示数据或成员身份失配时不继续信任旧索引。

缩略图经原有同源管理鉴权和父 key 白名单提供，重复内容共享同一个哈希 URL；采用 `private, max-age=86400, immutable` 浏览器缓存和 ETag，内存缓存仍须有界。一天缓存只适用于内容哈希不变的图片地址，不推广到会变更的运营接口。缩略图缺失、身份失效或浏览器加载失败时退回原标准 PNG 鉴权路由，原图也不可用才明确占位；保留鉴权、非法路径、失效来源及回退负例。

质量核对须覆盖卡片和详情的实际显示尺寸，对照小字可辨识度、像素画边缘、半透明及透明区域，不能只凭编码成功或大图预览选参数。颜色采用有损编码时，不宣称与 PNG 逐像素相同；要求保留透明通道时，须对同一缩小参考独立逐像素验证。体积分别统计逐条图片正文与去重后文件总量，注明是否包含 HTTP 头、304 校验和索引；重复 URL 可复用缓存，逐条总量不能当成浏览器实测流量。配方、离线读回及隔离后台验证范围见缩略图验证记录（历史本地记录），后续复用效果仍待观察。

名称检查覆盖纯日文和中日混合；无中文来源时标明中文说明性质并保留原名搜索。同名同图同日期且缺可靠限定信息时不猜属性、期数或领主，独立开关与整组合并涉及管理语义，应先明确；后台区分序号须标明其用途。

主城特效性能预算（已验证到原生静态逻辑与离线回放）：`framerate_division` 只轮流更新 Animation 状态，不能把除数当整层渲染开销的同比下降；TownParticleView 仍每帧遍历实例、清空并重绘离屏纹理。同时核对根群实例数、`parts.a` 每图类型池容量和逐帧活动叶命令，三者都不等于实测 draw call。现成 Flatomo profile 的 `visible_instance_peak/total` 也计入 alpha=0 命令，必须另外统计 alpha>0 的活动数，不能按字段名直接报告可见数；分时效果应结束对应段，不只靠透明度隐藏全部节点。图集尺寸按解码纹理计算，背景、blur、mask 的继承成本不要重复计新增，POT/缓冲未知时不报精确总显存。division>1 时序列边界检查仍只用当次 delta，可能跳过某群循环起点的随机重定位；离线预览必须复现原生谓词，不擅自每圈重抽位置。当前示例以单序列淡入淡出、持续移动和 wrap 避免依赖该分支；性能验收仍需同人物数/取景/画质的设备对照，不能用 Python 回放速度或压缩包大小替代。证据见主城特效预算与最终包独立读回（历史本地记录）。

主城美术适配（离线结构与坐标检查已验证，设备另验）：先读取实际 `scene/town/town_background.ui.amf3.deflate`，由 map 变换换算固定角色脚点，不把整图或美术建筑边界当手机视口/点击框。现用布局为 700×900 背景乘6、350×450 blur 约乘12；角色与粒子之后才绘制可选 `background_mask`，它是遮挡重绘图而非任意 alpha 裁剪，换景不能复用旧 mask 的 RGB。周年 mask 实际为城区透明、外围不透明；需要相同可见范围时，以新背景 RGB 配旧 alpha，逐像素核对并检查所有人物锚点，不能笼统解释为遮建筑。背景走 common 伪PNG，先查实际 reader 再决定平台配对，不凭“客户端资源”自动转 ATF。原生粒子按当前相机视口加 margin 随机发射，mask 再决定可见域；密度必须按常用视口验看，不能为了整图稀疏而把手机可见数压至几乎为零。预览裁框应由原生相机公式与明确的名义屏幕参数导出，初始目标仍随选中角色变化；整图数量不等于手机同屏数。核对 renderImage 与背景放大抵消、整层 ADD 而非逐粒子 ADD，并从最终 ZIP 的 parts/atlas/timeline 逐帧展开。像素尺寸、编码闭合、坐标图和离线回放各自记录，不提升为游戏遮挡或设备验收。可重建示例及边界见主城资源适配（历史本地记录）。

## 后台内存与四核同机性能

后台目录应避免按类型/分页反复读取和解析全部运营状态。在短读事务内一次捕获原始状态、revision和请求时刻，再按需解码并仅在该请求内复用；释放事务后分段计算。分页前只处理检索/汇总元数据，当前页才展开完整详情。动态到期及写事务内的最新权限/CAS继续独立判断，不把有效权限缓存为长期静态结果。

默认父项列表不必读取全部任务/商品控制。可显式捕获父项与parent/box/pass等依赖闭包，保留不带范围的旧完整快照接口；过滤前仍保留组计数、搜索、单通行证保护所需的全部父项集合。范围外state lookup必须明确拒绝，不能按未配置默认继续判断。静态分类/呈现和key范围可每store只留一版，按目录、呈现、历史、关联、thumbnail及asset manifest等实际来源身份更新，设条目上限；不要保留跨请求运行State。合并中间对象时只改请求新建row，不修改catalog原row或缓存呈现。前端请求effect可依赖规范化URL，避免相同查询的布局切换重取；展开系列绑定父查询身份，父筛选变化立即判旧展开失效，避免先发旧series再取消。完整响应、未知范围失败、隐藏依赖、来源变化、到期与CAS见连续切页实现与核验（历史本地记录）。

大核查报告保留为离线证据，运行侧消费来源绑定的精简摘要。重复角色/奖励用字典和有序引用保留全部关系与别名，预计算静态检索字段；来源哈希用有界流式读取。失配保持原有未核查/降级策略，旧请求持有自身的来源版本，不能混入后续索引。摘要加载与来源验证在主服务就绪前预热，不扩散到维护worker，不在GET内自动重建大报告。

共享4核时先减少总工作量并限制后台读并发，运行查询按小批次让出事件循环；前端取消过时搜索/详情，断连移除队列项，排队有上限，溢出给可理解的重试提示。写入、领奖及结算不进入此后台读队列。真实HTTP断连与队列释放需要独立故障注入，不能只看AbortController调用或模拟事件。

分批让出仍须做玩家同时操作的配对测量，不能默认更频繁yield一定更快。固定每16行yield及4ms预算两种候选曾通过功能检查但日常等待未获稳定收益，均撤回；保留原compiled、绑定、源码前像与不利原场，不覆盖原证据挑有利重跑。CPU采样加入await后可能丢HTTP路由祖先，应按可证实的唯一恢复帧补归因；显式route桶变小、JS Promise self很少都不足以证明总开销降低。最终只保留原调度下消除重复身份解析/序列化的优化，日常RSS峰下降不等于稳定延迟改善；日常、压力、峰值、idle与p95/p99分别报告。见日常玩家优先核查及隔离采用（历史本地记录）。

规则原件同时承担业务适配器输入时，新增native身份索引只能移除第二次解析/身份构造，不能宣称整个大JSON已从运行侧移除。预计算需保留原算法的属性插入顺序、完整key/digest/Map顺序，并绑定所有原生来源；不能改既有适配器哈希门禁来重签旧证据。每调用者提供独立Map，严格失配与有界流式读取分别验证；源依赖未变时可复用全目录和负例证据，最终候选的完整输入元组仍须重新绑定。852KB索引不是等量RSS节省，完整商店/关卡原件继续由实际业务消费者读取。

业务原件冷字段压缩不能只比编码大小或heap：原位accessor/WeakMap与对象布局本身、启动全值验证、临时Buffer和首次还原都有成本；完整getter返回字段、属性/数组顺序、别名/赋值/delete及真实启动身份链须独立等价。先用真实adapter短测并观察自然回收，RSS/首读/峰值无净收益时退出，不继续扩大场景。跨请求解码缓存也应先作为候选：只读模板按store、当前revision和fresh SQL完整原文匹配，不能复用时间/权限/响应或改变旧可变接口；深冻结未知字段，旧lazy capture不得重新准入旧版本。固定准入、条数/raw/对象估算共同限额可避免同序全扫LRU抖动，但命中多仍可能覆盖不了昂贵记录、增加驻留且不减总CPU/GC；必须先过真实日常配对，收益不足则保全证据并恢复旧元组，不提高预算或换压力负载择优。已验证的两项退出边界与本地数据见进一步性能探索（历史本地记录），均未采用到运行服。

生产登录的运营快照响应缓存与上述通用解码缓存分开：定义和能力随store初始化固定、正常运营写入原子推进revision时，可仅在登录/刷新wire响应复用完整只读快照，业务授权仍逐次读取最新状态，原Store.snapshot可变接口保持不变。按store、revision、最近动作截止及时间倒退重建，外层事务内绕过缓存；只在重建时独立复制并冻结，避免冻结借用的capability数组，命中只建新顶层和当前server_time_ms。不要为不属于正常写入口的直接改库/测试注入增加每请求全表校验，也不要把此特例推广到任意动态policy。验证保留关闭范围、旧领奖兑换资格、回滚、到期边界及编码正文一致。四核配对须使用生产编译选项，计算型回归与正式性能场分开运行，集中波次和固定到达跨度分别报告；400次快照+编码不是400在线或完整登录容量。当前为源码与隔离验证，云端采用另看部署回执，依据见登录缓存实现与测量（历史本地记录）。

任务授权的轮内解码复用与登录响应缓存分开。【已验证：隔离行为回归、主线及云端部署；收益仅有短时自然流量观察，非高峰或设备验收】固定 state/revision SQL 优先复用现有每连接 statement 缓存；每次授权仍执行 SQL，只在同一同步任务评估内按 Store、key 和完整 fresh raw 复用私有解析结果，不缓存权限布尔值或冻结时间。公共 state() 仍返回独立可变对象；缺行、损坏、修复和不推进 revision 的直接写入均由下一次鲜读发现。作用域在 finally 清理，异常、嵌套、异步 continuation 和下一奖励级联轮不能带出旧解析；在最终 claim 与持久奖励写入前结束。条目与原文字节设双重上限，超限继续原解析，不改变授权。保留 compute 后撤权、savepoint 回滚、到期边界、关联父箱任一关闭及旧领奖权益反例；统计实际 get 执行，不能把少 prepare 当少读库。合成配对保留无奖励、普通奖励、级联和极短无收益场，SQL 执行次数及完整结果等价；权限循环与完整任务结算、HTTP、云端收益分别报告。输入与限定结果见第一批授权查询优化（历史本地记录）。

多管理员读优化可先使用显式卡片投影与进行中查询复用，保留默认完整接口；逐一核对实际前端字段，完整State、scope、actionOverrides、截止控制和关联权限不能因减小正文而丢失。未使用的系列preview应连同构建一起省去，而非构建完整后只删JSON。复用键应覆盖路由/账号授权边界、store身份、目录摘要、revision及全部查询条件；到期不一定引起revision变化，序列化后还须检查所读状态的最近截止边界，跨期有界重建或明确重试。单个订阅取消不影响其他浏览器，最后一个取消才停止生产；完成不长期留存结果，异常、排队取消与真实HTTP断连分别检查清理。

共享JSON大小、订阅数和构建队列上限不等于进程RSS上限；完成订阅后的每连接发送缓冲不在共享计数内，大响应回退独立查询也仍有临时分配。人数对照应匹配每人实际完成量，管理员独立登录，并同时包含相同查询波次与不同条件轮转；429必须单列且延迟包含重试等待。记录warm/峰/结束的heap和RSS、整组提交内存及GC时机，保留原场与有依据的复测范围。某场RSS高峰未一致复现、共享计数归零或结束heap回落，都不能单独证明长期稳态或无泄漏。已验证的本地方法及不利项见多人查询对照（历史本地记录）。
