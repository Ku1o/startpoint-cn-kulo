# SP-SECURITY-001 · 认证、写入预算、事务与安全关闭

适用：`startpoint-cn-private-clean` Fastify 认证及编码路径、建号/登录、公开反馈、writer/admission、商品/任务/箱池、/load、后台榜单、存档和关闭恢复。涉及拒绝是否仍产生副作用、超时是否可重试、后台提交是否成功时读取。

验证层级：以下机制来自限定源码、隔离合成库、故障注入、真实 worker/进程及 HTTP/TCP 冒烟；不证明当前运行已加载、云部署或设备验收。完整批次、固定产物身份、测试数字、历史失败与修正见冻结历史（历史本地记录）。实际预算、环境覆盖和源码状态以任务对象为准，历史阈值不能自动修改。

## 路由认证、建号与输入

- raw URL 前缀与框架已命中的编码静态路径可能不一致；准入、登录、UDID、管理保护按实际匹配路由判断。拒绝用例核对业务处理器和 DB 副作用未触发，同时保留同路径正常票据/会话。管理前缀保护不改变玩家榜单读取协议。
- 两条建号入口共享来源和全局预算，正常登录/绑定沿用独立额度；预留跨窗口保留，失败释放长期额度，提交后回调失败仍计成功。旧设备回登与陈旧绑定重建账号分开处理，旧设备 signup 另有恢复预算。
- portproxy 可合并来源；不能信玩家 XFF 或豁免回环补救。固定窗口、进程内预算不等于持久磁盘总量或多实例共享控制。
- 输入完整校验，不能把 `fes-bad`、`★50` 截取成合法前缀。公开反馈的近期实际下发关联、TTL、去重和容量约束同时覆盖公开处理及关闭兜底学习；不能只限 HTTP。反馈公开请求不逐个创建刷盘等待者，批写保证正常关闭落盘，不保证崩溃前每条已持久化；全服 movie/seed 关联不是逐账号归属证明。
- bulk 关注即使域层已排队，也须在逐项解析目标前限输入长度。文件里存在旧 OpenAPI/legacy /load 不证明 CN 入口挂载，应查实际 server/cn-server 路由。

代表证据：认证与公开写入（历史本地记录）、顶层准入与输入预算（历史本地记录）。

## writer、admission 与请求寿命

- 异步持久化在建立 Promise 等待链前取得总量、单玩家、无玩家名额，覆盖排队和执行；顶层同步协调器也检查名额。已接纳异步命令可用有效期受限上下文复用名额，不能绕过预算或在已结束上下文继续写。
- 只有确定未执行的 queue-full 可映射繁忙/安全重试；超时、断连和未知提交结果不能伪装为未执行。TCP proof 先准入再等待；若后续 proof 被拒，HTTP 结算仍等待早先已接纳证明，不能以最后一个已拒 Promise 代替整体等待。
- 密码排队原验证契约为 10 秒单调时钟期限、共享 32 个无玩家名额；在迟到闭包写入前复核期限；超时/取消先结束请求，名额保留到闭包真实排空，重复取消不释放仍存活的 Promise 链。核对 SQL/profile/COMMIT 失败全回滚、账号归属/会话/存档不变，最后一次成功登录有效。
- 请求期限不等于同步 SQLite 或主线程阻塞下端到端硬期限；后台任务仍可能共享无玩家名额。COMMIT 后响应丢失不能回滚，不能让客户端断开提前释放真实执行资源。
- 旧同步入口、独立业务队列、未收拢原始 SQL 与磁盘总量不自动被上述门控覆盖；保留忙错误和明确重试边界，不宣称所有写入无感。

## /load 与存档兼容

- CN /load 的每日维护、永久校验/版本标记、Mode15/Rush/通关修复、任务/觉醒修复及含体力回填的快照准备放入同一有预算玩家事务；仅收前段会漏掉 prepare 隐式写入。
- 玩家对象排队后读取；校验异常须向外传播以回滚早先修复，不能吞错后提交。嵌套同步修复复用名额，满额保留原协议拒绝。响应编码及带原 playId 条件的清理发生在维护提交后，响应失败不说明维护回滚；跨 await 持有 scope，清理只能命中原 play。
- V2 导入保留目标账号/备注/凭据/设备/全部登录会话、目标已领取与未领取日邮及账本。历史邮件重建后核对 grant.mail_id 指向目标，除 ID 外字段不变；来源日邮按 dailyMailBasis 精确 ID 过滤，普通邮件不能用未限定首行查询。不导入历史及拒绝导入保留原 ID。
- 故障注入晚到日邮重映射后，比较被排除账本原行并验证 writer 回滚。原 HTTP 在备份前拒绝 V1 时，不能为了测试重新启用。测试夹具须补全必填字段，过时 reset 断言应匹配 preserve-target 防重复发放契约。

代表证据：/load 事务（历史本地记录）、V2 兼容与故障注入（历史本地记录）。

## 商品、任务与箱池事务

### 商品预算

- 新增原生兑换入口时先查旧商店、批买、列表与入手来源是否指向同一经济权益。共享商品用统一持久限购读取及同事务写入，覆盖新旧入口双向购买、旧档覆盖和重启，不能让每个接口各维护一份可用额度。绊证双入口例见本批整合记录（历史本地记录）。
- 邮件和奖励的数量约束按类型解释，不能统一把 `number=0` 当空附件；称号协议可用零数量表达单次授予。调整通用保护后同时覆盖有效特殊类型、重复领取及晚到历史写入失败回滚。

原验证契约为同商品 10 秒冷却、同玩家跨商品固定小时 60 次成功请求，预算缓存最多 5,000 玩家；这是机制参数而非当前运行配置声明。先返回 durable duplicate；预算判断位于同玩家事务。COMMIT 后、释放队列前同步记录额度及 fallback 次数，提交后不再读时钟/DB；SQL/COMMIT 失败不计数。预算缓存仅回收窗口和冷却均过期对象，不能淘汰仍活动的保护。并发核对最后额度与只一次发放，存档导入保留目标身份/支付账本/活动预算。进程内固定窗口重启清空、多实例不共享，不能称为持久预算或真实支付校验；无票据旧历史仍有边界。

### 任务事实

UI 自报只接受限定类型的正 safe-integer number，原限定五类同请求同 pattern 合计不超过 100，不同 pattern 保留独立额度；route 与结算都保留旧高于 target 的累计/stages，不能把自报限制套到通用服务端事实。限额不证明防伪动作，客户端批量/重复请求速率要另验。真实时间夹具先冻结 Date.now 再建玩家锚点，随后推进日周边界；不能旧 lastLoginTime 搭未来锚点。

### 箱池与元数据

- 库存/抽空/reset 按当前逐 reward 事实，不让旧/已移除 reward 总量抵扣当前库存；早关及重复 close 终态按契约处理，扩容只补既有空箱差额。扣币、发奖、draw facts、awake 与响应 reconcile 在同一事务；不能提交后再做第二 admission 导致已发奖却报失败。同币奖励先扣再加，返回最终余额。
- 在 SQL、COMMIT、响应收集/reconcile 故障注入后核对余额与抽取事实整笔回滚。无稳定 draw key 不宣称 HTTP exactly-once。
- 活动时段、前置箱、resetKind/closeKind 等取真实原始元数据；排队后事务重读时钟及逐 reward 事实，不能用缓存零库存代替抽空。缺 resetKind/resetLimit/requiredBoxId/period 时不猜政策，也不把单池修复推广所有池。
- 历史限定池的 seed、关闭/重复关闭/过期行为仅适用该池；不据历史日期自动补种、重开、改写旧列表或现有进度。具体池与值见历史证据，日常接手核对当前内容契约。

代表证据：商品预算（历史本地记录）、任务/box 事务（历史本地记录）、限定箱池元数据（历史本地记录）。

## 榜单计算、后台 worker 与提交恢复

- 总数不必计算 ROW_NUMBER，页面及本人可共用一次排名。同步结算用 SQLite 临时快照、分批读取，释放 better-sqlite3 iterate 游标后才在同连接写奖励；故障验证此前所有邮件/结果回滚及临时表清理。分批读数组仍可能阻塞，不能称异步结算。
- 常规元数据读取不重复 INSERT OR IGNORE，仅初始化/升级/截止事件写。大同步结算先用索引与 LIMIT+1 探测原始 run/round，再检查人数和邮件放大；超限明确暂缓保留数据，不能截获奖者或宣称后台完成。
- 管理结算/换季与自动任务排队前共享单任务名额，业务前置条件失败不阻碍立即纠正。专用 worker 中快照、全部邮件、结算收据及自动计划推进同事务提交；worker 启动失败不回退主线程。
- 上游有界写门等原生 writer 退出，再短初始化并交接后台写锁；等待线程关闭连接/退出才放行主线程。连接临时 busy_timeout=0 防旧原始写入同步等锁；受控异步写等待、旧同步入口快速拒绝。不能在主连接事务 await 后台长事务，超时也等原生句柄关闭。
- COMMIT 前故障整笔回滚。明确失败/未开始报告失败；只有开始后提交结果未知才查持久结果，自动任务还核对本次预期计划推进与赛季收据。completed 或奖励收据不能单独证明任意后台任务成功，不能掩盖最终 UPDATE/启动失败。
- COMMIT 后回报丢失保留查询恢复及发奖去重。HTTP 先断开仍可最终提交；手动任务无持久收件队列需显式重试，未执行内存队列不持久重放。自动到期停榜独立保留，失败榜留 due 计划继续同轮其他榜，重启可补跑。可选 expectedSeason 不匹配拒绝；旧客户端仍核对原赛季。

代表证据：worker 与故障边界（历史本地记录）、调度恢复（历史本地记录）、进程终止与未知提交（历史本地记录）。

## 安全关闭、取消与 WAL

- 同步撤新准入、停全部生产者，保留独立有效 scope 覆盖已接纳/排队子操作的后续写与 lease 收尾。先 await child cutoff ACK，再 drain 完整已受理 scope、同 ID 通知、真实反向 RPC 与导出实际线程退出，最后 owner/writer/checkpoint。单清 timer 不能阻止 await 后继续排队；stop 须等整轮异步调度结束。
- 原验证默认为关闭总期限 180 秒、150 秒取消、165 秒终止，原 worker 从创建起 120 秒；这些期限分别计算，历史参数不代替当前配置核对。旧显式 env 覆盖须尊重，不能在关闭时重置原 worker 期限。取消检查放 queued prepare BEGIN 与 worker COMMIT 前；真实 exit 及未知提交对账完成后才放写门。超期未完成应非零退出，不伪报排空成功。
- 第二个非空榜保留完整 due 计划。取消/超时未提交时奖励、收据和计划均不推进；202 清理停止后续 batch，保留 interrupted/剩余数。导入 writer 失败回滚，导出等待实际线程退出。
- WAL 要看实际 checkpoint 帧，不仅 busy：旧读事务下 PASSIVE busy=0 仍可能无进展，TRUNCATE busy=1；释放 reader 后重试成功不等于生产阈值/冷却已验。observer PRAGMA、测试缓存和关闭 auto-checkpoint 的实验不能冒充生产 worker 容量验收。
- 检查实际邮件负载、归属、唯一关联、FK/quick_check、端口及进程退出；DB/WAL 只读保护与真实提交结果分开。Windows CTRL_BREAK、真实服务管理器、外层 deadline、断电/磁盘满、长事务 WAL/持锁压力需分别验证。

入口：关闭整合与边界（历史本地记录）、writer 关闭契约（历史本地记录）、[实时 owner 关闭](realtime-relay.md)。

## 验证、增量与未覆盖项

- 不累加历史检查次数；固定编译产物只证明对应输入，不能代表持续变化的全仓。原仓测试失败须报告，派生夹具通过不能写原套全绿。并发成功断言与合法 admission 拒绝冲突时调整正确夹具，不放宽生产预算；真实时间夹具保留 clockVersion/冻结席位/租约边界。
- 五王席位测试分别覆盖 deadline 前保留、deadline 后真实清理；用有界条件等待代替脆弱固定 sleep，单调时钟 mock 不削弱并发名额或旧 clockVersion 无副作用拒绝。需真实 Node Timer 的授权寿命另按[AI 专题](multiplayer-ai.md)执行。
- junction 测试入口同时核对 preserve-symlinks/preserve-symlinks-main、实际 TMP/DATA_DIR，避免误用源 out/主临时目录。保留旧失败证据与后续修正的范围。
- 增量按精确前像和接手基线生成。已含修复的 before 不能当修复前回滚点；重叠完整补丁不可串行重放，整树 diff HEAD 不可混入已采纳并行改动。保持范围外变化和产物身份，后续整合另核实际差异。
- 榜单昂贵读取、全量邮件、长期磁盘增长、极大榜单、完整生产 worker 拓扑、断电/磁盘满、SCM/外层期限与云端容量需相应运行证据。单机合成耗时/心跳不能保证云服性能；未改主 out 或未加载服务时不把源码通过称运行已修复。历史未验项须按当前任务重新核对，不自动扩大修改范围。
