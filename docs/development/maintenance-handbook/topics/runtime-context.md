## 运行状态与线程归属

父业务进程负责 HTTP、玩家数据库和资格/支付/结算；独立 realtime owner 持有 TCP listener、房间/战局/场景屏障、返回名单和有限租约，父侧通过 command/projection 访问，child 不得打开玩家 DB。`MULTI_REALTIME_PROCESS` 与可选 `MULTI_BATTLE_RELAY_PROCESS` 是两个开关，owner 启用不证明 relay 启用；显式环境值仍可覆盖默认。已注册 writer 命令不代表所有写入都已迁移，active 中有包不代表全部发布。

配置定义、编译产物、实际 listener/child 与真实业务结果分别核对。历史本地 owner 运行和双 LAN 普通合作见双机结果（历史本地记录）；不能据此宣布云服、iOS 或公网通过。普通开服遵守工作区现行规则，确认已有服务或启动就绪后交客户端测试，不因本条增加例行全链探测。

## 合成完整服务冒烟

适用于已明确要求补做服务整合验证的任务，不作为普通开服的附加步骤。先复用当前产物的已有回归，只补缺失层：完整CN注册链的真实HTTP、正常启动/worker、独立owner的真实TCP、重启及退出。完整CN成功回包按Base64→MessagePack解码，测试子插件的JSON装饰器不能直接搬用；合成准入配置也须满足现行完整字段合同。先修正外部harness输入，不能为夹具失败修改业务合同。

状态目录放在所有Git工作树外，只继承OS/tool变量，显式指定全部写路径并加载现有`isolated-runtime-fs-guard.cjs`。端口0不保证避开本机保留端口：若当前系统动态范围包含8001/8003，绑定前选择范围外的回环高端口，绑定后核对实际地址。owner的fork若显式清空execArgv，父进程的`--require`不会自动传播；可只在本次合成子进程环境通过`NODE_OPTIONS`预加载，核对同路径require缓存、owner/worker实际marker与数据库禁开断言。Windows路径使用正斜杠避免预加载转义歧义，不改全局环境。

空CDN足以验证不依赖资源的业务HTTP，却可能使内容启动夹具的definitionReady返回409；这不自动构成业务缺陷。按实际缺失的有限归档补用规范只读CDN并比较前后哈希，不能禁用校验、复制真实数据库或另建资源测试链。最终记录进程正常退出、owner退出、确切端口关闭和原输入未变；既有权益、协议冒烟、资源下载、浏览器和设备分别报告。实际例证与可复用仓外脚本见完整服务冒烟结果（历史本地记录）；JS写入护栏不等于OS沙箱，writer启动也不证明每笔业务写入均走writer。

新增管理SPA页面还须检查已登录直达URL、刷新、未登录跳转与缺失静态资源404；菜单导航成功不能证明服务端回退白名单包含该页。礼包页曾因`sendAdminSpaFallback`漏列路径而只在刷新时报404，真实浏览器及最小HTTP红绿回归定位见界面验收（历史本地记录）。浏览器可用性是当时状态，后续明确要求验收时重新检查；保留桌面/窄屏的实际表单、失败保留、持久状态与截图证据，不把旧的工具不可用结论沿用为永久阻塞。

## 生成物、固定 SHA 与历史回滚

Git 保留源码、数据、依赖及编译策略，生成的 `out/` 不跟踪；旧未跟踪文件不等于运行文件不存在。云服包仍须含完整编译的运行文件，包括动态 worker、转发 child 及精确引用的 character_table JSON。用固定 source/base 分别 fresh 构建，再比较产物字节、CRC、清单、安全路径和必要运行成员；旧 Git 字节继续作为旧版本证据，不能只看跟踪文件列表推断删除。

相同完整输入的立即回滚可保留必要生成物；输入不同而缺少必要历史产物时应拒绝封包，不能猜测历史字节。历史迁移中旧 341 文件逐字节一致，完整输出 456；多出的 115 是旧记录不全，并非删除证据，见 `<workspace>/work/out-delivery-migration-20261010/`。固定源码交付实例见交付结果（历史本地记录）：远端 main、准确 source SHA 的检查和标签一致，仅证明包来源与离线完整性，不代表上传或部署。

只交付服务端修复、延期 CDN 时，先读取交付台账的 `scope_status` 和包外暂缓清单。`--selection-plan` 从完整旧基线与明确既有主线提交构造可重放的 Git tree，按该 tree 编译、取静态成员和计算剩余范围；来源锚点不是整仓交付进度。整仓基线、服务端组合、内容与 CDN 分开记录，后续普通整仓打包遇到 mixed 状态会停止，避免把暂缓增量当作已覆盖。不能只删 ZIP 而保留新 manifest，也不能把最新角色/超限代码与旧内容数据混用。工具与输入契约见[运行产物流程](../../runtime-artifacts.md#只交付服务端修复)，本次实际包与验证由 `<workspace>/work/server-only-cloud-20261021/` 及正式交付台账追踪；这些记录不构成云端部署证据。

CI 若在约 2 GB V8 堆上限耗尽并 exit 134，先辨明堆 OOM 与 TypeScript 错误。历史成功处理只对对应 workflow 任务设置 `NODE_OPTIONS` 为 4 GiB，再检查准确 SHA 的 hygiene/gitleaks/runtime-build；不顺带修改云运行堆。部署排空时间、旧局时钟保护、显式 TTL/REALTIME 值仍按该批交付说明处理，不能复用历史默认覆盖生产配置。

## “客户端准入配置暂时不可用”的条件恢复

该提示表示进程尚无成功加载的准入策略，不等于客户端被禁用。默认 `config/client-admission.json` 缺失且未指定替代路径时，即使 keys 存在、8001/8003 已监听，也会拒绝接入；日志可出现 `[client-admission] 配置读取失败`。文件为何缺失须另查，不能推测删除者或原因。

1. 确认实际配置路径、日志与当前失败阶段，区分策略未加载和身份/配对失败。
2. 仅在既有私有策略与本机 keys **完整配对已确认**后，原样恢复缺失的默认策略。历史可用备份位于 `<workspace>/.codex/local-runtime/starpoint-cn/client-admission.json`，路径存在不自动证明仍适用。
3. 固定配置路径每 2 秒重读，可原进程热加载；修改环境变量切换路径须重启。保留 enforce、准入编号、允许名单和密钥，不以不配对的云服策略替代本地策略。
4. 检查实际加载及对应 challenge/prove；握手通过只覆盖配置加载与本地协议，不等于设备登录、云服部署或包变更。

上述恢复曾对同一进程三个既有 build 通过，keys 未变且 enforce=true，见恢复检查（历史本地记录）。缺文件前提不成立时，退出此恢复路径。
